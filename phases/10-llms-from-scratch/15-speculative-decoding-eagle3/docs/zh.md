# 推测解码与 EAGLE-3

> 第 7 阶段 · 第 16 课证明了数学原理：Leviathan 拒绝规则精确地保持了验证器的分布。本课是 2026 年生产级推测解码的训练栈视图。EAGLE-3 将草稿模型从廉价的近似方案转变为一个在验证器自身隐藏状态上训练的目的构建式微型网络，然后添加了一个训练时测试循环，使其训练和推理分布对齐。结果：3× 到 6.5× 的端到端加速，对话场景下每 token 接受率超过 0.9，没有分布上的权衡。2026 年的每个生产推理栈默认都会搭载它。

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 7 · 16 (speculative decoding math), Phase 10 · 12 (inference optimization)
**Time:** ~75 minutes

## 学习目标

- 用一句话阐述 Leviathan 定理，并证明推测循环产生的样本在分布上与验证器相同。
- 走过从普通推测解码（Leviathan 2023）到 EAGLE、EAGLE-2 再到 EAGLE-3 的两年演进历程，并指出每一步消除了的确切限制。
- 从接受率 `α` 和草稿-验证器成本比 `c` 计算期望加速比，并为每种状态选择最佳草稿长度 `N`。
- 从零实现完整的推测循环：草稿、验证、从残差进行拒绝采样、拒绝时回滚 KV 缓存、完全接受时发出奖励 token。

## 问题

在 H100 上对 70B 模型进行自回归解码，大约每秒 35 个 token。GPU 远未饱和。内存带宽是上限：每个 token 需要从 HBM 加载 70B 权重，执行一步算术，产出一个 float。计算单元大部分空闲。

推测解码将其转变为一个你真正可以解决的吞吐量问题。一个廉价的草稿模型通过 N 个小型前向传递提出 N 个 token。验证器在原始前缀加上所有 N 个草案上运行一次。如果验证器在位置 `i` 的分布与草案一致（在我们即将精确说明的统计意义上），我们就接受；如果不一致，我们拒绝并从残差分布中采样一个修正。一次大模型前向传递产生最多 N+1 个被接受的 token，而不是一个。

重要的定理是 Leviathan、Kalman、Matias（ICML 2023）：输出分布与直接从验证器采样产生的分布*完全一致*。不是近似，是完全一致。这就是推测解码在生产中可被接受的全部理由——它是一种纯粹的延迟优化，没有质量上的取舍。

第 7 阶段 · 第 16 课给你的是数学。本课给你的是训练栈。一个好的草稿模型比一个廉价的草稿模型价值高出 2 倍加速比。EAGLE、EAGLE-2 和 EAGLE-3（Li 等人，2024–2025）将"草稿 = 同一模型的较小版本"转变为精确的工程学科。2026 年的生产推理服务器默认使用 EAGLE-3。

## 概念

### 不变量：Leviathan 拒绝采样

令 `p(t)` 为草稿模型在给定某些前缀下对下一 token 的分布，`q(t)` 为验证器的分布。采样一个草稿 token `d ~ p`。以概率 `min(1, q(d) / p(d))` 接受。拒绝时，从残差分布 `(q - p)_+ / ||(q - p)_+||_1` 中采样。结果样本服从 `q` 分布。无论 `p` 有多差，这都成立——p 越差，拒绝越频繁，但输出保持精确。

将这 N 次调用叠加在一起，使用一次验证器前向传递处理 `prefix + d_1 + ... + d_N`。验证器同时返回 `q_1, q_2, ..., q_{N+1}`。从左到右遍历。在位置 `j` 首次拒绝时，从 `residual(q_j, p_j)` 中采样并停止。完全接受时，从 `q_{N+1}` 中采样一个奖励 token。

### 决定加速比的因素

令 `α` 为每个草稿 token 的期望接受率。令 `c = cost(draft) / cost(verifier)` 为成本比。每次验证器前向传递的期望接受 token 数为：

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

每个接受 token 的期望总挂钟时间为 `(N * c + 1) / E[accepted]`。关于 `N` 最小化该值即为最佳点。对于 `α = 0.8, c = 0.05`：最优 `N` 约在 5–7，加速比 3.2×。对于 `α = 0.95, c = 0.02`：最优 `N` 约在 8–10，加速比推向 5×。

最大的杠杆是 `α`。在固定 `N = 5` 下，从 `α = 0.6`（普通草案）提升到 `α = 0.9`（EAGLE-3），每次验证器前向传递的期望接受 token 数从 2.2 跃升至 4.1。同样的验证器产出近 2 倍的吞吐量。

### 两年演进

**普通推测（Leviathan，2023）。** 草稿模型是同一家族的一个独立训练的较小 LLM。易于接入，`α ≈ 0.6`，加速比最佳约 2×。

**EAGLE-1（Li 等人，2024）。** 草稿是一个微小的 transformer——通常一到两层——接受验证器最后一层隐藏状态作为输入，直接预测下一个 token。因为草稿看到了验证器的特征表示，其分布与验证器的更接近。`α` 攀升至 0.7–0.8。

**EAGLE-2（Li 等人，2024）。** 添加了动态草稿树：不提出单个 N 个 token 的序列，而是提出一个小型候选树，用验证器在一次前向传递中（树状注意力）逐一评分，并选择最高概率的路径。草稿长度变为每步自适应。每个接受路径 token 的 `α` 攀升至 0.85 以上。

**EAGLE-3（Li 等人，2025，NeurIPS）。** 两项额外变化。首先，完全放弃特征预测损失——EAGLE-1/2 训练草稿以匹配验证器的隐藏状态，这限制了数据量的帮助。EAGLE-3 直接在 token 预测上训练。其次，训练时测试（TTT）：在草稿训练过程中，将草稿自身之前的预测作为输入反馈多步，与推理时相同的运作方式。这使训练和测试分布对齐，并阻止误差累积。实测加速比：对话端到端最多 6.5×，在 SGLang 上 H100 batch 64 下吞吐量提升 38%。

### KV 缓存回滚

验证在一次传递中将验证器的 KV 缓存扩展 `N` 个条目。如果拒绝发生在位置 `j`，缓存中位置 `j-1` 之后的内容现在都是错误的。两种常见实现：写入临时缓冲区并在接受时提交（vLLM、TensorRT-LLM），或者保持物理 KV 缓存加一个逻辑长度，在拒绝时截断。无论哪种方式，回滚成本是每层每头的字节数，与前向传递成本相比可以忽略不计。

对于 EAGLE-2 的树搜索，验证器使用一个尊重树拓扑的非因果掩码运行注意力。工程上有些繁琐，但计算是一次标准的 flash-attention 调用，使用自定义掩码。

### 2026 年的草稿架构

| 策略 | 草稿类型 | `α` | 加速比 | 训练成本 |
|----------|-----------|-----|---------|---------------|
| 普通 | 独立的小 LLM | 0.55-0.70 | 1.8-2.3× | 无（复用现有的小型模型） |
| Medusa | 验证器上额外的 LM 头 | 0.65-0.75 | 2-3× | ~1B SFT tokens |
| EAGLE-1 | 基于隐藏状态的 1 层 transformer | 0.70-0.80 | 2.5-3× | ~60B tokens |
| EAGLE-2 | EAGLE-1 + 动态草稿树 | 0.80-0.88 | 3-4× | ~60B tokens |
| EAGLE-3 | 多层特征融合 + TTT | 0.88-0.92 | 3.5-6.5× | ~60-200B tokens |
| Lookahead | 无草稿（Jacobi 迭代） | N/A | 1.3-1.6× | 无 |

2026 年生产中：vLLM 和 SGLang 在可用时默认使用 EAGLE-3，否则使用 EAGLE-2。TensorRT-LLM 为 Meta 和 NVIDIA 公开模型提供最快的 Medusa 路径。llama.cpp 为 CPU 部署搭载普通草案。

## 构建它

参见 `code/main.py`。这是完整的 Leviathan 推测循环，包含所有部分：N 草案、验证器并行传递、逐位拒绝、残差采样、奖励 token、KV 回滚，以及输出分布与从 `q` 直接采样匹配的经验验证。

### 步骤 1：拒绝规则

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 步骤 2：残差分布

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 步骤 3：一个完整的推测步骤

`scep_step` 函数从 `p` 起草 `N` 个 token，然后在一次并行 `q` 评估中验证所有 token。对每个草稿 token 应用拒绝规则，在首次拒绝时从残差中采样修正。如果全部接受，从 `q_{N+1}` 发出一个奖励 token。

### 步骤 4：KV 回滚记账

模拟器跟踪每个 worker 的逻辑 `kv_length`。在接受 `k` 个草案时，`kv_length += k`。在位置 `j` 拒绝时，缓存已经写入 `j` 之后，但逻辑长度被设置为 `prefix_length + j + 1`——修正 token 之后的一位。后续读取截断到逻辑长度。

### 步骤 5：Leviathan 检验

运行 50,000 次推测步骤。统计接受 token 的经验分布。与从 `q` 直接抽样的 50,000 次进行比较。卡方统计量应远低于临界值。定理在实践中通过。

### 步骤 6：加速比 vs α

通过以不同幅度将 `p` 偏离 `q` 来扫描草稿质量。测量 `α`，然后绘制每次验证器调用的期望 token 数作为 `α` 和 `N` 的函数。代码会打印一个表格，展示 EAGLE-3 级别的草稿质量（`α ≈ 0.9`）如何解锁每次验证器调用 4–5 个 token。

## 使用它

生产级 `vllm serve` 使用 EAGLE-3：

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

SGLang 在 H100 batch 64 下使用 EAGLE-3：根据 EAGLE-3 论文，比 batch-64 普通解码吞吐量提升约 1.38×。

何时使用推测解码：

- 任何交互式对话工作负载，其中 p50 延迟比峰值吞吐量更重要。
- 代码生成和结构化输出（JSON、SQL）。`α` 高于 0.9，因为目标分布高度可预测。
- 长文本生成（数千 token）。摊销的加速持续有效。

何时不用：

- 非常小的模型（< 3B）。草稿不比验证器便宜太多。
- 极小的 batch-1 CPU 部署。草稿模型的内存开销可能不值得。
- 非常高温的创意采样，`α` 崩塌。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| Leviathan 规则 | "min(1, q over p)" | 以概率 `min(1, q(d)/p(d))` 的 Bernoulli 接受/拒绝，在拒绝时从残差采样，精确保持验证器分布 |
| 残差分布 | "(q minus p) plus, 归一化" | `(q - p)_+` 截零后重新归一化——拒绝时采样的正确分布 |
| 接受率 α | "草稿模型多经常正确" | 拒绝规则下的每个 token Bernoulli 成功期望概率；支配所有加速比数学 |
| EAGLE-1 | "隐藏状态草稿" | 以验证器最后一层隐藏状态为条件的微型 transformer 草稿（Li 等人，2024） |
| EAGLE-2 | "动态草稿树" | EAGLE-1 加上候选续写树，在一次验证器传递中用树注意力评分 |
| EAGLE-3 | "训练时测试" | 放弃特征预测损失，在直接 token 预测上训练，训练期间草稿输入自身输出 |
| 训练时测试（TTT） | "曝光偏差修复" | 训练期间让草稿自回归运行，使训练和测试输入分布匹配——计划采样的直接类比 |
| KV 回滚 | "撤销被拒绝的草案" | 在拒绝后将验证器 KV 缓存重置为已接受前缀长度的记账操作 |
| 奖励 token | "免费的那个" | 当所有 `N` 个草案都接受时，从 `q_{N+1}` 额外采样一个 token，不增加验证器成本 |
| 树注意力 | "一次验证多个候选" | 使用尊重草稿树拓扑的非因果掩码的注意力；在一次前向传递中为树中每个节点计算 `q_i` |
