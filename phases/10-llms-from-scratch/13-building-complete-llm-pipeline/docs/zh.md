# 构建完整的 LLM 流水线

> 从第 01 课到第 12 课的一切都是一条流水线的一个阶段。本课是将这些阶段转化为单次端到端运行的脚手架：分词、预训练、扩展、SFT、对齐、评估、量化、服务。这是顶点项目。

**类型：** 构建
**语言：** Python（stdlib）
**前置课程：** 所有 Phase 10 第 01-12 课
**时间：** ~120 分钟

## 学习目标

- 将之前的 11 节课组合成单个可复现的流水线规范
- 定义阶段间的工件契约：每个阶段消费什么、生成什么，以及下一个阶段如何验证输入
- 构建跟踪实验、哈希工件并在评估阈值上把关发布决策的编排器
- 设计回滚计划：哪些工件便宜可以重新运行，哪些昂贵，以及损坏的检查点会损失什么

## 问题

前面的课都各自工作：分词器训练好了、迷你 GPT 预训练了、SFT 数据集组装了、奖励模型训练了、DPO 运行了、Eval 测量了、量化权重导出了、推理服务器启动了。但前沿训练运行不是笔记本——一个损坏的检查点、一次数据污染、一次评估倒退可以耗费一个团队一周的墙钟时间和一个月的 GPU 预算。

团队通过流水线规范来生存：每个阶段都有确定性输入、确定性输出、清单、哈希和门禁。这是顶点课程。你将编写协调阶段的编排器、描述运行的清单、把关发布决策的验证器，以及让第三方从单一文件重新运行你的工作的重放计划。

## 概念

### 十二个阶段

每个 Phase 10 课程都是一个阶段。依赖图：01 分词器 → 02 → 03 分片数据集 → 04 基础模型 → 05 扩展训练 → 06 SFT → 07 奖励模型/PPO → 08 DPO → 09 CAI/GRPO → 10 评估报告 → 11 量化权重 → 12 推理服务器 → 发布门禁。阶段 07 和 08 可并行运行。

### 清单

清单是一个单文件，完全描述了一次运行，足以重放它。流水线产生的结果不依赖于清单之外的任何状态。阶段 N 的输出哈希是阶段 N+1 的输入哈希。任何偏差都会使流水线停止。

### 工件类型

每个阶段的输出是一个类型化工件，具有已知的模式（分词器、数据集、检查点、SFT 模型、奖励模型、策略、评估报告、量化模型、服务器规范）。类型化防止最常见的故障模式：将阶段 08 的输出用作阶段 06 的输入。

### 评估门禁

发布不是"训练完成"，而是"训练完成且通过了评估门禁"。每个门禁是一个数字阈值：MMLU >= 基线 + 0.5、HumanEval >= 基线 + 1.0、KL 预算限制、安全拒绝率、总成本。两个门禁能抓住大多数灾难：*回归门禁*（核心基准上不倒退）和*KL 预算门禁*（对齐策略没有偏离太远）。

### 编排器

大约 200 行 Python：解析 DAG，检查每个阶段的输入哈希是否已存在（跳过），运行阶段，验证输出哈希，失败时写入失败清单。不是 Airflow，不是 Kubeflow——你想要简单可信赖的东西。

### 其他组件

**实验跟踪器**（wandb, neptune, mlflow）记录损失曲线和评估指标。**工件存储**（S3, R2, GCS）是按内容寻址的不可变对象存储。**成本计算**涵盖运行前估算（FLOPs、GPU 小时、美元成本）和运行中跟踪。**可复现性 vs 确定性**——分布式训练的归约顺序和 GPU 内核非确定性意味着位级别不相同但指标匹配即视为"可复现"。**回滚计划**——运行前写下每个阶段失败时会发生什么。

### 2026 年观察到的生产配方

- 分词器：128k BPE 带字节回退
- 预训练：10-20T token，主要是网络+代码+合成数据，Muon 或 AdamW，FSDP2/ZeRO-3
- SFT：500k-2M 高质量指令对，混合人类和合成数据
- 对齐：DPO 或 CAI+GRPO，仅在偏好信号过于多维时使用 RLHF
- 评估：MMLU-Pro、MATH、HumanEval+、GPQA、SWE-Bench Verified、LiveBench + 内部保留集
- 量化：4-bit GPTQ/AWQ 用于服务，8-bit 用于安全评估
- 服务：vLLM、TensorRT-LLM 或自家，连续批处理，推测解码

## 构建它

`code/main.py` 实现了编排器和清单检查器。关键组件包括 `Manifest` 数据类、`Stage` 数据类、`Orchestrator.run()`（解析 DAG、调度阶段、验证哈希）、`EvalGate.check()`、`ArtifactStore`（内存桩，模拟 S3）和 `CostTracker`。每个阶段用生成正确形状和哈希输出工件的占位符模拟。

## 使用它

三个命令：`plan`（验证清单、计算成本估算、打印 DAG）、`run`（执行阶段）、`gate`（应用评估门禁，输出 SHIP 或 HOLD）。每次先运行 `plan`——在便宜的一端捕捉 Bug。

## 交付成果

`outputs/skill-llm-pipeline-reviewer.md`：检查所有契约（阶段类型、哈希链、门禁、回滚计划、成本估算）的流水线审查工具。

## 练习

1. 扩展编排器以支持阶段 07 和 08 的并行执行
2. 添加污染检查门禁：检验评估数据与训练数据的重叠
3. 从第一性原理实现成本估算器：估算 FLOPs、GPU 小时和美元成本
4. 构建部分回滚：模拟阶段 09 的失败，重新运行 09-12 而 01-08 缓存
5. 添加 OpenTelemetry 可观测性：每个阶段带有属性的 span

## 关键术语

| 术语 | 含义 |
|------|------|
| 清单 | 描述版本、种子、阶段配置和门禁阈值的 YAML/JSON |
| 内容寻址 | 通过 SHA-256 按内容存储工件 |
| 评估门禁 | 发布前必须通过的基准指标和安全性分数的数值阈值 |
| KL 预算 | 对齐阶段中允许的累积 KL 散度上限 |
| MFU | 模型 FLOPs 利用率——70B 规模典型为 40% |
| 回滚计划 | 每个阶段失败时预先写好的行动：重新运行、回退、修订重训练 |
| 编排器 | 读取清单、调度阶段、验证哈希、在任何合同违例时停止 |
| 工件存储 | 不可变的内容寻址对象存储 |
| 成本门禁 | 运行前成本估算 + 运行中跟踪器 |
