# 原生稀疏注意力（DeepSeek NSA）

> 在 64k token 上，注意力消耗解码延迟的 70-80%。每个开放模型实验室都有解决它的计划。DeepSeek 的 NSA（ACL 2025 最佳论文）是那个站稳脚跟的方案：三条并行注意力分支——压缩的粗粒度 token、选择性保留的细粒度 token、以及用于局部上下文的滑动窗口——通过一个学习的门控组合在一起。它是硬件对齐的（kernel 友好），原生可训练的（在预训练中工作，而非推理时才嫁接），在 64k 解码上，它的运行速度比 FlashAttention 更快，同时质量匹配或超过全注意力。本课端到端构建这三条分支，并展示为什么稀疏性是端到端可微的。

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 7 · 12 (KV cache, flash-attention), Phase 7 · 15 (attention variants), Phase 10 · 16 (differential attention)
**Time:** ~60 minutes

## 学习目标

- 阐述三条 NSA 注意力分支以及每条捕获什么内容。
- 解释为什么 NSA 是"原生可训练的"，而之前的稀疏注意力方法仅仅是推理时的方案。
- 在压缩块大小和选择 top-k 的函数下，计算 NSA 相比于 64k 上下文中全注意力的注意力计算节省。
- 在 stdlib Python 中实现短合成序列上的三条分支组合，并验证门控权重的行为。

## 问题

序列长度 N 上的全注意力消耗 `O(N^2)` 时间和 `O(N)` 的每层 KV 缓存。在 64k token 上，计算和内存带宽数字是灾难性的。根据 NSA 论文的实测理论估计：注意力占据了 64k 时解码总延迟的 70-80%。所有下游指标——TTFT、tokens/sec、每百万 token 成本——都被注意力成本主导。

稀疏注意力是显而易见的答案。之前的尝试分为两类。固定模式稀疏（滑动窗口、跨步、块局部）丢弃信息，在长程召回任务上失败。推理时稀疏（KV 缓存剪枝、H2O、StreamingLLM）应用于在密集注意力上预训练的模型，只回收了一部分潜在加速，因为模型从未被要求将信息通过稀疏模式路由。

原生稀疏注意力（Yuan 等人，DeepSeek + PKU + UW，ACL 2025 最佳论文，arXiv:2502.11089）两者兼顾：一个模型在预训练中学习的稀疏模式，实现为一个 kernel 对齐的算法，实际上在推理时实现了计算节省。两年后，NSA 或其直接后继将成为每个前沿长上下文模型上的默认注意力。

## 概念

### 三条并行分支

对于每个查询，NSA 对 KV 缓存的三种不同视图运行三次注意力：

1. **压缩分支。** Token 被分组为大小为 `l` 的块（通常为 32 或 64）。每个块通过一个小型学习式 MLP 压缩为一个摘要 token。查询在这些压缩 token 上进行注意力，获取整个序列的粗粒度视图。

2. **选择分支。** 使用压缩分支的注意力得分，识别与当前查询最相关的 top-k 块。从这些块中读取细粒度（未压缩）的 token，查询对所有这些进行注意力。可以将压缩分支的注意力视为选择的路由信号。

3. **滑动窗口分支。** 查询关注最近 `W` 个 token（通常为 512），获取局部上下文。这条分支捕获另外两条可能错过的结构密集型短程模式（句法、局部共指）。

三条分支输出通过一个学习式的逐位置门控组合：

```
out = g_cmp * out_cmp + g_sel * out_sel + g_win * out_win
```

`g_cmp, g_sel, g_win` 是查询上的一个小型 MLP 产生的门控权重。它们不需要和为 1——它们可以独立加权各分支。

### 为什么这是"原生可训练的"

选择步骤（top-k 块）是离散的。离散操作会打断梯度流。之前的稀疏注意力工作要么跳过选择的反向传播（限制了训练），要么使用不给推理时真正稀疏性的连续松弛。

NSA 绕过了这一点：压缩分支注意力是对整个序列的可微粗粒度注意力。top-k 操作只是重用压缩分支的最高注意力得分来选择加载哪些细粒度块。梯度通过压缩分支得分流动（这些得分影响压缩输出和选择逻辑），所选块对最终输出的贡献也是可微的。不可微的 `top_k` 操作在前向计算图上是无操作——它只控制从内存中加载哪些块。

这就是为什么 NSA 可以端到端用于预训练。模型学习通过三条分支联合路由信息，产生一个在推理时真正实现承诺加速的稀疏模式。

### 硬件对齐的 kernel

NSA 的 kernel 是为现代 GPU 内存层级设计的。kernel 按 GQA 组加载查询（外层循环），按组获取相应的稀疏 KV 块（内层循环），并在 SRAM 上运行注意力。因为每个查询组看到相同的选定块（选择是按查询组而非按查询头），KV 加载在组内摊销。算术强度保持较高。

论文报告了 Triton kernel 在 64k 解码上比 FlashAttention 快 9 倍，加速比随序列长度增长。前向和后向 kernel 均已提供。

### 计算预算

令 `N` 为序列长度，`l` 为压缩块大小，`k` 为 top-k 选择计数，`w` 为滑动窗口，`b` 为选定块大小（通常等于 `l`）。

- 压缩分支：每个查询 `O(N/l)` 个键，总计 `O(N * N / l)`。
- 选择分支：每个查询 `O(k * b)` 个键，总计 `O(N * k * b)`。
- 滑动分支：每个查询 `O(w)` 个键，总计 `O(N * w)`。

总计：`O(N * (N/l + k*b + w))`。

当 `N = 64k, l = 64, k = 16, b = 64, w = 512`：每个查询成本为 `1000 + 1024 + 512 = 2536 keys`。全注意力是 `64000 keys`。25 倍计算减少。

当 `N = 128k, l = 64, k = 16, b = 64, w = 512`：每个查询成本为 `2000 + 1024 + 512 = 3536 keys`。全注意力是 `128000 keys`。36 倍减少。收益随序列长度增长，这正是一切的意义所在。

### 如何比较

| 方法 | 可微 | 真实推理加速 | 长程召回 |
|--------|---------------|----------------------|-------------------|
| 仅滑动窗口 | 是 | 是 | 失败 |
| 跨步 / 块稀疏 | 是 | 是 | 部分 |
| KV 剪枝（H2O, StreamingLLM）| N/A（推理时）| 是 | 部分 |
| MoBA（Moonshot）| 部分 | 是 | 良好 |
| NSA | 是（原生）| 是（64k 下 9x）| 匹配全注意力 |

MoBA（Moonshot, arXiv:2502.13189）是同期发表的，采取了类似的三合一方案，将 MoE 原理应用于注意力块。NSA 和 MoBA 是 2026 年长上下文预训练需要了解的两个架构。

## 构建它

`code/main.py` 在短合成序列上实现三条分支，并展示：

- 压缩 MLP（为教学清晰使用简单均值池化基线；真实 NSA 使用学习式 MLP）。
- 由压缩分支得分驱动的 top-k 块选择。
- 对最后 `w` 个 token 的滑动窗口注意力。
- 门控组合。
- 与全注意力比较的计算计数打印。

### 步骤 1：将 token 压缩为块

```python
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out
```

### 步骤 2：压缩分支注意力

对查询与压缩后的键运行 softmax 注意力。压缩分支得分同时充当 top-k 选择的信号。

### 步骤 3：top-k 块选择

选择得分最高的 `k` 个压缩块的索引。从这些块加载原始未压缩 token，并对它们运行注意力。

### 步骤 4：滑动窗口注意力

取最后 `w` 个 token，对它们运行标准注意力。

### 步骤 5：门控 + 组合

查询上的小型 MLP 产生三个门控权重。最终输出是三条分支输出的加权和。

### 步骤 6：计算计数

打印每条分支每个查询关注的键数以及总数。与 `N`（全注意力）比较。在 1024 token 合成序列上，`l = 32, k = 4, w = 128`，NSA 每个查询看到 `32 + 128 + 128 = 288` 个键，而全注意力是 1024——3.5 倍更少。

## 使用它

NSA 在 DeepSeek 自身的长上下文预训练流水线中搭载。截至 2026 年 4 月，在公共推理栈中的集成状态：

- **DeepSeek 内部**：原生，发布权重使用 NSA 或其继任者 DSA（Deepseek Sparse Attention）。
- **vLLM**：为 DeepSeek-V3.x 权重开发中的实验性 NSA 支持。
- **SGLang**：NSA 基准已发布；生产路径跟随 vLLM。
- **llama.cpp / CPU**：不支持；kernel 分解的开销在 CPU 吞吐量级别上不值得。

何时使用 NSA：

- 预训练或继续训练运行，目标 64k+ 上下文，有足够的计算预算。
- DeepSeek 自身长上下文权重的推理。权重是 NSA 原生的。

何时不用：

- 部署一个现有的密集注意力预训练模型。在没有继续训练的情况下无法改造 NSA。
- 上下文在 16k 以下。三条分支的开销主导了节省。
- Batch-1 交互对话。延迟敏感的解码受益，但仅在长上下文时。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| 压缩分支 | "粗视图" | 对分块平均键的注意力，以 O(N/l) 键每查询提供全局上下文 |
| 选择分支 | "Top-k 块" | 对压缩分支得分最高的 `k` 个块进行细粒度注意力 |
| 滑动窗口 | "局部上下文" | 对最后 `W` 个 token 的注意力，用于短程模式 |
| 原生可训练 | "预训练时就开启稀疏性" | 稀疏模式在预训练中学习，而非推理时才嫁接 |
| 压缩块大小 l | "粗视图的组大小" | 多少 token 合并为一个摘要；典型 32-64 |
| Top-k | "保留的块数" | 读取其未压缩 token 的压缩块数；典型 16 |
| 滑动窗口 W | "局部注意力半径" | 通常 512；更短影响局部连贯性，更长浪费计算 |
| 分支门控 | "如何混合三者" | 逐位置 MLP 输出，对三条分支的贡献加权 |
| 硬件对齐 | "Kernel 友好稀疏性" | 选择的稀疏模式使实际 GPU kernel 实现理论加速 |
| DSA | "NSA 的继任者" | Deepseek Sparse Attention，DeepSeek 族系中跟随 NSA 的架构 |
