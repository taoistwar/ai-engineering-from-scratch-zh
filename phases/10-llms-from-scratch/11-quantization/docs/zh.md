# 量化：让模型放得下

> FP16 中的 70B 模型需要 140GB。仅权重就需要两个 A100。量化到 FP8：一个 80GB GPU。INT4：一台 MacBook。

**类型：** 构建
**语言：** Python（使用 numpy）
**前置课程：** Phase 10, 第 01-10 课（从零开始的 LLM）
**时间：** ~120 分钟

## 学习目标

- 实现从 FP16 到 INT8 和 INT4 的对称和非对称量化，包括逐张量和逐通道缩放
- 计算量化带来的内存节省，并确定哪种精度适合给定 GPU 的显存
- 解释训练后量化（PTQ）和量化感知训练（QAT）之间的区别
- 应用 GPTQ 或 AWQ 对真实模型进行量化，并在基准测试上衡量准确率与内存的权衡

## 问题

Llama 3 70B 有 700 亿个参数。每个参数是一个 16 位浮点数。即 1400 亿字节。140GB。单个 A100 有 80GB 显存。你甚至无法加载权重，更不用说在单个 GPU 上进行推理了。你需要两个 A100，每个每小时 2 美元，仅为了服务一个模型。

但每个参数 16 位是浪费的。神经网络中的大多数权重聚集在零附近。FP16 的全动态范围（从 0.000000059 到 65,504）几乎完全没有被使用。如果你测量 Llama 3 70B 中权重的实际分布，95% 的权重落在 -0.1 和 +0.1 之间。你正在燃烧 16 位来表示可以用 4 位表示的值。

量化将高精度数字替换为低精度数字。FP16 到 FP8 将内存减半。FP16 到 INT4 将其减至四分之一。那个 140GB 的模型变成 35GB。它适合单个消费级 GPU。推进到 2 位量化（激烈、有损，但对某些任务可用），同样的模型可以在 16GB 笔记本电脑上运行。

代价是准确率。你移除的每个位都破坏了信息。问题是你损失了多少准确率以及在哪里损失的。一个良好量化的 INT4 模型在大多数基准测试上保留了原版的 95-99% 质量。一个朴素的 INT4 量化可能完全毁掉模型。区别在于技术。

## 概念

### 数字格式：每个位做了什么

每个浮点数有三部分：符号、指数和尾数。符号是 1 位。指数决定范围（数字可以多大或多小）。尾数决定精度（你有多少位小数）。

```
FP32:  [1 符号] [8 指数] [23 尾数]  = 32 位
FP16:  [1 符号] [5 指数] [10 尾数]  = 16 位
BF16:  [1 符号] [8 指数] [7  尾数]  = 16 位
FP8:   [1 符号] [4 指数] [3  尾数]  = 8  位 (E4M3)
FP8:   [1 符号] [5 指数] [2  尾数]  = 8  位 (E5M2)
INT8:  [1 符号] [7 值]               = 8  位 (均匀步长)
INT4:  [1 符号] [3 值]               = 4  位 (总计 16 个级别)
```

**FP32** 是全精度。23 个尾数位给你大约 7 位小数的精度。训练曾经完全在 FP32 中进行。

**FP16** 将位数减半。适用于权重（聚集在零附近）但对可能在训练期间激增的激活值和梯度是危险的。

**BF16** 保留了 FP32 的 8 位指数，但将尾数缩减到 7 位。与 FP32 相同的范围，比 FP16 精度低。每个现代训练运行都使用 BF16 或 BF16/FP32 混合。

**FP8** 有两种口味。E4M3 用于推理（更多精度），E5M2 用于训练中范围比精度更重要的梯度。H100 上的 FP8 推理比 FP16 快 30-50%。

**INT8** 是一个整数格式。256 个均匀间隔的值，从 -128 到 127。A100 上的 INT8 矩阵乘法达到 624 TOPS vs FP16 的 312 TFLOPS。

**INT4** 更进一步。只有 16 个可能的值。最先进的 INT4 方法（GPTQ、AWQ）保留了原版 95%+ 的质量。

### 量化如何工作

核心操作很简单。取一个浮点值张量，找到一个缩放因子，乘以它，四舍五入到最近的整数，并存储整数加上缩放因子。

**量化：** `scale = max(abs(tensor)) / max_int_value`、`quantized = round(tensor / scale)`
**反量化：** `reconstructed = quantized * scale`

**逐张量 vs 逐通道量化。** 逐张量对整个权重矩阵使用一个缩放因子。简单但有损。逐通道对每个输出通道使用一个缩放因子。开销更多但质量显著更好。

**非对称量化** 添加一个零点偏移：`quantized = round(tensor / scale) + zero_point`。这处理了不以零为中心的分布，如 ReLU 激活值。

### 敏感性层次

模型中并非一切对量化的容忍度相同。存在明确的层次：权重（最鲁棒）< 激活值（中等敏感）< KV 缓存（高敏感）< 注意力 logits（最敏感）。

注意力中的 softmax 对其输入的微小变化高度敏感。大多数量化方案即使在一切都被量化时也保持注意力计算在更高精度（FP16 或 BF16）。

### PTQ vs QAT

**训练后量化（PTQ）** 量化已训练的模型。无需重新训练。对 INT8 和 FP8 效果好。对 INT4，朴素 PTQ 常常失败。高级 PTQ 方法（GPTQ、AWQ）使用校准数据最小化量化误差。

**量化感知训练（QAT）** 在训练期间的前向传播中插入假的量化操作。模型学会将其权重放在舍入误差小的位置。对 INT4 和 INT2 产生比 PTQ 更好的结果，但需要完整的训练运行。

### GPTQ、AWQ、GGUF

**GPTQ：** 一次性的 PTQ 方法。使用小校准数据集（通常 128 个示例）测量 Hessian（关于输出对每个权重敏感度的二阶信息）。GPTQ 是第一个使 INT4 量化为 LLM 实用的方法。

**AWQ：** 观察到一小部分权重（约 1%）不成比例地重要，因为它们与大的激活值相乘。AWQ 在量化前识别并放大这些显著权重以保护它们。

**GGUF：** llama.cpp 及其生态系统使用的文件格式。支持混合量化：不同层获得不同的位宽。Q4_K_M 是最流行的 GGUF 量化变体，平衡了质量和大小。针对 CPU 推理和 Apple Silicon 优化。

### 质量测量

- **困惑度：** 最常见的度量。delta < 0.5 优秀，0.5-1.0 良好，1.0-2.0 可接受，> 2.0 有问题。
- **任务特定基准：** 在 MMLU、HumanEval、GSM8K 上运行。量化和代码任务对精度损失更敏感。
- **输出比较：** 对相同提示词从两个模型生成响应并比较。
- **延迟和吞吐量：** 量化存在是为了让模型更快更便宜。

## 关键术语

| 术语 | 人们怎么说 | 真正的含义是什么 |
|------|----------------|----------------------|
| FP16 | "半精度" | 16 位浮点数，5 指数字和 10 尾数，最大 65,504，标准推理格式 |
| BF16 | "Brain float" | 16 位浮点数，8 指数字（与 FP32 相同范围）和 7 尾数，Google 为训练设计 |
| FP8 | "8 位浮点" | 两种变体：E4M3（推理，更多精度）和 E5M2（训练，更多范围），H100 原生支持 |
| INT8 | "8 位整数" | 从 -128 到 127 的 256 个均匀间隔值，需要从浮点映射的缩放因子 |
| INT4 | "4 位整数" | 总共 16 个级别，需要复杂方法（GPTQ、AWQ）以维持质量 |
| 逐通道量化 | "每行一个缩放因子" | 为每个输出通道使用单独的缩放因子，显著减少误差 |
| GPTQ | "Hessian 方法" | 使用二阶信息的训练后量化，一次一层地最小化输出误差 |
| AWQ | "激活感知" | 在量化前放大与高激活值相乘的显著权重以保护它们 |
| GGUF | "llama.cpp 格式" | 包含混合精度层的自包含模型文件，为 CPU 和 Apple Silicon 优化 |
| PTQ | "训练后量化" | 将训练后模型的权重转换为更低精度，快速但在极端压缩下有限 |
| QAT | "训练期间量化" | 在前向传播中插入假量化，使模型学会容忍舍入 |
