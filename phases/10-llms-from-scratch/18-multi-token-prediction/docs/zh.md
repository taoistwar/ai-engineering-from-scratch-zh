# 多 Token 预测（MTP）

> 从 GPT-2 到 Llama 3，每个自回归 LLM 在每个位置上用一个损失训练：预测下一个 token。DeepSeek-V3 在每个位置上增加了一个额外的损失：预测下一个之后的 token。671B 模型上额外的 14B 参数通过梯度流被蒸馏回主模型，训练好的 MTP 头在推理时被重新用作推测解码的草稿器，接受率达到 80%+。1.8× 生成吞吐量免费获得。本课根据 DeepSeek 技术报告构建顺序 MTP 模块，计算损失和共享头参数布局，并解释为什么 MTP 保持因果链而 Gloeckle 等人的原始并行 MTP 破坏了它。

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 10 · 04 (pre-training a mini GPT), Phase 10 · 15 (speculative decoding)
**Time:** ~60 minutes

## 学习目标

- 阐述 MTP 训练目标并推导跨预测深度的联合损失。
- 解释 Gloeckle 等人的并行 MTP 头（2024）与 DeepSeek-V3 的顺序 MTP 模块之间的区别，以及为什么顺序设计保持了因果链。
- 计算向预训练运行添加 MTP 模块的参数和内存开销。
- 从零实现一个 MTP 模块：共享嵌入、每深度 transformer 块、投影和共享输出头。

## 问题

下一 token 预测是标准的 LLM 训练目标。每个隐藏状态被监督只预测一件事：紧跟着的下一个 token。这是一个令人惊讶的弱信号。序列中的大部分信息扩展到一个 token 之外——结构、连贯性、事实准确性、算术流程。模型必须通过在数万亿 token 上累积许多单 token 信号来学习这些。

MTP 提问：如果每个隐藏状态同时被监督预测多个未来 token 会怎样？Gloeckle 等人（Meta，2024）证明这有帮助。他们的实现在骨干网络上放置了几个独立的输出头，每个预测不同的偏移量。并行、简单，但这些头看到相同的隐藏状态而没有任何层级精炼——并且预测没有因果链相连，因此它们不能用于推测解码。

DeepSeek-V3（2024 年 12 月）将 MTP 重新设计为在每预测深度保持因果链的顺序模块。模型从 `h_i^(0)` 预测 `t+1`，然后从一个新的隐藏状态 `h_i^(1)`（组合了 `h_i^(0)` 和 `E(t+1)` 嵌入）预测 `t+2`，依此类推。每个深度是自己小型 transformer 块。共享嵌入和共享输出头使参数开销适中。在 DeepSeek-V3 的规模上，MTP 模块跨 671B 主模型权重的额外 14B 参数。2% 的开销换来了更密集的训练信号和一个在推理时就绪的推测解码草案。

本课从零构建一个 MTP 模块和 D 深度损失。数学简洁。实现约 150 行。

## 概念

### 顺序 MTP 方案

DeepSeek-V3 在主模型之上添加 `D` 个 MTP 模块。每个模块 `k`（`k = 1..D`）预测深度 `k` 的 token——即，给定前缀到位置 `i` 时预测 `t_{i+k}`。

模块 `k` 包括：

- 一个具有自身注意力和 MLP 的 transformer 块 `T_k`。
- 一个投影矩阵 `M_k`，将上一深度的隐藏状态与下一深度的真实 token 嵌入组合。
- 共享嵌入 `E`（与主模型相同）。
- 共享输出头 `Out`（与主模型相同）。

在训练时，对于前缀到位置 `i`，每深度隐藏状态为：

```
h_i^(0) = 位置 i 的主模型骨干
h_i^(k) = T_k( M_k * concat(RMSNorm(h_i^(k-1)), RMSNorm(E(t_{i+k}))) )   for k >= 1
```

每深度预测为：

```
logits_{i+k} = Out(h_i^(k-1))   for k = 1..D
```

每深度损失是与真实 `t_{i+k}` 的交叉熵：

```
L_k = CE(logits_{i+k}, t_{i+k})
```

跨深度的联合损失：

```
L_MTP = (lambda / D) * sum_{k=1..D} L_k
```

`lambda` 是一个小的加权因子——DeepSeek-V3 在训练的前 10% 使用 0.3，之后使用 0.1。总训练损失是 `L_main + L_MTP`。

### 为什么是顺序的而非并行的

Gloeckle 的原始并行 MTP 有 D 个输出头，每个直接应用于 `h_i^(0)`。每个头从相同的骨干隐藏状态预测 `t_{i+k}`。这样训练良好，但预测不互相条件化。你不能使用 `head_1` 的输出来帮助 `head_2`——这些头并行触发。

DeepSeek-V3 的顺序设计从 `h_i^(k-1)` 加上实际的下一个 token 嵌入 `E(t_{i+k})` 构建 `h_i^(k)`。这保持了因果链：要预测 `t_{i+k+1}`，深度 `k+1` 的模块看到 `t_{i+k}` 是什么。这在结构上等同于自回归解码器消费自身输出的方式——使 MTP 模块可直接用作推测解码的草稿器。

在推理时：将 `h_i^(k-1)` 和草案 `t_{i+k}` 输入模块 `k+1`，得到对 `t_{i+k+1}` 的预测。重复。这正是 EAGLE 风格的草稿，使用训练好的 MTP 模块作为草稿网络。DeepSeek-V3 报告第一个 MTP 模块接受率 80%+，约 1.8× 加速比。

### 参数统计

对于一个隐藏维度为 `h`、词表大小为 `V` 的模型：

- 主模型：数十亿参数，加上一个大小为 `V * h` 的输出头。
- 共享输出头：复用主模型的头。无额外参数。
- 共享嵌入：复用主模型的嵌入。无额外参数。
- 每 MTP 模块：
  - 投影 `M_k`：`(2h) * h = 2h^2`。
  - Transformer 块 `T_k`：注意力（MHA 为 `4h^2`）加 MLP（SwiGLU 比率 8/3 通常为 `8h^2`）。每块约 `12h^2`。

每模块额外总计：`~14h^2`。对于 DeepSeek-V3 的 `h = 7168`，D = 1 模块：论文 `~14 * 7168^2 = ~720M` 参数。DeepSeek-V3 报告 14B——差异主要是 MTP 模块中的专家层也是 MoE。

### 推测解码回报

在预训练期间，MTP 模块使训练减慢约 10%（更多前向计算，额外损失）。回报是双重的：

1. 更密集的训练信号。每个隐藏状态看到 D+1 个监督目标。在 MMLU、GSM8K、MATH、HumanEval 上测量的效果：DeepSeek-V3 的消融中一致的几个百分点提升。

2. 推理时免费的推测解码草案。MTP 模块已经训练好预测接下来的几个 token。被重新用作草稿网络，它提供 80%+ 的接受率。在该级别，N=3 或 N=5 的推测解码提供 1.8× 吞吐量。10% 的训练时成本在你第一次运行推理时就回本了。

### 与 EAGLE 的关系

EAGLE 在预训练后单独训练一个小型草稿模型。MTP 将草稿烘焙到预训练中。两种方法汇聚到相似的接受率，但通过不同的流水线：

| 维度 | EAGLE-3 | MTP (DeepSeek-V3) |
|-----------|---------|------------------|
| 何时训练 | 预训练后 | 预训练期间 |
| 与已有权重向后兼容 | 是 | 否（需要重新训练） |
| 草稿参数 | 1-2 transformer 层 | 1 transformer 块 + 投影 |
| 接受率 | 0.88-0.92 | 深度 1 为 0.80+ |
| 超越加速的收益 | 仅推测解码 | 更密集的训练信号 + 加速 |

## 构建它

`code/main.py` 端到端构建一个 MTP 模块：共享嵌入、投影、transformer 块、共享输出头。然后计算短合成序列上的每深度交叉熵损失，并按组件打印参数量。32 个 token 的玩具词表使数字可读。

### 步骤 1：共享嵌入表

一个 `vocab_size x hidden` 表由主模型和在每个深度的每个 MTP 模块使用。不是第二份副本——字面上是同一个 tensor。

### 步骤 2：每深度组合

```python
def combine(prev_hidden, next_token_embed, M_k):
    # 沿特征维度拼接，然后投影到 hidden
    concat = rms_norm(prev_hidden) + rms_norm(next_token_embed)  # 向量加法作为替代
    projected = matvec(M_k, concat)
    return projected
```

真实 DeepSeek-V3 将两个 RMSNorm 后的向量拼接为 `[2h]`，并用 `h x 2h` 矩阵投影。玩具使用向量加法以求 stdlib 简洁。

### 步骤 3：深度 k 的 transformer 块

自注意力加 MLP。在玩具中，一个一层的线性注意力块和一个 SwiGLU MLP 在不需要 numpy 的情况下保持结构可见。

### 步骤 4：共享输出头

复用主模型的输出投影。在词表上的 logits。

### 步骤 5：每深度损失

softmax(logits) 与偏移量 `k` 处真实 token 的交叉熵。以 `lambda / D` 缩放因子在深度上聚合。

### 步骤 6：参数统计

打印总参数量、共享（嵌入、头部）计数和每模块额外计数。展示 MTP 额外量与主模型大小的比率。

## 使用它

MTP 已集成到 DeepSeek-V3（2024 年 12 月）和 DeepSeek-R1 系列中。在推理时：

- DeepSeek 自身的推理栈开箱即用地消费 MTP 模块作为推测解码器。
- 截至 2026 年 4 月，vLLM 和 SGLang 有 DeepSeek-V3 MTP 的集成路径。
- AMD 的 ROCm SGLang 教程展示了一个特定的 MTP 推测解码配置，在 V3 checkpoint 上测量到 1.8× 加速比。

在新建预训练运行中何时使用 MTP：

- 你掌控完整的预训练流水线，并想存储更密集的训练信号。
- 你知道你将大规模部署模型，并希望免费获得推测解码。
- 你的隐藏大小至少为 4096。在 1B 规模上，开销的伤害大于收益的帮助。

何时不用：

- 微调已有的预训练密集模型。MTP 模块是未经训练的。
- 研究模型，你需要一个干净的基线来比较。MTP 改变了架构。

## 练习

1. 运行 `code/main.py`。展示随着合成信号变强，每深度损失单调下降。修改合成以使用固定模式，验证深度 1 和深度 2 损失都收敛。

2. 为一个密集 70B 模型（hidden 8192, 80 layers）计算 D=1 MTP 模块的参数开销。与 DeepSeek-V3 报告的 14B 开销比较。解释为什么 DeepSeek 的数字更高：MTP transformer 块继承了相同的 MoE 结构，膨胀了每模块参数量。

3. 在玩具中实现 D=2：添加第二个 MTP 模块，接受 h^(1) 并预测 `t_{i+2}`。验证联合损失和参数统计匹配 DeepSeek 论文的公式 19-21。

4. 将玩具切换到并行 MTP（Gloeckle 风格）：在主隐藏状态之上添加 D 个输出头，每个预测不同的偏移量。测量每深度损失与顺序版本在相同合成信号上的比较。顺序版本应该对 k > 1 产生更低的深度 k 损失，因为它以中间预测为条件。

5. 使用训练好的 MTP 模块作为 EAGLE 风格草案：在推理时调用模块 k 以提出 `t_{i+k}`。在留出序列上测量这些草案 token 相对于主模型预测的接受率。如果你在玩具上达到 50%+，你就复现了经验的 MTP 作为草案特性。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| MTP 模块 | "额外的损失块" | 一个小型 transformer 块加投影，预测主模型前 k 位的 token |
| 预测深度 | "哪个偏移量" | 整数 `k`，使得模块 `k` 从前缀到位置 `i` 预测 `t_{i+k}` |
| 并行 MTP | "Gloeckle 风格" | 同一骨干隐藏状态上 D 个独立头，无条件链 |
| 顺序 MTP | "DeepSeek-V3 风格" | 每个模块以上一深度隐藏状态加下一 token 嵌入为条件；保持因果链 |
| 共享输出头 | "复用主头部" | MTP 模块调用主模型的 LM 头，而非单独的输出投影 |
| 共享嵌入 | "复用主表" | 相同的词嵌入表到处使用；无重复参数 |
| 投影矩阵 M_k | "组合隐藏 + 下一 token" | 一个 `h x 2h` 线性层，将前一个隐藏状态和目标 token 嵌入折叠到下一深度的输入中 |
| 联合损失 L_MTP | "平均额外损失" | 每深度交叉熵损失的算术平均，以 `lambda` 缩放 |
| 深度 1 接受率 | "MTP 草案多经常正确" | D=1 MTP 模块的 top-1 预测等于主模型 top-1 预测的比率；DeepSeek-V3 上 80%+ |
| Lambda 加权 | "额外损失的重要性" | 每深度缩放因子；DeepSeek-V3 训练开始时 0.3，之后 0.1 |
