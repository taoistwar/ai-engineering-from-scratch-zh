# 视频生成

> 图像是 2-D 张量。视频是 3-D 张量。理论相同；计算困难 10-100 倍。OpenAI 的 Sora（2024 年 2 月）证明了这是可能的。到 2026 年，Veo 2、Kling 1.5、Runway Gen-3、Pika 2.0 和 WAN 2.2 以 1080p 从文本发布生产级视频——而开源权重栈（CogVideoX、HunyuanVideo、Mochi-1、WAN 2.2）落后 12 个月。

**类型：** 构建
**语言：** Python
**前置条件：** 第八阶段 · 07（潜在扩散），第七阶段 · 09（ViT），第八阶段 · 06（DDPM）
**时间：** 约 45 分钟

## 问题

以 24fps 播放的 10 秒 1080p 视频是 240 帧 1920×1080×3 像素。每个剪辑约 1.5 GB 原始数据。像素空间扩散不可行。你需要：

1. **时空压缩。** 一个 VAE 将视频编码为时空补丁序列，而不是帧。
2. **时间一致性。** 帧需要在数秒内共享内容、光照和物体身份。网络必须建模运动。
3. **计算预算。** 对于相同模型大小，视频训练比图像昂贵 10-100 倍。
4. **条件化。** 文本、图像（首帧）、音频或另一个视频。大多数生产模型接受所有四种。

解决此问题的架构是应用于时空补丁的 **Diffusion Transformer (DiT)**，在巨大的（提示、字幕、视频）数据集上训练。与第 06 课相同的扩散损失。

## 概念

![视频扩散：补丁化、DiT、解码](../assets/video-generation.svg)

### 补丁化

用 3D VAE（学习的时空压缩）编码视频。潜在向量形状为 `[T_latent, H_latent, W_latent, C_latent]`。分割成大小为 `[t_p, h_p, w_p]` 的补丁。对于 Sora 风格模型，`t_p = 1`（每帧补丁）或 `t_p = 2`（每两帧）。一个 10 秒 1080p 视频压缩到约 20,000-100,000 个补丁。

### 时空 DiT

Transformer 处理扁平的补丁序列。每个补丁有 3D 位置嵌入（时间 + y + x）。注意力通常是因式分解的：

- **空间注意力** 在每帧的补丁内部。
- **时间注意力** 在相同空间位置跨帧。
- **完整 3D 注意力** 昂贵 16-100 倍；仅在低分辨率或研究中用。

### 文本条件化

与大型文本编码器的交叉注意力（Sora 用 T5-XXL，CogVideoX-5B 用 T5-XXL）。长提示很重要——Sora 的训练集有 GPT 生成的密集重新字幕，平均每个剪辑 200 个 token。

### 训练

在时空潜在向量上的标准扩散损失（ε 或 v 预测）。数据：网页视频 + ~100M 策划剪辑 + 合成文本字幕。计算：即使是小型研究运行也需要 10,000+ GPU 小时；Sora 规模需要 100,000+。

## 动手构建

`code/main.py` 模拟核心时空 DiT 思想：补丁化小型合成视频，添加每补丁位置嵌入，并通过补丁上的 transformer 风格注意力对整个序列去噪。无 numpy；纯 Python。我们展示了即使在 1-D 中，当相邻帧补丁共享去噪器和位置嵌入时，时间一致性也会涌现。

### 步骤 1：补丁化合成 1-D "视频"

```python
def make_video(T_frames=8, rng=None):
    # "视频"是遵循平滑轨迹的 1-D 值序列
    base = rng.gauss(0, 1)
    return [base + 0.3 * t + rng.gauss(0, 0.1) for t in range(T_frames)]
```

### 步骤 2：每帧位置嵌入

```python
def pos_embed(t, dim):
    return sinusoidal(t, dim)
```

### 步骤 3：去噪器看到整个序列

我们的微型网络不是独立地对每帧去噪，而是拼接所有帧值 + 它们的位置嵌入，并联合预测所有帧的噪声。

### 步骤 4：时间一致性测试

训练后，采样一个视频。测量帧到帧的增量。如果模型学到了时间结构，增量保持小于独立采样每帧。

## 缺陷陷阱

- **独立每帧采样 = 闪烁。** 如果在每帧上单独运行图像扩散，输出会闪烁，因为每帧的噪声是独立的。视频扩散通过注意力或共享噪声耦合帧来修复。
- **朴素 3D 注意力 = OOM。** 在 10 秒 1080p 潜在向量上的完整 3D 注意力是数千亿次操作。因式分解为空间 + 时间。
- **数据字幕比尺寸更重要。** Sora 相比之前工作的主要升级是在约 10 倍更详细的字幕上训练（GPT-4 重新标记的剪辑）。OpenAI 的技术报告对此很明确。
- **首帧条件化。** 大多数生产模型还接受图像作为首帧。这是"图像到视频"模式；训练包括此变体。
- **物理漂移。** 长剪辑（>10 秒）积累微小的不一致性。滑动窗口生成 + 关键帧锚定有帮助。

## 练习

1. **简单。** 在 `code/main.py` 中，比较 (a) 独立每帧采样，(b) 联合序列采样的帧到帧增量。报告增量的均值和方差。
2. **中等。** 添加首帧条件：将帧 0 固定在给定值，采样其余部分。测量固定值如何传播。
3. **困难。** 使用 HuggingFace diffusers 在本地 GPU 上运行 CogVideoX-2B。对 6 秒剪辑以 720p 计时 20 个推理步骤。分析时空注意力以识别瓶颈。

## 生产笔记：视频潜在向量是内存带宽问题

一个 24 fps 的 10 秒 1080p 剪辑是 240 帧 × 1920 × 1080 × 3 ≈ 1.5 GB 原始像素。经过 4× 视频 VAE 压缩（`2 × spatial × 2 × temporal`）后，潜在向量约为每个请求 100 MB。在批次 1 下通过时空 DiT 以 30 步运行，你每步通过 HBM 移动约 3 GB——内存带宽而非 FLOPs 是瓶颈。

三个生产旋钮，全部来自推理文献的推理章节：

- **跨 DiT 的张量并行（TP）。** 文本到视频模型通常 ≥10B 参数。跨 4 张 H100 的 TP=4 是标准；对于 405B 类模型 PP=2 × TP=2。每步延迟大致随 TP 线性下降，直到 all-reduce 墙。
- **帧批处理 = 连续批处理。** 在生成时，视频概念上是由注意力链接的帧批次。连续批处理（飞行中调度）适用：如果模型架构允许滑动窗口生成，开始渲染帧 `t+1`，同时返回帧 `t-1`。
- **剪辑级预填充缓存。** 对于图像到视频，首帧条件化类似于 LLM 的提示预填充：计算一次，在时间解码器传递之间重用。这实际上是视频的 KV 缓存。
