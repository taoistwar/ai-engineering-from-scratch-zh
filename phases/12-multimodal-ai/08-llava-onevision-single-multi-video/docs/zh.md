# LLaVA-OneVision：单图像、多图像、视频于一体的模型

> 在 LLaVA-OneVision（Li 等人，2024 年 8 月）之前，开源 VLM 领域有互不相干的分支：LLaVA-1.5 用于单图像，Mantis 和 VILA 等多图像模型，Video-LLaVA 和 Video-LLaMA 等视频模型。每个都在自己的基准上获胜，而在其他基准上失败。LLaVA-OneVision 认为，一个单一的课程可以训练一个模型在所有三种场景中占据主导地位，并且涌现的任务迁移效应（单图像技能导出到视频，多图像推理导出到单图像）超越了专家的总和。这个配方简单得令人意外：一个在不同场景间保持恒定的视觉 token 预算，加上一个从单图像到 OneVision（多图像）再到视频的显式课程。本课阅读预算、课程和涌现行为。

**Type:** Build
**Languages:** Python (stdlib, token budget solver + curriculum planner)
**Prerequisites:** Phase 12 · 05 (LLaVA), Phase 12 · 06 (any-resolution)
**Time:** ~180 minutes

## 学习目标

- 设计一个在单图像、多图像和视频输入之间保持恒定的视觉 token 预算。
- 排列一个训练课程，将技能从单图像迁移到视频，而不会发生灾难性遗忘。
- 解释为什么当课程设计正确时，一个单一模型在相同参数数量下优于专门的模型。
- 列举 LLaVA-OneVision 报告的三种涌现能力：多摄像头推理、标记集提示、iPhone 截图代理。

## 问题

图像、多图像和视频对模型施加不同的压力。

单图像需要高分辨率 token（AnyRes，约 2880 个视觉 token）来捕获 OCR 和细节。每个样本预算：一张图像，2880 个 token。

多图像需要多张中等分辨率的图像（每张约 576 个 token），以便跨图像推理能放入上下文。每个样本预算：4-8 张图像，每张 576 个，共 2300-4600 个 token。

视频需要许多低分辨率帧（池化后每帧约 196 个 token）来捕获时间动态。每个样本预算：8-32 帧，每帧 196 个，共 1600-6200 个 token。

如果训练独立的模型，你只选择一个预算。如果训练一个模型，你需要预算在不同场景间合理扩展，而不会使上下文爆炸。

在 OneVision 之前，默认答案是"训练一种场景，忽略其他"。Video-LLaVA 通过额外的训练阶段将视频改造到图像模型上。LLaVA-NeXT 通过平铺添加了多图像支持。没有哪个能干净地处理全部三种场景。

## 概念

### OneVision Token 预算

LLaVA-OneVision 选择每个样本约 3000-4000 个 token 的统一视觉 token 预算，按场景进行不同分配：

- 单图像：AnyRes-9（3x3 平铺 + 缩略图），每个平铺 384 分辨率下 729 个 patch，激进双线性池化 2x2 → 每平铺 182 个。总计：9 * 182 + 182 = 1820 个 token。或 AnyRes-4 每平铺 729 = 2916 + 729。
- 多图像：每张中等分辨率（384，不平铺），729 个 token 不池化。预算 6 张图像 → 4374 个 token。
- 视频：32 帧，384 分辨率，激进 3x3 双线性池化 → 每帧 81 个 token。总计：32 * 81 = 2592 个 token。

分配保持大致恒定的总 token 数。LLM 永远不会看到一个会炸毁其上下文的 batch。编码器在不同场景下产生不同的几何形状，但 LLM 消费相同的预算。

### 三阶段课程

LLaVA-OneVision 分三个阶段训练：

1. 单图像 SFT（阶段 SI）。所有数据都是单图像加文本。在高分辨率 AnyRes 输入上训练。这教的是感知、OCR 和细粒度理解。使用 LLaVA-NeXT 数据加上 OneVision 特定的单图像数据。
2. OneVision SFT（阶段 OV）。混合单图像 + 多图像 + 视频（均匀采样的帧）。在统一 token 预算上训练。这教会模型处理异构 batch 形状。不重置权重——从阶段 SI 继续。
3. 任务迁移（阶段 TT）。以目标任务混合继续训练，通常根据产品需求在多图像或视频上更侧重。可选的部署微调。

关键：课程顺序很重要。先训练视频或先训练多图像会产生比单图像优先更差的图像性能，即使使用相同的数据。论文对此进行了明确的消融。

### 为什么课程有效

单图像训练构建了感知基础。Patch token 携带细粒度的视觉特征；LLM 学会将它们与文本整合。多图像和视频引入了结构挑战（哪张图像是哪张，什么先发生），没有强大的感知基础很难学习。

如果你从一开始就一起训练所有场景，模型会欠拟合感知（每个 batch 中有限的单图像数据）而过拟合结构（大量的多图像/视频数据）。结果：一个能遵循跨图像推理模式但视觉上浅薄的模型。

课程排序让你从阶段 SI 获得感知强度，然后从阶段 OV 获得组合/时间推理能力，而不失去任何一方面。

### 涌现的跨场景技能

LLaVA-OneVision 论文报告了三种涌现的能力：

1. 多摄像头推理。分别在多图像和视频上训练；在推理时，被要求推理一个多摄像头驾驶场景。尽管在训练中从未见过这种格式，模型仍能正确整合视图。
2. 标记集提示。用户用编号标记标注图像中的物体；模型推理"标记 3 相对于标记 7 在做什么"。既没有训练过标记也没有训练过标注；从空间定位 + 多图像参照的组合中习得。
3. iPhone 截图代理。用户提供 iPhone 屏幕截图并要求规划下一次点击。在 UI 截图、用户工作流程视频和多图像前后对上进行训练。泛化到代理用例。

这些不是训练的任务；它们从课程的组合结构中涌现。

### 视觉 Token 池化

Token 预算需要池化。OneVision 在 2D patch 网格上使用双线性插值：24x24 = 576 个 patch 变为 12x12 = 144（2 倍因子）或 8x8 = 64（3 倍因子）。池化在 patch 网格空间中进行，而不是在 token 空间中，以保持局部性。

每场景的池化因子选择本身就是一个超参数。更少池化 = 更多 token = 更丰富的表示。更多池化 = 更少 token = 更多帧/图像可以放入。

### LLaVA-OneVision-1.5

2025 年的后续版本（LLaVA-OneVision-1.5，arXiv 2509.23661）在训练数据、模型权重和代码方面"完全开源"。在某些基准上与专有模型的差距相匹敌，并使该配方民主化。相同的课程，更多的数据，更好的基础 LLM。没有架构变化。

### 与 Qwen2.5-VL 的对比

Qwen2.5-VL（第 12.09 课）做出了不同的选择。它使用 M-RoPE 和动态 FPS 而不是固定池化。其预算随输入扩展——一分钟视频比五秒视频使用更多 token。LLaVA-OneVision 固定预算并扩展池化。两者都有效；它们在可配置性和可预测性之间进行权衡。

## 使用

`code/main.py` 是一个 OneVision 风格的 VLM 课程和预算规划器。给定每个样本的 token 预算和目标场景混合（比如 40% 单图像、30% 多图像、30% 视频），它：

- 按场景分配分辨率、池化因子和帧数。
- 检查每个场景是否适合共享预算。
- 报告预期的 token 数、LLM FLOPs 以及哪些场景 token 不足。
- 打印阶段训练计划。

用它来规划 OneVision 微调或检查 VLM 部署的每个请求成本。

## 产出

本课产出 `outputs/skill-onevision-budget-planner.md`。给定目标任务分布和每个样本的预算，它发出 AnyRes 因子、每帧池化、视频帧数和课程阶段权重。每当训练或微调统一场景 VLM 时使用此技能。

## 练习

1. 你的产品支持 80% 单图像、10% 多图像（2-4 张图像）、10% 视频（8-16 帧）。设计 token 预算。你会将从不需要大量多图像预算中节省下来的额外预算放在哪里？

2. 阅读 LLaVA-OneVision 第 4.3 节（涌现能力）。提出一种课程可能会解锁但论文未报告的第四种涌现技能。

3. 交换课程顺序——先训练多图像，然后单图像，然后视频。预测哪些基准会下降以及为什么。

4. 论文报告视频基准训练仅使用每个样本 8 帧。这能在推理时泛化到 30 秒的视频吗？首先崩溃的是什么——token 预算还是时间推理？

5. 24x24 patch 双线性池化至 12x12 是每维度 4 倍减少。用 Python 标准库实现池化，并验证每个 2x2 块的均值是否与双线性输出匹配。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| OneVision 场景 | "单图像、多图像或视频" | 统一 VLM 处理的三种输入形状之一；预算在此之间保持恒定 |
| Token 预算 | "每个样本多少个 token" | LLM 每个训练/推理样本所见的视觉 token 总数，通常为 3000-4000 |
| 课程 | "训练顺序" | 为了涌现迁移而选择的阶段排序（单图像 → 多图像 → 视频） |
| 双线性池化 | "Token 收缩" | 对 patch 网格（2D）应用双线性插值以减少 token 数同时保持局部性 |
| 涌现技能 | "未经训练，仍然有效" | 在推理时出现但没有匹配训练数据的能力，源于课程组合结构 |
| AnyRes-k | "k 平铺设置" | 固定分辨率的 k 个子平铺加一个缩略图，典型 k ∈ {4, 9} |
| 任务迁移 | "跨场景泛化" | 在单图像上习得的技能通过共享骨干网络应用到视频上（反之亦然） |
