# 多模态 RAG 与跨模态检索

> 视觉原生文档 RAG 只是其中的一个切片。生产级多模态 RAG 的范围更广——跨文本、图像、音频和视频进行检索，用于旅行规划（"帮我找一家安静、适合素食早午餐且自然光线充足的餐厅"）、医疗分诊（"什么伤情与这张照片 + 这些笔记匹配"）、电子商务（"搭配类似这张自拍的服装，我的尺码"）和现场服务（"诊断这个引擎声音加上零件照片"）等工作流。三篇 2025 年综述——Abootorabi 等人、Mei 等人、Zhao 等人——编纂了子问题：跨模态检索、检索融合、生成依据、多模态评估。本课阅读这些综述并设计生产流水线。

**Type:** Build
**Languages:** Python (stdlib, cross-modal retriever with fusion + grounded generator)
**Prerequisites:** Phase 12 · 23 (ColPali), Phase 11 (RAG basics)
**Time:** ~180 minutes

## 学习目标

- 设计跨模态检索：文本 → 图像、图像 → 文本、音频 → 视频等。
- 比较三种融合策略：分数融合、基于注意力的融合、MoE 融合。
- 解释生成依据：当来源是多种模态混合时，"引用你的来源"是什么样子。
- 列举 2025 年的三篇权威多模态 RAG 综述及其子问题分类法。

## 问题

单模态 RAG 是一个已解决的模式：嵌入查询，嵌入块，检索，填入 LLM。多模态 RAG 需要：

1. 多个检索头（每种模态需要在兼容空间中有嵌入）。
2. 跨模态检索结果的融合。
3. 跨模态引用来源的生成依据。
4. 覆盖跨模态信号的评估指标。

2025 年的综述都到达了相同的分类法。

## 概念

### 跨模态检索

给定模态 A 的查询，检索模态 B 的文档。三种模式：

1. 共享嵌入空间。CLIP 和 CLAP 产生共享空间中的文本 + 图像 / 文本 + 音频嵌入。跨模态余弦相似度直接可用。仅限于 CLIP 训练的配对。

2. 每种模态编码器 + 翻译。文本编码器 + 图像编码器 + 一个在空间之间映射的小型翻译模块。Gupta 等人的 Sen2Sen 和其他 2024 设计。灵活但增加复杂度。

3. VLM 作为编码器。使用 VLM 的隐藏状态作为检索表示。VLM 支持的任何模态都能工作。更高质量，更昂贵。

选择：CLIP / SigLIP 2 用于文本+图像；CLAP 用于文本+音频；VLM 隐藏状态用于前沿质量的跨模态。

### 融合策略

你检索到 10 个结果：5 张图像、3 段文本、2 个音频片段。如何合并？

分数融合（最便宜）。每种模态有自己的检索器，各自返回分数。在模态内归一化分数然后求和。简单，通常有效。

基于注意力的融合。拼接所有检索到的项，让一个小型注意力网络对它们进行加权。需要训练。

MoE 融合。门控网络路由到模态特定专家。不同的查询类型有不同的路由——视觉问题对图像加权更高。

生产默认：分数融合，对查询的主要模态有轻微偏置。如果 A/B 测试显示在你的领域有明确收益，则升级到 MoE。

### 生成依据

LLM 应引用哪个检索项驱动了每个声明。对于多模态：

- 文本来源：标准引用 `[1]`。
- 图像来源：`[img 3]` 附简短说明。
- 音频：`[audio 2 at 0:34]`。

使用包含依据的数据训练生成器：训练目标中的每个声明都标有来源索引。在推理时，模型自然发出引用。

### 2025 年综述

Abootorabi 等人（arXiv:2502.08826，"以任意模态提问"）：多模态 RAG 分类法。涵盖检索、融合、生成。最广泛的覆盖。

Mei 等人（arXiv:2504.08748，"多模态 RAG 综述"）：侧重于子任务基准和故障模式。适用于评估设计。

Zhao 等人（arXiv:2503.18016）：以视觉为重点的综述。在 ColPali 家族工作上很强。

通读三篇可了解截至 2025 年春季的最新进展。大多数子问题仍然是开放的。

### MuRAG——奠基性论文

MuRAG（Chen 等人，2022）是第一个多模态 RAG。从多模态知识库中检索图像 + 文本，生成答案。在 VLM 浪潮之前展示了可行性。现代系统（REACT、VisRAG、M3DocRAG）在其基础上构建。

### 生产旅行规划器示例

查询："帮我找一家安静、适合素食早午餐且自然光线充足的餐厅。"

流水线：

1. 分解查询。"安静" → 音频/评论关键词；"素食早午餐" → 菜单项；"自然光线" → 图像特征。
2. 按模态检索：
   - 文本检索评论："素食早午餐，安静氛围。"
   - 图像检索餐厅照片："自然光线，通透。"
   - 音频检索环境声音片段："低分贝，无音乐。"
3. 融合分数。每家餐厅有一个综合分数。
4. Top-k 餐厅 → VLM 生成器带所有证据 → 带引用的答案。

这远超文本 RAG。每种模态添加了文本单独缺失的信号。

### 代理式多模态 RAG

多跳：如果第一次检索未返回高置信度答案，LLM 重新表述并再次检索。第 14 阶段的代理式 RAG 模式在此适用。示例：

- 检索初始 top-10 → LLM 说"太吵，筛选 <40 dB" → 重新检索。
- 检索图像 → LLM 看到一张图像有菜单 → 检索菜单文本 → 回答。

增加了复杂度，但处理了单次检索无法处理的查询。

### 评估

跨模态评估仍然不成熟。常见的替代指标：

- 每种模态的回忆率@k。
- 融合后的 top-k 准确率。
- 人工评判的端到端满意度。
- 任务特定的（完成的预订、做出的购买）。

没有涵盖所有模态的标准基准。大多数论文在领域特定任务上进行评估。

## 使用

`code/main.py`：

- 三个模拟检索器（文本、图像、音频），在共享的餐厅语料上操作。
- 分数融合，使用可配置权重组合模态分数。
- 一个生成器存根，发出带引用的最终答案。
- 一个简单的代理循环，在置信度低时重新表述查询。

## 练习

1. 提出一个医疗分诊多模态 RAG：查询 = 伤情照片 + 文本症状。从什么知识库中检索什么模态？

2. 分数融合是简单的加权和。它有什么失败模式是 MoE 融合可以避免的？

3. 阅读 Abootorabi 等人的分类法（第 3 节）。三种规范子问题是什么，它们如何映射到你的选定产品？

4. 为旅行规划多模态 RAG 设计一个评估规范。什么指标涵盖图像回忆、音频回忆和综合正确性？

5. 代理式多跳 RAG 每次往返有延迟代价。在什么查询难度下准确率的收益能证明延迟是合理的？

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| 跨模态检索 | "查询一种模态，检索另一种" | 文本查询检索图像；图像查询检索文本；需要共享空间或翻译器 |
| 分数融合 | "组合分数" | 每种模态检索分数的加权和；最简单的融合 |
| MoE 融合 | "模态路由专家" | 门控网络选择每个查询应信任哪种模态的分数 |
| 有依据的生成 | "引用你的来源" | 答案中的每个声明都标有来源索引 |
| MuRAG | "第一个多模态 RAG" | 建立多模态 RAG 模式的 2022 年论文 |
| 代理式多跳 | "重新表述并重试" | 当首次置信度低时，LLM 重新查询检索器 |
