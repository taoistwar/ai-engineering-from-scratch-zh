# Qwen-VL 系列与动态 FPS 视频

> Qwen-VL 系列——Qwen-VL（2023）、Qwen2-VL（2024）、Qwen2.5-VL（2025）、Qwen3-VL（2025）——是 2026 年最具影响力的开源视觉语言模型家族。每一代都做出了一个决定性的架构赌注，开源生态系统在十二个月内纷纷复制：通过 M-RoPE 实现原生动态分辨率、带有绝对时间对齐的动态 FPS 采样、ViT 中的窗口注意力以及结构化的代理输出格式。到 Qwen3-VL，配方已经稳定：一个支持原生宽高比输入的 2D-RoPE-ViT 编码器、一个连接到大 Qwen3 语言基底的 MLP 投影器，以及强调 OCR、定位和代理行为作为一等公民目标的训练阶段。本课按时间顺序阅读这个家族，让你理解每个旋钮为什么在它现在的位置。

**Type:** Learn
**Languages:** Python (stdlib, M-RoPE encoder + dynamic-FPS sampler)
**Prerequisites:** Phase 12 · 06 (patch-n'-pack)
**Time:** ~120 minutes

## 学习目标

- 计算 M-RoPE 的三轴旋转（时间、高度、宽度），并解释为什么三者都需要。
- 为视频选择动态 FPS 采样策略，并推理每秒 token 数 vs 事件检测准确率的关系。
- 按顺序列举 Qwen-VL 的四代升级及其各自带来的能力。
- 连接 Qwen2.5-VL 风格的 JSON 代理输出格式，并解析来自 VLM 响应的结构化工具调用。

## 问题

Qwen-VL 于 2023 年 8 月发布，作为对 LLaVA-1.5 和 BLIP-2 的直接回应。Qwen 团队瞄准的差距是三个方面的：分辨率、视频和结构化输出。

分辨率：LLaVA-1.5 以 336x336 运行。对照片还好，但对中文发票或密集的电子表格截图毫无用处。Qwen-VL 的第一个创新是 448x448 和基于定位的边界框输出，让模型能够指向物体。

视频：Video-LLaMA 堆叠逐帧编码器并将其馈送到 LLM。对短视频片段有效，但对时间轴是信号关键的多分钟视频无效。Qwen 团队想要一个理解时间的单一编码器。

结构化输出：LLaVA 输出自由格式文本。代理需要 JSON。Qwen-VL 在显式的 JSON 输出格式上进行训练，包括作为文本的边界框坐标。

Qwen-VL 的每一代都扩展了这三个轴中的一个。

## 概念

### Qwen-VL（2023 年 8 月）

第一代：OpenCLIP ViT-bigG/14 作为编码器（2.5B 参数）、兼容 LLama 的 Q-Former（1 步，256 查询）、Qwen-7B 基础。贡献：

- 448x448 分辨率（当时开源 VLM 的 SOTA）。
- 定位：在具有显式坐标 token 输出的图像-文本对上训练。"The cat is at <box>(112, 204), (280, 344)</box>"。
- 从一开始就是中英文多语言训练。

当时的基准：在英语上与 GPT-4V 有竞争力，在中文上占据主导地位。定位监督是真正的头条新闻。

### Qwen2-VL（2024 年 9 月）——M-RoPE 与原生分辨率

Qwen2-VL 用原生动态分辨率 ViT 编码器替换了固定分辨率 + Q-Former 堆栈。关键变化：

- 原生动态分辨率。ViT 接受任何能被 28 整除的 HxW（patch 14，2x 空间合并）。一张 1120x672（40x24 合并 patch）的图像产生 960 个视觉 token。无需尺寸调整、无需平铺、无需缩略图。
- M-RoPE（多模态 RoPE）。每个 token 携带 3D 位置（t, h, w）而不是 1D。对于图像 t=0，对于视频 t=帧索引。RoPE 以每个轴的频率旋转查询/键向量。没有位置嵌入表。
- MLP 投影器。放弃 Q-Former；在合并后的 patch token 上使用 2 层 MLP。
- 动态 FPS 视频。默认以 1-2 FPS 采样视频，但模型接受任意帧数。

结果：Qwen2-VL-7B 在多个多模态基准上匹配 GPT-4o，并在 DocVQA 上击败它（94.5 vs 88.4）。架构变化是决定性的举措。

### Qwen2.5-VL（2025 年 2 月）——动态 FPS + 绝对时间

Qwen2.5-VL 的重大转变是视频。动态 FPS 不仅仅是"在需要时采样更多帧"。论文形式化了以下几点：

- 绝对时间 token。使用实际时间戳而非位置索引（帧 0、1、2...）。"At 0:04, the cat jumps." 模型看到与帧 token 交错的 `<time>0.04</time>` token。
- 动态 FPS。对慢动作以 1 FPS 采样，对动作以 4+ FPS 采样。用户或训练者选择；M-RoPE 进行适配。
- ViT 中的窗口注意力。空间注意力被窗口化（块内局部）以提高吞吐量；每隔几层添加全局注意力。
- 显式 JSON 输出格式。在工具调用数据上训练："{\"tool\": \"click\", \"coords\": [380, 220]}"。开箱即用即可作为代理使用。
- MRoPE-v2 缩放。位置根据最大输入尺寸进行缩放，使 10 分钟的视频不会超出频率范围。

基准：Qwen2.5-VL-72B 在大多数视频基准上击败 GPT-4o，在文档上匹配 Gemini 2.0，并设定开源模型在 GUI 定位上的 SOTA（ScreenSpot：84% 准确率 vs GPT-4o 的 38%）。

### Qwen3-VL（2025 年 11 月）

Qwen3-VL 是一个增量式升级，巩固而非重新发明：更大的 LLM 骨干网络（Qwen3-72B）、扩大训练数据、改进 OCR、通过 Qwen3 "思考模式" 增强推理能力。ViT 和 M-RoPE 继续保留。论文关注数据和训练改进而非架构。

家族启示：到 2025 年，Qwen-VL 架构已趋于稳定。后续世代扩展的是计算和数据，而非原语。

### M-RoPE 的数学原理

经典 RoPE 使用配对坐标按位置 `m` 旋转查询 `q`（维度 `d`）：

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE 将隐藏维度分成三个波段。假设 `d = 96`。分配 32 维度给时间、32 给高度、32 给宽度。每个波段由其自身的轴位置旋转。位于 (t=5, h=10, w=20) 的 patch 获得应用于其三个波段的旋转 `R_t(5)`、`R_h(10)`、`R_w(20)`。

文本 token 使用 `t = text_index, h = 0, w = 0`（或标准化选择）以保持兼容性。视频帧使用 `t = frame_time, h = row, w = col`。单图像使用 `t = 0`。

好处：一种位置编码处理文本、图像和视频，无需分支代码或不同的位置表。

### 动态 FPS 采样逻辑

给定一段时长为 `T` 秒的视频和一个目标 token 预算 `B`：

1. 计算你能承受的最大 FPS：`fps_max = B / (T * tokens_per_frame)`。
2. 从 `{1, 2, 4, 8}` 中选择满足 `fps <= fps_max` 的目标 FPS。
3. 如果运动量高（光流启发式或显式用户要求），选择更高的 FPS。如果运动量低，选择更低的。
4. 以选定的 FPS 均匀采样；在帧之间插入 `<time>t</time>` token。

Qwen2.5-VL 隐式地训练此逻辑；在推理时，用户通过 `fps` 参数控制。一段 60 秒的动作序列以 4 FPS 且每帧 81 个 token = 19440 个 token，在 32k 上下文中可管理。

### 结构化代理输出

Qwen2.5-VL 的代理训练显式地针对结构化工具调用：

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

解析是确定性的：对模型输出进行 JSON.parse。相比之下，自由格式的 "click at (1024, 512)" 需要正则表达式和歧义处理。这种转变是 Qwen2.5-VL 的 ScreenSpot 分数从 Qwen2-VL 的 55% 跃升至 84% 的原因。

## 使用

`code/main.py` 实现了：

- 对一个混合文本、图像 patch 和视频帧的打包序列进行 M-RoPE 位置计算。
- 动态 FPS 采样器：给定（时长、预算、运动级别），选择 FPS 并发出帧时间戳。
- 一个玩具 Qwen2.5-VL JSON 输出解析器，处理带有坐标字段的工具调用响应。

运行它，然后感受将一段 5 分钟视频从固定 FPS 切换到动态 FPS 时的差异。

## 产出

本课产出 `outputs/skill-qwen-vl-pipeline-designer.md`。给定一个视频任务（监控、代理、动作识别、无障碍），它发出 Qwen2.5-VL 配置（帧预算、FPS 策略、窗口注意力标志、代理输出模式）和延迟估算。每当为视频产品部署 Qwen-VL 家族模型时使用此技能。

## 练习

1. 计算一个位于 (t=3, h=5, w=7) 的 patch 的 M-RoPE 旋转，隐藏维度为 48（每个波段 16 个，基础 theta 10000）。展示每个波段前三对旋转角度。

2. 一段 10 分钟的安全摄像头录像以 1 FPS 产生多少帧？在 384 分辨率及 3x 池化下，总共多少个 token？Qwen2.5-VL 的默认 32k 上下文能否处理？

3. 为一个 30 秒的网球回合 vs 一个 30 秒的菜谱演示 vs 一个 30 秒的 UI 代理录屏选择 FPS。使用动态 FPS 逻辑为每个论证理由。

4. Qwen2.5-VL 完全放弃了 Q-Former。为什么一个简单的 MLP 在 2025 年有效而在 2023 年无效？（提示：数据规模和编码器质量。）

5. 将三个 Qwen2.5-VL JSON 工具调用输出解析为 Python dict。对于格式错误的 JSON 会有什么失败情况？Qwen 烹饪书推荐了什么恢复策略？

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| M-RoPE | "多模态 RoPE" | 三维旋转位置嵌入，在隐藏维度中分为时间、高度和宽度波段 |
| 动态 FPS | "智能采样" | 基于运动、时长和 token 预算为每段视频选择的帧采样率 |
| 绝对时间 token | "时间戳 token" | 在序列中交错的 `<time>t</time>`，使模型看到实际秒数而非帧索引 |
| 窗口注意力 | "局部注意力" | 空间自注意力限于小窗口以提高速度；周期性添加全局注意力 |
| 结构化代理输出 | "JSON 模式" | 训练数据监督，教导 VLM 输出可解析的 JSON，包含坐标和工具名称 |
| min_pixels / max_pixels | "分辨率边界" | Qwen2.5-VL 的每请求控制，限制总像素数从而限制 token 数 |
| 定位 | "指出来" | 以文本 token 形式输出边界框坐标；自从 Qwen-VL v1 开始使用 |
