# InternVL3：原生多模态预训练

> InternVL3 之前的每个开源 VLM 都遵循相同的三步配方：取一个在万亿文本 token 上训练的文本 LLM，加上一个视觉编码器，然后微调接缝。这能工作但有对齐债务——文本 LLM 已将其全部预训练预算花在纯文本上，并不会原生理解视觉 token。当事后添加视觉时，LLM 必须重新学习如何将视觉输入与其文本推理关联起来，同时不忘记文本能力。InternVL3（Zhu 等人，2025 年 4 月）拒绝了事后挂载的方法：一次预训练运行，文本和多模态从第一步开始交错训练。结果是，在 78B 开源参数下，在 MMMU-Pro 上匹配 Gemini 2.5 Pro。本课阅读原生预训练的案例，以及采用这种方式时会改变什么。

**Type:** Learn
**Languages:** Python (stdlib, training-corpus mixer)
**Prerequisites:** Phase 12 · 05, Phase 12 · 07 (recipes)
**Time:** ~120 minutes

## 学习目标

- 解释为什么事后 VLM 训练会累积对齐债务，引用三种可测量的症状（灾难性遗忘、答案偏移、图文不一致）。
- 描述 InternVL3 的原生预训练语料混合，以及为什么文本 : 交错 : 标题的比例很重要。
- 将 V2PE（可变视觉位置编码）与 Qwen2-VL 的 M-RoPE 进行比较。
- 列举 Visual Resolution Router (ViR) 和解耦视觉语言部署 (DvD) 优化。

## 问题

事后 VLM 训练是默认方式。LLaVA、BLIP-2、Qwen-VL、Idefics——都取一个已预训练的 LLM（Llama、Vicuna、Qwen、Mistral）并添加视觉。训练阶段通常如下：

1. 冻结 LLM + 冻结视觉编码器 + 可训练投影器，在标题对上训练以对齐嵌入。
2. 解冻 LLM，在指令数据（LLaVA-Instruct、ShareGPT4V）上训练。
3. 可选的任务特定微调。

对齐债务显示出三种症状：

- 灾难性遗忘。事后 VLM 遗忘纯文本技能。GSM8K 分数下降 5-10 分。Hellaswag 分数下降。纯文本代理退化。
- 答案偏移。对相同视觉问题的小措辞变化会得到不同的答案。视觉编码器与 LLM 的连接比 LLM 自己的 token 更弱。
- 图文不一致。VLM 可以正确描述图像，然后回答一个与其自身描述相矛盾的问题。视觉 token 不参与 LLM 的内部一致性检查，不像文本那样。

这些症状已被充分记录。MM1.5 第 4 节对其进行了量化。LLaVA-OneVision 的消融中也有暗示。原生预训练是答案。

## 概念

### 原生多模态预训练

InternVL3 从第一步开始在原生多模态语料上从头训练。混合比例为：

- 40% 纯文本数据（FineWeb、Proof-Pile-2 等）
- 35% 交错图像-文本数据（OBELICS、MMC4 风格）
- 20% 配对图像-标题数据
- 5% 视频-文本数据

视觉 token、文本 token 和跨模态交互从第一个梯度步骤就参与同一个损失函数。没有对齐预训练，没有投影器冻结阶段，没有需要恢复的灾难性遗忘。

对于基础模型，训练是一个单一阶段。指令微调随后进行，但基础模型已经将视觉 token 理解为一等公民。

### V2PE（可变视觉位置编码）

Qwen2-VL 使用具有固定轴分配的 M-RoPE。InternVL3 引入了 V2PE：位置编码根据模态类型（文本、图像、视频）而变化，具有可学习的缩放。在实践中：

- 文本 token 获得 1D 位置（文本索引）。
- 图像 patch 获得 2D 位置（行，列）。
- 视频帧获得 3D 位置（时间，行，列）。

三者共享相同的 RoPE 频率基础，但每个波段的隐藏维度分配是一个可学习的参数，而非固定分割。在预训练期间自由地在时间与空间频率分辨率之间进行权衡。

V2PE 的消融声明：在相同计算量下，视频基准比 M-RoPE 高 1-2 分。不是革命性的，但更干净。

### Visual Resolution Router (ViR)

部署优化。并非所有图像都需要全分辨率编码。一张低细节的单物体照片在 1280px 原生编码下浪费 token。ViR 是一个小型分类器，在编码前预测回答问题所需的最小分辨率。

路由有三个层级：低分辨率（256 个 token）、中等（576 个）、高（2048+）。对于生产流量中 60% 的查询，低或中等分辨率就足够了。净效果：同等质量下 2-3 倍吞吐量。

### 解耦视觉语言部署 (DvD)

当服务大型 VLM 时，视觉编码器每张图像运行一次，但 LLM 对每个输出 token 进行自回归运行。两个组件的瓶颈不同（视觉 = 用于卷积 + 注意力的 GPU 内存带宽；LLM = KV 缓存）。DvD 将它们拆分到不同的 GPU 上，并在两者之间进行流式传输。

对于 8B + 400M 编码器模型，DvD 相比放在同一 GPU 上大约使每节点吞吐量翻倍。

### 单阶段 vs 多阶段质量

InternVL3 的主要基准声明：在 78B 参数下匹配 Gemini 2.5 Pro 的 MMMU-Pro。在 38B 下匹配 GPT-4o。在 8B 下领先开源 8B 排行榜。全部使用单阶段预训练 + 指令微调配方。

对齐债务假说是可测量的：InternVL3-8B 在每单位视觉基准增益上比 Qwen2.5-VL-7B 损失更少的文本基准分数（MMLU、GSM8K）。该模型更像是一个通才，因为训练是一体的，而非两部分的。

### InternVL3.5 与 InternVL-U

InternVL3.5（2025 年 8 月）扩展了该配方。相同的原生预训练方法，更多数据，更多参数。MMMU 的提升是渐进的。

InternVL-U（2026）添加了统一生成——在同一骨干网络上通过 MMDiT 头进行图像输出。"U" 代表 "Understanding + generation"，追求 Transfusion 风格的统一模型（第 12.13 课）。相同的原生预训练骨干网络同时支持理解和生成头。

### 原生预训练的权衡

原生预训练不是免费午餐：

- 计算。从头训练新的 VLM 与训练文本 LLM 成本相同——数百万 GPU 小时。事后适配复用现有 LLM 权重，节省大部分成本。
- 数据。大规模交错图像-文本语料很稀缺。OBELICS 是 1.41 亿文档；MMC4 是 5.71 亿。纯文本就有 15T token。多模态预训练数据的稀缺性是一个硬约束。
- 基础 LLM 复用。原生预训练放弃了稍后插入新 LLM 的选项。事后方法允许你通过仅重新训练适配器来将 Llama-3.1 切换为 Llama-4。

InternVL3 的赌注：对齐债务比复用损失更糟糕。基准支持这一主张。生产它的成本阻碍了其他实验室廉价复制。事后 VLM 将继续存在，因为它们对大多数项目来说仍然更便宜。

## 使用

`code/main.py` 是一个训练语料混合器和 ViR 路由器模拟器。它：

- 接受目标语料混合（%文本、%交错、%标题、%视频），并计算每种模态的预期步骤数。
- 在一个查询 batch 上模拟 ViR 路由（分布：50% 低细节、30% 中等、20% 高细节），并报告平均 token 数。
- 报告给定编码器 vs LLM FLOPs 的 DvD 吞吐量估算。
- 打印事后 vs 原生预训练在参数、计算、数据以及预期对齐债务症状方面的对比。

## 产出

本课产出 `outputs/skill-native-vs-posthoc-auditor.md`。给定一份提出的 VLM 训练计划，它审核是否应选择原生方式还是事后方式，标记对齐债务风险，并推荐语料混合。当你在规划一个新的开源 VLM 项目且需要选择训练策略时使用此技能。

## 练习

1. 估算 InternVL3-8B（原生预训练）和 LLaVA-OneVision-7B（事后）之间的计算差距。GPU 小时之比大约是多少？什么解释了这个差距？

2. InternVL3 报告 40% 文本 / 35% 交错 / 20% 标题 / 5% 视频。如果你的目标任务以视频为主，提出一个新的比例并论证为什么基础模型仍然需要大量的文本和标题数据。

3. 阅读 MM1.5 第 4 节关于遗忘的内容。指出事后训练显示出最大退化的确切基准。退化造成了多大代价？

4. ViR 将 60% 的流量路由到低分辨率编码。哪种类型的查询它可能会错误路由（发送到低分辨率而实际需要高分辨率）？提出三种路由器故障模式。

5. DvD 将视觉和 LLM 拆分到不同的 GPU 上。在什么流量模式下 DvD 反而会损害而非帮助吞吐量？

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| 原生多模态预训练 | "从头一起" | 文本 + 图像 + 视频 token 从步骤 1 开始参与损失函数，而非事后挂载 |
| 对齐债务 | "事后处罚" | 将视觉挂载到冻结 LLM 后产生的文本技能和答案一致性的可测量退化 |
| V2PE | "可变视觉位置编码" | InternVL3 的 M-RoPE 继任者，每种模态具有可学习的位置编码分配 |
| ViR | "分辨率路由器" | 在编码前为每个查询选择最低所需分辨率的小型分类器，节省推理 token |
| DvD | "解耦部署" | 视觉编码器在一个 GPU 上，LLM 在另一个 GPU 上，带流式移交；使大型 VLM 的吞吐量翻倍 |
| InternVL-U | "统一理解 + 生成" | 2026 年后续版本，在原生预训练骨干网络上添加图像生成头 |
| 交错语料 | "OBELICS / MMC4" | 具有自然阅读顺序的文本和图像文档；原生预训练的原材料 |
