# MIO 与任意模态到任意模态的流式多模态模型

> GPT-4o 发布了一款大多数开源模型无法复制的产品：一个能听声音、看视频并实时回应的智能体。2024 年底开源生态系统的答案是 MIO（Wang 等人，2024 年 9 月）。MIO 对文本、图像、语音和音乐进行 token 化，在交错序列上训练一个因果 Transformer，并能从任意模态生成任意模态。AnyGPT（Zhan 等人，2024 年 2 月）是概念验证；MIO 是扩展版；Unified-IO 2（Allen AI，2023 年 12 月）是包含视觉 + 动作定位的变体。本课阅读任意到任意的模式——四种分词器，一个 Transformer，流式友好的解码。

**Type:** Learn
**Languages:** Python (stdlib, four-modality token allocator + streaming decode loop)
**Prerequisites:** Phase 12 · 11 (Chameleon), Phase 6 (Speech and Audio)
**Time:** ~120 minutes

## 学习目标

- 设计一个托管文本、图像、语音和音乐 token 而不冲突的共享词表。
- 在压缩 + 重建权衡方面比较 SEED-Tokenizer（图像）和 SpeechTokenizer residual-VQ（语音）。
- 解释构建任意到任意生成的四阶段课程。
- 列举三种开源任意到任意的配方及其主要权衡：MIO、AnyGPT、Unified-IO 2。

## 问题

声称统一多模态模型很容易，但要大规模构建则很难。直到 2024 年，大多数"任意到任意"系统都是流水线化的：视觉模型 → 文本表示 → 语音模型 → 音频。每一步跳跃损失信息、增加延迟并复杂化训练。GPT-4o 的演示视频展示了毫秒级响应的单一模型替代方案；开源系统滞后了数月。

工程挑战：

- 每种模态都必须有分词器，以无损-足够的方式进行压缩以便重建，并以 Transformer 可以消费的速率产生 token。
- 单一词表必须为文本（32k+）、图像（16k+）、语音（4k+）、音乐（8k+）分配空间。至少四万多个条目。
- 训练数据必须覆盖每种输入-输出对（文本→图像、图像→语音、语音→图像等），否则模型必须进行组合。
- 推理必须足够快地流式输出 token 以实现对话延迟（首个音频字节时间 <500ms）。

## 概念

### 四种模态的四种分词器

MIO 的分词器栈：

- 文本：标准 BPE，词表约 32000。
- 图像：SEED-Tokenizer（2023）——带离散码本的量化 VAE，4096 个条目，每张图像 32x32 个 token。
- 语音：SpeechTokenizer residual-VQ（2023）——将 16kHz 波形编码为 8 个层级码本；第一层是粗粒度内容，后续层添加韵律和说话人身份。
- 音乐：类似的 residual-VQ（Meta 的 MusicGen / Encodec 家族），4-8 个码本。

每种模态产生整数 token。token 在共享词表中获得不相交的 ID 范围：

```
text:   0..31999
image:  32000..36095  (4096 个图像 token)
speech: 36096..40191  (4096 个语音基础 token，加上残差层)
music:  40192..48383  (8192 个音乐 token)
sep:    48384..48390  (<image>, <speech>, <music>, </...>, 等)
```

总计：约 48k 词表。输入嵌入和输出投影覆盖全部。

### 流式解码

语音生成使用 residual-VQ。Transformer 预测基础（第 0 层）语音 token；并行解码的残差量化器预测后续层。每个第 0 层 token 在 16kHz 下大约是 50ms 的音频。

流式模式：

1. 用户对着话筒说话；实时音频分词器每 50ms 发出语音 token。
2. MIO 在 token 到达时消费它们（提示预填充 + 增量前向传播）。
3. 输出 token 以流式生成；并行语音解码器将它们转换为音频样本，延迟约 50-150ms。
4. 首个音频字节时间：MIO 论文中约 300-500ms，接近 GPT-4o 的约 250ms。

Mini-Omni（arXiv:2408.16725）、GLM-4-Voice（arXiv:2412.02612）和 Moshi（arXiv:2410.00037）是互补的流式语音-LLM 设计。Moshi 特别是在单个 GPU 上实现了 160ms 的往返延迟。

### 四阶段课程

MIO 的训练课程：

1. 阶段 1——对齐。大规模模态配对语料：文本-图像、文本-语音、文本-音乐。每对使用自己的 token 词表段。训练共享词表。
2. 阶段 2——交错。多模态交错文档（包含图像 + 视频的博客、带转录的播客等）。训练跨模态上下文。
3. 阶段 3——语音增强。额外的音频数据以提升语音质量而不损失文本能力。
4. 阶段 4——SFT。跨模态指令微调：VQA、标题生成、旁白、语音到语音对话。

缺少一个阶段会降低特定能力：跳过阶段 2，模型失去跨模态上下文；跳过阶段 3，语音质量差。

### 视觉思维链

MIO 引入了视觉思维链：模型发出中间图像 token 作为推理步骤。对于"这只猫在爬树吗？"，模型：

1. 发出渲染场景的 `<image>` token（来自输入图像或草图）。
2. 发出分析草图的文本。
3. 发出最终答案。

渲染的中间图像充当便签。在空间推理任务上基准得到了提升。这个思路镜像了文本推理的思维链。

### 任意到任意的竞争者

- AnyGPT（arXiv:2402.12226）：4 种模态（文本、图像、语音、音乐），类似设计。
- Unified-IO 2（arXiv:2312.17172）：增加了视觉动作输出、深度、法线。更多任务多样性，规模更小。
- NExT-GPT（arXiv:2309.05519）：LLM + 模态特定扩散解码器。不是单一模型方法。
- CoDi（arXiv:2305.11846）：可组合扩散；通过共享潜在空间实现任意到任意。

MIO 是最接近纯 token 任意到任意的模型。AnyGPT 是其概念祖先。

### 延迟预算

对于对话产品，每个组件的延迟都很重要：

- 麦克风到音频 token：~50ms。
- 预填充（音频 token + 历史）：在 8B 模型上约 100ms。
- 首个输出 token：~50ms。
- 并行 residual-VQ + 语音解码器：~100-150ms。

首个音频字节总时间：最小约 300ms。GPT-4o 声称约 250ms。Moshi 声称 160ms。按照公开基准，MIO/AnyGPT 在 400-600ms 范围内。

### 为什么任意到任意仍然困难

即使在 2026 年，开源任意到任意模型在两个轴上仍落后于闭源模型：

- 语音质量。residual-VQ 分词器是有损的；对话语音与 ElevenLabs 级别的语音相比听起来像机器人。
- 跨模态推理。要求模型"根据你所看到的唱一首歌"仍然比纯视觉任务更容易失败。

这些是开放的研究问题。Qwen3-Omni（第 12.20 课）是 2025 年最先进的开源尝试。

## 使用

`code/main.py`：

- 定义四种模态的词表分配并打印。
- 通过分词器路由器路由一个多模态输入列表（文本、图像、音频片段、音乐）。
- 模拟文本到语音响应的流式解码，并进行延迟计数。
- 给定编码器、预填充和解码器延迟，计算预期的首个音频字节时间。

本课产出 `outputs/skill-any-to-any-pipeline-auditor.md`。给定对话产品规格（输入模态、输出模态、延迟目标），它审核 MIO 家族的设计选择并计算延迟预算。

## 练习

1. 你的产品接受语音输入并返回语音输出。端到端延迟预算目标是多少？列出花费时间的组件。

2. SpeechTokenizer residual-VQ 使用 8 个码本。提出为什么并行解码残差层是必要的（相对于顺序解码），以及它带来的延迟节省。

3. 你的词表有 32k 文本 + 4k 图像 + 4k 语音。添加 8k 音乐和约 10 个分隔符。在隐藏维度 4096 下嵌入矩阵的参数成本是多少？

4. 视觉思维链发出中间图像。哪种类型的问题受益？哪种类型因额外的 token 而受损？

5. 阅读 Moshi（arXiv:2410.00037）。描述其"内心独白"技术，并与 MIO 的视觉思维链进行比较。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| 任意到任意 | "多模态输入/输出" | 一个能够接受并发出文本、图像、语音和音乐的单模型，任意方向均可 |
| Residual-VQ | "语音分词器栈" | 多码本 token 化，每层添加信息；基础层是内容，后续层是韵律 |
| SEED-Tokenizer | "图像编码" | MIO 使用的具有 4096 条目码本的离散图像分词器 |
| 视觉思维链 | "视觉便签" | 模型在最终答案之前生成中间图像作为推理步骤 |
| 首个音频字节时间 | "TTFAB" | 从用户语音到首次音频输出的延迟；<500ms 才有对话感 |
| 四阶段课程 | "训练配方" | 对齐 → 交错 → 语音增强 → SFT，按此顺序 |
