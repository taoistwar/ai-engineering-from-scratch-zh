# LLM 路由层 — LiteLLM、OpenRouter、Portkey

> 提供者锁定代价高昂。不同的工具调用工作负载适合不同的模型。路由网关提供一个 API 界面、重试、故障转移、成本追踪和保护栏。2026 年有三种原型占主导：LiteLLM（开源自托管）、OpenRouter（托管 SaaS）、Portkey（生产级，2026 年 3 月开源）。本课程点明决策标准并演练一个标准库路由网关。

**Type:** Learn
**Languages:** Python（stdlib，路由 + 故障转移 + 成本跟踪器）
**Prerequisites:** Phase 13 · 02（函数调用），Phase 13 · 17（网关）
**Time:** ~45 分钟

## 学习目标

- 区分自托管、托管和生产级路由选项。
- 实现一个在定义优先级顺序中对提供者失败进行重试的回退链。
- 跟踪跨提供者的每次请求成本及令牌使用情况。
- 在 LiteLLM、OpenRouter 和 Portkey 之间为给定的生产约束做出决定。

## 问题

需要提供者路由的场景：

1. **成本。** Claude Sonnet 的成本是 Haiku 的 3 倍。对于分诊任务，Haiku 足够了；对于合成任务，Sonnet 值得。按请求路由。

2. **故障转移。** OpenAI 有一天状态不好。每个请求都失败。你希望在不重新部署的情况下自动回退到 Anthropic。

3. **延迟。** 一个实时聊天 UI 需要快速的首令牌时间。批量摘要器则不需要。按延迟 SLA 路由。

4. **合规。** 欧盟用户必须留在欧盟区域内。按区域路由。

5. **实验。** 对同一工作负载进行 A/B 测试两个模型。按测试桶路由。

在每个集成中手工编码所有这些都是重复的。路由网关提供一个 OpenAI 兼容的 API 并处理其余部分。

## 概念

### OpenAI 兼容代理形态

每个人都说 OpenAI 形态。路由网关暴露 `/v1/chat/completions`，接受 OpenAI 模式，并在内部代理到 Anthropic / Gemini / Cohere / Ollama / 任何提供者。客户端无关紧要。

### 模型别名

你的代码使用 `our_smart_model` 而不是 `claude-3-5-sonnet-20251022`。网关将别名映射到实际模型。当 Anthropic 发布 Claude 4 时，你在服务器端更改别名；你的代码丝毫不必修改。

### 回退链

```
primary: openai/gpt-4o
on 5xx: anthropic/claude-3-5-sonnet
on 5xx: google/gemini-1.5-pro
on 5xx: refuse
```

网关在配置中定义这个。重试在预算内计算，以便回退级联不会爆炸成本。

### 语义缓存

完全相同或几乎相同的提示词命中缓存而不是提供者。在重复的代理循环上可节省 30% 到 60%。键是基于嵌入的；几乎相同的提示词共享一个缓存槽。

### 保护栏

网关级别：

- **PII 编辑。** 发送提示词前基于正则表达式或 ML 的过滤。
- **策略违规。** 拒绝包含禁止内容的提示词。
- **输出过滤器。** 清洗补全内容以防泄露。

Portkey 和 Kong 都提供了意见化的保护栏。LiteLLM 将它们作为可选项。

### 每个密钥的速率限制

一个 API 密钥 = 一个团队。每个密钥的预算防止一个团队消耗共享配额。大多数网关支持此功能。

### 自托管 vs 托管的权衡

| 因素 | LiteLLM（自托管） | OpenRouter（托管） | Portkey（生产） |
|------|-------------------|-------------------|-----------------|
| 代码 | 开源、Python | 托管 SaaS | 开源（2026 年 3 月）+ 托管 |
| 设置 | 部署代理 | 注册 | 任意 |
| 提供者 | 100+ | 300+ | 100+ |
| 计费 | 你自己的密钥 | OpenRouter 额度 | 你自己的密钥 |
| 可观测性 | OpenTelemetry | 仪表盘 | 完整 OTel + PII 编辑 |
| 最适合 | 想要完全控制的团队 | 快速原型 | 带合规的生产 |

LiteLLM 在你有 SRE 团队并想要数据主权时胜出。OpenRouter 在你想要单一订阅且无基础设施时胜出。Portkey 在你需要开箱即用的保护栏和合规时胜出。

### 成本追踪

每个请求携带 `provider`、`model`、`input_tokens`、`output_tokens`。乘以每个模型的每个令牌价格（从网关维护的定价表拉取）。按用户/团队/项目聚合。

### MCP 加路由

一个网关可以同时路由 LLM 调用和 MCP 采样请求。当采样请求的 modelPreferences 偏好特定模型时，网关转换到正确的后端。这是第 13 阶段 · 17（MCP 网关）和本课程的路由网关有时合并为一个服务的地方。

### 路由策略

- **静态优先级。** 列表中第一个；错误时回退。
- **负载均衡。** 轮询或加权。
- **成本感知。** 选择满足延迟/质量的最便宜模型。
- **延迟感知。** 选择最近 N 分钟中最快的模型。
- **任务感知。** 提示词分类器将编程任务路由到一个模型，摘要任务路由到另一个模型。

## 使用

`code/main.py` 在大约 150 行中实现了一个路由网关：接受 OpenAI 形态的请求，转换为按提供者的存根，运行优先级回退链，跟踪每次请求的成本，并对输入应用 PII 编辑传递。用三种场景运行它：正常请求、触发回退的主提供者故障、被编辑捕获的 PII 泄露。

关注要点：

- `ROUTES` 字典：别名 -> 优先级排序的具体提供者列表。
- 回退循环在 5xx 上重试。
- 成本跟踪器将令牌使用量乘以每个模型的费率。
- PII 编辑器在转发前清洗 SSN 形状的模式。

## 练习

1. 运行 `code/main.py`。触发故障场景；确认回退落在第二个提供者上且成本正确归属。

2. 添加语义缓存：提示词的 SHA256 是查找键；缓存命中立即返回。衡量重复调用上的成本节省。

3. 添加一个提示词分类器，将"code ..."提示词路由到偏好智能的别名，将"summarize ..."提示词路由到偏好速度的别名。

4. 设计每个团队的预算：每个团队有月度支出上限；网关在达到上限后拒绝请求。选择强制粒度（按请求或窗口化）。

5. 并列阅读 LiteLLM、OpenRouter 和 Portkey 的文档。说出每个产品独有的、其他两个不具备的功能。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|----------|
| 路由网关 | "LLM 代理" | 在许多提供者前面的单一 API 界面层 |
| OpenAI 兼容 | "讲 OpenAI 模式" | 接受 `/v1/chat/completions` 形态，转换到任何后端 |
| 模型别名 | "our_smart_model" | 你代码中网关映射到具体模型的名称 |
| 回退链 | "重试列表" | 失败时尝试的有序提供者列表 |
| 语义缓存 | "提示词嵌入缓存" | 键是提示词的嵌入；近似重复共享缓存命中 |
| 保护栏 | "输入/输出过滤器" | 编辑 PII、拒绝策略违规 |
| 每个密钥的速率限制 | "团队预算" | 限定到 API 密钥的配额 |
| 成本追踪 | "每次请求支出" | 聚合令牌使用量 x 每个模型的价格 |
| LiteLLM | "开放代理" | 可自托管的 OSS 路由网关 |
| OpenRouter | "托管 SaaS" | 带有基于额度计费的托管网关 |
| Portkey | "生产选项" | 开源 + 托管，内置保护栏 |
