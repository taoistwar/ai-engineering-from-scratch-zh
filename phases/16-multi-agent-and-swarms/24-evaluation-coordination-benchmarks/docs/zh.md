# 评估与协调基准

> 五个2025-2026年基准涵盖多智能体评估空间。**MultiAgentBench / MARBLE**（ACL 2025，arXiv:2503.01935）用里程碑KPI评估星形/链式/树形/图拓扑；**图在研究上最佳**，认知规划添加约3%里程碑达成。**COMMA**评估多模态非对称信息协调；包括GPT-4o在内最先进模型挣扎于击败随机基线。**MedAgentBoard**（arXiv:2505.12371）涵盖四个医疗任务类别，经常发现多智能体不占优于单LLM。**AgentArch**（arXiv:2509.10769）基准测试结合工具使用+内存+编排的企业智能体架构。**SWE-bench Pro**（arXiv:2509.16941）有1865个问题跨越41个仓库涵盖商业应用、B2B服务和开发者工具；前沿模型在Pro上得分约23% vs Verified上70%+——污染的现实检查。Claude Opus 4.7（2026年4月）在Pro上报告**64.3%**，采用显式智能体团队协调（尚无Anthropic主要来源发布——视为初步）；Verdent（智能体脚手架）在Verified上达到**76.1% pass@1**（[Verdent技术报告](https://www.verdent.ai/blog/swe-bench-verified-technical-report)）。**AAAI 2026桥接项目WMAC**（https://multiagents.org/2026/）是2026年社区焦点。本课构建MARBLE指标，运行拓扑-指标扫描，并确定"仅通过SWE-bench Verified不是泛化证据"的规则。

**Type:** Learn
**Languages:** Python (stdlib)
**Prerequisites:** Phase 16 · 15 (Voting and Debate Topology), Phase 16 · 23 (Failure Modes)
**Time:** ~75 minutes

## 问题

当一篇论文声称"我们的多智能体系统更好"时，问题是：比什么更好，在什么上，如何测量？2023-2024年的多智能体评估时代是混乱的——每个人选择自己的指标、自己的基线和自己的任务集。2025-2026年基准施加了结构。

没有共享基准，你无法有意义地比较两个多智能体系统。更糟的是，没有保留基准，前沿模型可能污染。SWE-bench Verified在2025年中部分被训练语料库污染；前沿分数膨胀；Pro被设计为未污染的现实检查。

本课枚举五个规范的2026年基准，命名每个测量什么，并教你怀疑地阅读基准声明。

## 概念

### MultiAgentBench（MARBLE）——ACL 2025

arXiv:2503.01935。在研究、编程和规划任务上评估四种协调拓扑（星形、链式、树形、图）。基于里程碑的KPI追踪部分进展而非仅最终成功。

测量结果：

- **图**拓扑在研究场景中最佳；支持任意到任意批评。
- **链式**在逐步提纯编程中最佳。
- **星形**在快速事实合并中最佳。
- **协调税**在图拓扑约4个智能体后出现。
- **认知规划**跨拓扑添加约3%里程碑达成。

使用时机：你想逐个比较协调拓扑。MARBLE仓库（https://github.com/ulab-uiuc/MARBLE）提供评估器。

### COMMA——多模态非对称信息

涵盖智能体具有不同观察模态且必须在没有完全信息共享下协调的任务。报告的结果令人不安：包括GPT-4o在内的前沿模型挣扎于在COMMA中击败**随机基线**的智能体-智能体协作。信号是多智能体模态训练不足和评估不足——LLM合理处理单模态合作；多模态协调崩溃。

使用时机：你的系统具有多模态或非对称信息协调。COMMA的零结果是声称之前测量的警告。

### MedAgentBoard——领域压力测试

arXiv:2505.12371。四个医疗任务类别：诊断、治疗计划、报告生成、患者沟通。比较多智能体vs单LLM vs传统基于规则系统。

发现：多智能体在大多数类别上不占优于单LLM。多智能体优势狭窄——任务分解在子任务明显可分离时有帮助（诊断+治疗）；它在协调开销超过专门化增益时有害（报告生成）。

使用时机：你的领域有明确的单LLM基线。如果MedAgentBoard的经验教训泛化，许多提议的多智能体系统是过度工程化的。

### AgentArch——企业架构

arXiv:2509.10769。工具使用、内存和编排层叠的企业设置。基准隔离每层的贡献：添加工具有多大帮助？添加内存？添加多智能体编排？

使用时机：你正在设计企业智能体栈，需要证明每层合理性。AgentArch帮助避免购买你无法衡量价值的功能。

### SWE-bench Pro——现实检查

arXiv:2509.16941。1865个问题跨越41个仓库涵盖商业应用、B2B服务和开发者工具。设计为**未污染**，训练截止日期较晚。前沿模型在Pro上得分约23% vs Verified上70%+。差距是污染信号。

2026年4月分数：
- Claude Opus 4.7在Pro上：**64.3%**（以显式智能体团队协调报告；尚无Anthropic主要来源发布——视为初步）。
- Verdent（智能体脚手架）在Verified上：**76.1% pass@1**（[技术报告](https://www.verdent.ai/blog/swe-bench-verified-technical-report)）。
- 在没有智能体脚手架下前沿Pro原始分数：约23-35%（[SWE-bench Pro论文](https://arxiv.org/abs/2509.16941)）。

结论："我们击败了SWE-bench Verified"不再是能力的证据。Pro是当前的门禁测试。智能体团队脚手架在Pro上产生可测量增益（约30-40点增量），这是2026年对多智能体协调最强的经验论据之一。

### AAAI 2026 WMAC

AAAI 2026桥接项目——多智能体协调研讨会（https://multiagents.org/2026/）。2026年多智能体AI研究的社区焦点。被接收的论文和研讨会论文集是评估新方法的规范场所；在生产决策中推迟于WMAC接受的声明而非arXiv预印本。

### 怀疑地阅读基准声明——2026年检查清单

当有人声称多智能体结果时：

1. **哪个基准，哪个分割？** SWE-bench Verified vs Pro很重要。在错误分割上报告的数字毫无价值。
2. **污染检查。** 基准在模型训练截止日期后发布了吗？如果没有，谨慎对待。
3. **基线比较。** Vs单LLM基线、vs随机、vs先前多智能体工作。不是"vs同一系统的未调优版本。"
4. **统计显著性。** N次试验、p值、置信区间。前沿模型高方差；单次运行误导。
5. **任务多样性。** 一个还是许多任务？泛化对生产重要。
6. **成本披露。** 每个任务Token，墙钟。90%解决方案以20倍成本是商业决策，非能力声明。

### 没有基准测量好的

- **长周期协调。** 数天墙钟交互。所有当前基准运行短。
- **对抗鲁棒性。** 当一个智能体恶意或被破坏时发生什么？
- **部署下漂移。** 基准是静态的；生产分布变化。
- **成本归一化性能。** 大多数基准报告原始准确率，非每美元准确率。

为你实际关心的轴构建自己的内部基准通常是正确做法。

## 构建它

`code/main.py` 是非交互式遍历：

- 在玩具任务上模拟3个多智能体系统。
- 计算每个的MARBLE风格里程碑指标。
- 通过从"训练"集中保留任务运行污染检查。
- 显式与随机基线比较。
- 打印基准声明记分卡。

运行：

```bash
python3 code/main.py
```

预期输出：带原始准确率、里程碑达成、每任务成本、vs随机基线增量和污染检查注释的系统记分卡。

## 运用

`outputs/skill-benchmark-reader.md` 读取任何多智能体基准声明并应用审查清单。输出：等级和注意事项。

## 交付物

生产评估纪律：

- **构建反映你实际生产分布的内部基准。** 公共基准提供信息但不替代。
- **在每次比较中包含随机基线。** 如果你不能在协调任务上以大幅差距击败随机，任务可能不当。
- **与准确率一起报告成本。** Token成本和墙钟。运维团队需要两者。
- **每季度重新构建基准。** 生产分布变化；陈旧基准误导。
- **避免过拟合已发布基准。** 如果你的团队专门为SWE-bench Pro数字优化，你不会在生产上退步。

## 练习

1. 运行 `code/main.py`。识别三个模拟系统中哪个有最佳每里程碑成本。它匹配最高原始准确率系统吗？
2. 阅读MultiAgentBench（arXiv:2503.01935）。对你自己的任务领域，决定MARBLE会推荐四种拓扑中的哪一种。从论文结果论证。
3. 阅读SWE-bench Pro论文。什么具体使其抗污染？相同技术可否应用于你关心的其他基准？
4. 阅读COMMA在多模态协调上的发现。设计一个简单多模态协调任务你可以添加到你的内部基准。什么算作有用信号？
5. 将基准声明检查清单应用于最近一篇多智能体论文的头条结果。你会给该声明什么等级？
