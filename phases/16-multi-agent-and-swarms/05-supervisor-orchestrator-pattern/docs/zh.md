# 监督者/编排者-工作者模式

> 一个主导智能体规划并委派；专门化的工作者在并行上下文中执行并报告回来。这是Anthropic研究系统背后的模式（Claude Opus 4作为主导，Sonnet 4作为子智能体），在内部研究评估中相对于单智能体Opus 4达到+90.2%。Anthropic的工程文章报告说，BrowseComp上80%的方差仅由token使用量解释——多智能体获胜很大程度上是因为每个子智能体获得一个全新的上下文窗口。本课从原语构建监督者模式，并涵盖来自生产部署的2026年工程经验教训。

**Type:** Learn + Build
**Languages:** Python (stdlib, `threading`)
**Prerequisites:** Phase 16 · 04 (Primitive Model)
**Time:** ~75 minutes

## 问题

研究是单智能体系统失败的典型任务。你问"2023年到2026年间多智能体系统发生了什么变化？"单智能体顺序阅读五篇论文，用它们的文本填满半个上下文，然后必须对所有五篇一起进行推理。当到达第五篇时，它已忘记了第一篇。它无法并行化。

监督者模式修复了这一点：一个主导智能体规划搜索，将每个子问题委派给一个工作者，然后综合。每个工作者针对一个狭窄问题获得自己的200k token窗口。主导从不看到原始论文——只有工作者摘要。

Anthropic的生产研究系统报告在内部研究评估中相对于单Opus 4达到+90.2%。同一篇文章指出，BrowseComp上80%的方差仅由*token使用量*解释。每个子智能体获得全新上下文是主要机制。

## 概念

### 模式

```
                 ┌──────────────┐
                 │   主导        │  规划、分解、
                 │  (Opus 4)   │  综合
                 └──┬────┬───┬──┘
                    │    │   │
            ┌───────┘    │   └───────┐
            ▼            ▼           ▼
      ┌─────────┐  ┌─────────┐  ┌─────────┐
      │  工作者1  │  │  工作者2  │  │  工作者3  │
      │(Sonnet)  │  │(Sonnet)  │  │(Sonnet)  │
      └─────────┘  └─────────┘  └─────────┘
        全新的        全新的         全新的
        上下文        上下文         上下文
```

主导从不读取原始材料。在工作主导综合之前，工作者从不看到彼此的工作。每条箭头是带有一个狭窄产物的移交。

### 为什么它获胜

三个机制：

1. **每个子智能体获得全新上下文。** 一个探索"FIPA-ACL遗产"的工作者不携带主导规划时花费的40k token。它为一个问题获得200k窗口。
2. **通过提示专门化。** 主导的提示是"分解和综合"，而非"研究"。每个工作者的提示是狭窄的："找到X中变化了什么"。聚焦的提示产生聚焦的输出。
3. **并行性。** 工作者并行运行。墙钟时间大致为 `max(工作者时间) + 规划 + 综合`，而非 `sum(工作者时间)`。

### 工程经验教训（Anthropic 2025）

Anthropic文章列出了几个在2026年仍然相关的生产经验教训：

- **将工作量匹配到查询复杂性。** 简单查询：一个智能体，3-10次工具调用。复杂查询：10+个智能体。主导必须估计这一点，而不是调用者。
- **先宽后窄。** 先分解为宽泛的子问题，然后如果答案值得深度则每个子问题生成更多工作者。
- **彩虹部署。** 智能体是长时间运行且有状态的。传统的蓝绿部署不适用。Anthropic使用彩虹部署：新版本逐步推出，同时旧版本耗尽。
- **Token使用量占主导地位。** 多智能体的token使用量约为单智能体的15倍。仅当任务价值证明成本合理时才运行它。

### LangGraph转向

LangGraph最初以带有高级`create_supervisor`辅助函数的`langgraph-supervisor`库发布。2025年，LangChain将建议转向通过工具调用直接实现监督者模式，因为工具调用给予更多对*监督者看到什么*的控制（上下文工程）。该库仍然有效；文档现在推荐工具调用形式。

### 失败模式

- **主导幻觉出计划。** 如果主导生成的子问题不能分解真正的问题，工作者就在错误的目标上进行精确的研究。
- **工作者过度探索。** 没有显式范围边界，工作者漂移至超出分配的子问题，污染综合步骤。
- **综合冲突。** 两个工作者返回矛盾的事实。主导必须要么重新询问（添加一轮），要么显式注明分歧。默默选择一方是最糟糕的失败：用户永远不会知道分歧发生了。

### 何时监督者是错误的

- **顺序任务。** 如果第2步字面上需要第1步的输出，并行性毫无收获。使用流水线（CrewAI Sequential、LangGraph线性图）。
- **简单查询。** 单智能体更快更便宜地处理它们。在生成工作者之前使用主导的"缩放工作量"检查。
- **严格确定性。** 监督者使用LLM选择委派。当审计/重放比适应性更重要时，静态图更好。

## 构建它

`code/main.py` 使用 `threading` 实现一个由三个并行工作者组成的监督者。主导将查询分解为子问题，工作者在每个子问题上并行运行，主导进行综合。没有真实的LLM——工作者被脚本化以模拟获取和摘要。

关键结构：

- `Lead.plan(query)` 将查询分解为3个子问题。
- `Worker.run(sub_q)` 返回一个假摘要（在生产环境中可以是任何使用工具的智能体）。
- `Lead.run(query)` 在线程中启动工作者，合并，并综合。

运行：

```
python3 code/main.py
```

输出显示计划、带有开始/结束时间戳的并行工作者追踪，以及最终的综合。你可以看到墙钟时间的优势：三个0.3秒的工作者约在0.35秒内运行，而非0.9秒。

## 运用

`outputs/skill-supervisor-designer.md` 接收用户查询并生成监督者模式设计：主导系统提示、工作者角色、子问题分解规则以及综合模板。在构建新的研究风格智能体系统之前使用此技能。

## 交付物

部署监督者模式之前的检查清单：

- **模型配对。** 主导使用推理级模型（Opus级别，`o3`级别）。工作者使用更快、更便宜的模型（Sonnet、`o4-mini`）。
- **工作者超时。** 任何超过2倍中位运行时间的工作者被终止；主导要么以更窄范围重新生成，要么在没有它的情况下继续。
- **每个工作者的Token上限。** 硬限制（比如预期综合输入的10倍）防止失控工作者超出预算。
- **可观测性。** 追踪主导的计划、每个工作者的工具调用和综合。这是任何事后调试的基础。
- **彩虹推出。** 有状态的长时间运行的智能体需要渐进版本过渡，而非热交换。

## 练习

1. 运行 `code/main.py`，然后将主导修改为生成5个工作者而非3个。观察墙钟时间效果。在什么工作者数量下生成开销超过并行节省（在此演示中）？
2. 实现工作者超时：终止任何运行超过0.5秒的工作者，让主导综合剩余结果。你需要什么可观测性来知道一个工作者被切断了？
3. 在主导的综合中添加冲突检测步骤：如果两个工作者返回矛盾答案，主导注明分歧而非选择一方。你如何在没有调用LLM的情况下检测矛盾？
4. 阅读Anthropic的研究系统工程文章。列出这个玩具演示需要采纳的三种实践才能在生环境中运行。
5. 比较LangGraph的 `create_supervisor`（遗留）与新的工具调用建议。哪个让你对监督者看到什么有更好的控制？为什么Anthropic在综合中显式地只传递子答案而非原始工作者上下文？

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|----------------|------------------------|
| 监督者 | "主导智能体" | 一个规划、委派和综合的编排者智能体。不自己做工作。 |
| 工作者 | "子智能体" | 由监督者以窄范围和自己的上下文窗口调用的聚焦智能体。 |
| 编排者-工作者 | "监督者模式" | 相同的东西，不同的名称。2026年文献两者都用。 |
| 全新上下文 | "清洁窗口" | 工作者的上下文从其系统提示和分配的问题开始，而非主导的历史。 |
| 彩虹部署 | "渐进推出" | 有状态的长时间运行的智能体需要版本化的耗尽和替换，而非蓝绿部署。 |
| Token主导 | "上下文是变量" | 按Anthropic，研究评估中80%的方差来自使用的总token，而非模型选择。 |
| 缩放工作量 | "将智能体数量匹配到复杂性" | 主导估计查询难度，相应地生成1 vs 10+个工作者。 |
| 综合冲突 | "工作者有分歧" | 两个工作者返回矛盾事实；主导必须浮现分歧，而非默默选择一方。 |
