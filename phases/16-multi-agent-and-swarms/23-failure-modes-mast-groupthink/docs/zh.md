# 失败模式——MAST、群体思维、单一文化、级联错误

> 2026年的参考分类法是**MAST**（Cemri等人，NeurIPS 2025，arXiv:2503.13657），源自7个最先进开源MAS的1642条执行追踪，显示**41–86.7%的失败率**。三个根类别：**规范问题**（41.77%）——角色模糊、任务定义不清；**协调失败**（36.94%）——通信故障、状态不同步；**验证差距**（21.30%）——缺失验证、缺失质量检查。**群体思维**族（arXiv:2508.05687）添加：单一文化崩塌（相同基础模型→相关失败）、从众偏差（智能体互相强化错误）、心智理论缺陷、混合动机动态、级联可靠性失败。级联示例：重试风暴中支付失败触发订单重试，触发库存重试，使库存服务过载（数秒内10倍负载——需要断路器）。内存污染：一个智能体的幻觉进入共享内存，下游智能体将其视为事实；准确率逐渐衰减，根因诊断痛苦。**STRATUS**（NeurIPS 2025）报告通过专门化检测/诊断/验证智能体实现1.5倍缓解成功改进。本课将失败模式视为一等工程目标。

**Type:** Learn
**Languages:** Python (stdlib)
**Prerequisites:** Phase 16 · 13 (Shared Memory), Phase 16 · 14 (Consensus and BFT), Phase 16 · 15 (Voting and Debate Topology)
**Time:** ~75 minutes

## 问题

多智能体系统在真实任务上41-86.7%的时间失败（Cemri等人2025年跨7个开源MAS测量）。那不能用"多加智能体"来调试。失败有结构性原因。MAST分类法给你类别。本课将每个类别映射到具体检测、诊断和缓解模式，使数字不再显得随意。

2026年生产实践是将失败模式视为设计输入。你的架构不是"足够好"，直到你能指向每个MAST类别并命名你部署的缓解措施。

## 概念

### MAST类别

**规范问题（41.77%的失败）。** 智能体的任务定义不够紧密。示例：

- 角色模糊：两个智能体都认为自己是审阅者。
- 任务规定不足：当用户想要特定角度时"总结这个"。
- 成功标准隐含：智能体无法判断它是否成功。

缓解措施：
- 编写显式角色契约。每个智能体的提示陈述它做什么*以及它不做什么*。
- 每个任务的验收测试。在智能体开始前，定义"完成看起来像X。"
- 飞行前规范检查：独立智能体在分派前审查任务定义。

**协调失败（36.94%）。** 通信或状态故障。

示例：
- 两个智能体更新共享状态而没有同步。
- 智能体间消息丢失（队列失败、超时）。
- 状态漂移：智能体A认为任务完成；智能体B仍在执行。

缓解措施：
- 带乐观并发的版本化共享状态。
- 关键消息的显式确认（重试直到确认）。
- 周期性状态同步检查点；尽早检测漂移。

**验证差距（21.30%）。** 输出上无独立检查。

示例：
- 一个智能体声称成功；无人验证。
- 智能体链每个信任前一个的输出。
- 涌现组合行为上缺失测试覆盖。

缓解措施：
- 独立验证者智能体（第13课）。只读，独立来源访问。
- 显式移交契约："A的输出必须通过检查器C，然后B开始。"
- 用于事后分析的结果日志。

### 群体思维族（arXiv:2508.05687）

当智能体同质化或互相模仿时的五种相关失败：

**单一文化崩塌。** 相同基础模型或训练数据→相关错误。当三个智能体共享LLM时，它们共享其幻觉。

**从众偏差。** 智能体调整向最大声或最自信的对等体，即使错了。

**心智理论缺陷。** 智能体无法彼此建模信念；协调崩溃（第18课）。

**混合动机动态。** 部分对齐激励的智能体漂向折衷中点，无人满意。

**级联可靠性失败。** 一个组件的错误模式触发依赖组件中的错误模式。

### 级联示例——重试风暴

经典2026年事故模式：

```
支付服务10%请求失败
   ↓
订单智能体重试支付（指数退避但天真）
   ↓
每次重试是新订单-库存检查
   ↓
库存服务看到2倍正常负载
   ↓
库存服务开始超时
   ↓
每次订单重试库存检查
   ↓
库存服务看到10倍正常负载
   ↓
集群宕机
```

修复是经典的：**断路器**。当下游错误率超过阈值时，以缓存或默认结果短路。加上每次请求的上限重试预算。

断路器是少数你直接从分布式系统借用而无需修改的多智能体失败缓解措施之一。

### 内存污染（重温）

来自第13课：一个智能体的幻觉成为共享内存事实；下游智能体在被污染的事实上推理。在MAST术语中，这是共享内存层的验证差距。

逐渐准确率衰减是症状。你不会得到崩溃；你得到难以根因的缓慢漂移。

缓解：仅追加日志、来源、不可写入验证者。已在第13课涵盖。

### STRATUS——用于失败检测的专门化智能体

STRATUS（NeurIPS 2025）报告当你部署以下时实现1.5倍缓解成功改进：

- **检测智能体。** 观察症状模式（高分歧、重试飙升、准确率漂移）。
- **诊断智能体。** 给定症状，从MAST分类法推断可能的根因。
- **验证智能体。** 在缓解措施应用后，检查症状是否清除。

这是应用于智能体系统的SRE风格事故响应。三个角色都可以是具有专门化提示的LLM智能体。

### 失败模式审计

2026年最佳实践是年度（或每次大发布）失败模式审计：

1. **追踪采样。** 收集约1000条真实执行追踪。
2. **分类。** 对每个追踪的失败，映射到MAST+群体思维类别。
3. **计算按类别失败率。** 哪些类别在你的系统中占主导？
4. **排名缓解措施。** 哪个修复会消除最多的失败？
5. **选择2-3个缓解措施。** 实现；下季度重新审计。

纪律比具体选择更重要。没有审计，失败融入噪声，从不被系统性地处理。

### 当系统静默失败时

最危险的失败类别是静默正确性失败。大声失败（崩溃、异常、警报）可监控。产生合理但错误输出的系统不能被异常日志检测到。这就是为什么验证差距是按数量仅21.30%但每次失败最昂贵的类别。

投资于：
- 基于采样的人类审查。
- 黄金数据集回归测试。
- 重要输出上的跨智能体交叉检查。

### 失败 vs 慢速失败

一些失败是即时的；一些是慢速的。即时失败（超时、模式不匹配、认证错误）检测廉价。慢速失败（内存污染、单一文化漂移、角色模糊）检测和预防昂贵。

2026年工程动作：仪表化慢速失败代理，使你可以在漂移成为可见错误之前捕获它。一致率、重试率、输出长度分布和连续智能体版本间的编辑距离都是有用的代理。

## 交付物

生产中的失败模式纪律：

- **每季度MAST审计。** 不是年度。类别随系统增长而变化。
- **到处断路器。** 对任何依赖服务的每次对外调用。以5-10%错误率默认打开阈值。
- **黄金数据集。** 小、高质量、手工审计。每周对其回归测试。
- **STRATUS三人组。** 监控生产的检测+诊断+验证智能体。仅从检测智能体开始；当症状嘈杂时添加诊断。
- **失败预算。** 按类别的显式SLO失败率。超出预算触发停止交付对话。

## 练习

1. 运行 `code/main.py`。确认断路器限制重试风暴。改变失败阈值并观察权衡。
2. 实现**慢速失败代理**：3个并行智能体的一致率。当它急剧下降时触发警报。通过逐渐关联智能体输出来模拟单一文化漂移。
3. 阅读Cemri等人（arXiv:2503.13657）。选择他们7个MAS系统之一，映射其前3个失败类别。这些与MAST预测的比较如何？
4. 阅读群体思维论文（arXiv:2508.05687）。识别五种模式中哪一种在生产中最难检测。提出代理指标。
5. 为你所知的特定多智能体系统设计STRATUS风格检测-诊断-验证三人组。检测观察哪些症状？诊断推荐什么缓解措施？验证如何确认它们有效？

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|----------------|------------------------|
| MAST | "2026年分类法" | Cemri 2025年；3个根类别+14种子类型失败。 |
| 规范问题 | "角色模糊" | 任务或角色定义不足；智能体不知做什么。 |
| 协调失败 | "状态漂移" | 智能体间的通信或同步故障。 |
| 验证差距 | "无人检查" | 输出在没有独立验证的情况下被接受。 |
| 群体思维族 | "同质性失败" | 单一文化、从众、心智理论缺陷、混合动机、级联。 |
| 单一文化崩塌 | "相同模型，相同幻觉" | 来自共享基础模型或训练数据的相关错误。 |
| 重试风暴 | "级联错误放大" | 一次失败触发重试，放大下游负载。 |
| 断路器 | "错误率时快速失败" | 错误率超过阈值时打开；以默认短路。 |
| STRATUS | "事故响应三人组" | 检测+诊断+验证智能体。1.5倍缓解成功。 |
| 内存污染 | "幻觉传播" | 共享内存事实被污染；下游智能体在被污染上推理。 |
