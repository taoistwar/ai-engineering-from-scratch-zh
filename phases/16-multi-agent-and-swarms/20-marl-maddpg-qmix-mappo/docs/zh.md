# MARL——MADDPG、QMIX、MAPPO

> 多智能体协调的强化学习遗产，在2026年仍然影响LLM智能体系统。**MADDPG**（Lowe等人，NeurIPS 2017，arXiv:1706.02275）引入了集中训练、去中心化执行（CTDE）：每个评论者训练时看到所有智能体的状态和行动；测试时仅运行本地actor。适用于合作、竞争和混合设置。**QMIX**（Rashid等人，ICML 2018，arXiv:1803.11485）是带单调混合网络的值分解；每个智能体的Q组合成联合Q，使`argmax`干净分布——在星际争霸多智能体挑战（SMAC）上占主导地位。**MAPPO**（Yu等人，NeurIPS 2022，arXiv:2103.01955）是带集中价值函数的PPO；在粒子世界、SMAC、Google Research Football、Hanabi上以最少调优"令人惊讶地有效"。这些支撑了必须去中心化行动的智能体团队的训练策略。MAPPO是**默认的2026年合作MARL基线**。本课从小网格世界玩具构建每种算法，并在触及LLM智能体训练前将三个想法植入肌肉记忆。

**Type:** Learn
**Languages:** Python (stdlib, small NumPy-free implementations)
**Prerequisites:** Phase 09 (Reinforcement Learning), Phase 16 · 09 (Parallel Swarm Networks)
**Time:** ~90 minutes

## 问题

LLM智能体系统越来越多地训练智能体间协调的策略：何时推迟、何时行动、调用哪个对等体。告诉你如何训练此类策略的文献是多智能体强化学习（MARL），它早于LLM浪潮，并有一个小集合的主导算法。

没有模式词汇阅读MARL论文是痛苦的。集中训练带去中心化执行（CTDE）、值分解和集中评论者不是流行词——它们是对特定问题的特定答案：

- 独立RL（每个智能体单独学习）从每个智能体的角度看是非平稳的。糟糕。
- 集中RL（一个智能体控制所有）不扩展并违反执行约束。
- CTDE获取两全其美：以全局信息训练，以本地策略部署。

## 概念

### 论文使用的三种环境

- **粒子世界（多智能体粒子环境）。** 带合作/竞争任务的简单2D物理。MADDPG的原始试验台。
- **星际争霸多智能体挑战（SMAC）。** 合作微管理，部分观察。QMIX的试验台。离散动作，连续状态。
- **Google Research Football、Hanabi、MPE。** MAPPO基线。

不同环境有不同动作/观察类型。算法相应选择。

### MADDPG（2017年）——CTDE模式

每个智能体`i`有一个actor `mu_i(o_i)`将自己的观察映射到动作。每个智能体也有一个评论者`Q_i(x, a_1, ..., a_n)`在训练时看到所有观察和所有动作。actor通过策略梯度针对评论者评估更新。

```
actor update:    grad_theta_i J = E[grad_theta mu_i(o_i) * grad_a_i Q_i(x, a_1..n) at a_i=mu_i(o_i)]
critic update:   TD on Q_i(x, a_1..n) given next-state joint estimate
```

为什么CTDE：在训练时，我们知道每个人的行动；我们使用它来减少每个评论者的方差。在部署时，每个智能体仅看到`o_i`并调用`mu_i(o_i)`。

失败模式：评论者随N个智能体增长（输入包括所有行动）。没有近似无法扩展到约10个智能体以上。

### QMIX（2018年）——值分解

仅合作。全局奖励是每个智能体Q值的单调函数之和：

```
Q_tot(tau, a) = f(Q_1(tau_1, a_1), ..., Q_n(tau_n, a_n)),   df/dQ_i >= 0
```

单调性保证`argmax_a Q_tot`可由每个智能体独立选择`argmax_{a_i} Q_i`计算。这正是你需要的**去中心化执行属性**。训练时，混合网络从每个智能体的Q产生`Q_tot`。

为什么QMIX在SMAC上获胜：合作星际争霸微管理有同质智能体、局部观察、全局奖励——完美适配值分解。

失败模式：单调性约束是限制性的；一些任务有不可分解为单调的奖励结构（一个智能体为团队牺牲）。扩展（QTRAN、QPLEX）放宽这一点。

### MAPPO（2022年）——被忽视的默认值

多智能体PPO：带集中价值函数的PPO。每个智能体有自己的策略；所有智能体共享（或有每个智能体的）价值函数看到完整状态。Yu等人2022年在五个基准上对比MADDPG、QMIX及其扩展基准测试了MAPPO，发现：

- MAPPO在粒子世界、SMAC、Google Research Football、Hanabi、MPE上匹配或击败离策略MARL方法。
- 需要最少的超参数调优。
- 训练稳定；跨种子可复现。

社区在本文之前低估了在策略MARL。在2026年，MAPPO是合作MARL的默认基线；任何新方法必须击败它。

### 为什么LLM智能体工程师应关心

三种直接用途：

1. **路由器训练。** 元智能体选择哪个子智能体处理任务。这是一个带有N个去中心化子智能体和一个集中化路由器的MARL问题。MAPPO适用。
2. **角色涌现。** 在生成式智能体模拟中，训练智能体随时间采用互补角色是伪装的MARL问题。QMIX风格的值分解通过构造强制互补性。
3. **多智能体工具使用。** 当智能体共享工具并竞争预算时，通过CTDE训练它们产生服从资源约束的可部署本地策略。

实际警示：在2026年，大多数生产LLM智能体系统提示其策略而非训练它们。MARL在你拥有(a)大量交互数据，(b)清晰的奖励信号，和(c)愿意投资训练基础设施时进入。

### CTDE作为RL之外的设计模式

即使没有训练，CTDE是有用的架构模式：

- 在*设计*时，假设完全团队可见性。
- 在*运行时*，强制去中心化执行：每个智能体仅看到`o_i`。

该模式迫使你保持每个智能体状态显式并提前考虑部分可观测性。许多生产多智能体系统默默假设到处都是共享状态——CTDE纪律防止这一点。

### 非平稳性问题

当多个智能体同时学习时，每个智能体的环境（包括其他智能体的策略）是非平稳的。经典单智能体RL证明破裂。本课中的MARL算法都解决这一点：

- MADDPG：全局评论者看到所有行动，因此其价值估计是平稳的。
- QMIX：值分解将学习移动到最优性已定义的联合Q空间。
- MAPPO：集中价值函数抑制来自其他策略变化的方差。

在LLM智能体系统中，非平稳性表现为"我的智能体上个月有效，现在上游的其他智能体变了，我的出问题了。"使用CTDE训练MARL是原则性修复；提示级修复更快但耐久性较差。

### 本课不涵盖什么

训练实际网络是第09阶段主题。本课构建脚本化策略版本，演示CTDE、值分解和集中价值模式，无需梯度更新。目标是在你拿起完整MARL库（PyMARL、MARLlib、RLlib多智能体）之前内化模式。

## 构建它

`code/main.py` 实现三种模式演示，全部在一个微型2智能体合作网格世界上：

- 环境：4x4网格上的2个智能体，一个奖励球。如果任何智能体到达球则奖励=1；任务完成。
- `IndependentAgents`——每个智能体将其他视为环境。基线。
- `MADDPGStyle`——集中评论者计算联合价值；actor策略从中更新。脚本化策略改进。
- `QMIXStyle`——带单调混合器的值分解。
- `MAPPOStyle`——集中价值函数；策略针对共享基线更新。

所有四种运行相同episode并报告平均达到目标步数。CTDE变体收敛到比独立基线更短的路径。

运行：

```
python3 code/main.py
```

预期输出：独立智能体平均约6步；CTDE变体收敛到约3.5步（4x4网格的最优是3步）。模式差异显示在脚本化策略中。

## 交付物

生产中的MARL罕见。当你确实使用时：

- **从MAPPO开始。** 2022年论文将此建立为基线；首先复现它节省数周追逐更花哨方法的时间。
- **记录每个智能体的观察和行动流。** 没有每个智能体追踪调试MARL是无望的。
- **将训练代码与执行代码分离。** CTDE是纪律；让执行路径真的只看到`o_i`。
- **奖励塑造警告。** MARL对奖励设计极其敏感。塑造中的一个协调Bug，智能体学会利用它。运行对抗测试。
- **对于LLM智能体**，首先考虑提示级策略。仅当交互数据+奖励信号+基础设施全都就位时才投资MARL训练。

## 练习

1. 运行 `code/main.py`。测量独立和MAPPO风格智能体之间达到目标步数的差距。在6x6网格上差距增长还是缩小？
2. 实现竞争变体：两个智能体，一个球，只有第一个到达获得奖励。哪种模式干净处理竞争？历史上MADDPG。
3. 阅读MADDPG（arXiv:1706.02275）第3节。用你自己的话以伪代码符号化地实现确切的评论者更新规则。
4. 阅读MAPPO（arXiv:2103.01955）。作者为什么论证集中价值+PPO在他们的基准上击败离策略MARL？列出三个最强的论点。
5. 将CTDE作为设计模式应用于假设LLM智能体系统（例如研究智能体+摘要者+编码者）。设计时可用但运行时不可用的联合信息是什么？

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|----------------|------------------------|
| MARL | "多智能体RL" | 多智能体系统的强化学习。 |
| CTDE | "集中训练，去中心化执行" | 以全局信息训练；以本地策略部署。 |
| MADDPG | "多智能体DDPG" | 带每个智能体评论者看到所有观察+行动的CTDE。 |
| QMIX | "值分解" | 每个智能体Q的单调混合。合作的。 |
| MAPPO | "多智能体PPO" | 带集中价值函数的PPO。2026年默认基线。 |
| 值分解 | "单独Q之和" | 联合Q表示为每个智能体Q的单调函数。 |
| 非平稳性 | "移动目标" | 每个智能体的环境随其他学习而变化。核心MARL问题。 |
| 在策略/离策略 | "从当前/重放学习" | PPO是在策略的（MAPPO）；DDPG和Q-learning是离策略的。 |
| SMAC | "星际争霸多智能体挑战" | 合作微管理基准；QMIX的主场。 |
