# 扩展律

> 2020 年 Kaplan 的论文说：更大的模型，更低的损失。2022 年 Hoffmann 的论文说：你训练不足。计算分为两个桶——参数和 token——而分割并不明显。

**类型：** 学习
**语言：** Python
**前置条件：** 第七阶段 · 05（完整 Transformer），第七阶段 · 07（GPT）
**时间：** 约 45 分钟

## 问题

当你有 C FLOPs 的训练计算量并想要最好的模型时，你面临两个旋钮：

1. **多少参数（N）？** 更大的模型，更高的容量。
2. **多少训练 token（D）？** 更多的数据，更好地利用容量。

FLOPs 大致按 `6 × N × D` 扩展。你可以增大 N 并减少 D，或增大 D 并减少 N。哪个更好？

2022 年之前，答案是"大力推 N"。GPT-3（2020）是 175B 参数，在约 300B token 上训练。大约是每个参数 1.7 个 token 的比率。Kaplan 扩展律支持了这一点。

Hoffmann 等人（2022）训练了一个名为 Chinchilla 的小型模型家族，发现了不同的东西：最佳比率接近于**每个参数 20 个 token**。GPT-3 训练不足了 10 倍。Chinchilla（70B 参数，1.4T token）在每个基准上以 2.5 倍更低的推理成本击败了 GPT-3（175B，300B token）。

2026 年是 Chinchilla 的世界——但有一个重要的转折。Llama 3 8B 在 15 万亿 token 上训练，比率是每个参数 1,875 个 token。比 Chinchilla 最佳值多出九十四倍。对于将在大规模上使用的模型，推理成本比训练成本更重要，因此对较小的可部署模型过度训练（超过 Chinchilla）是 2026 年的默认做法。

## 概念

![Chinchilla 曲线：在不同 N/D 比率下的损失 vs 计算量](../assets/scaling-laws.svg)

### Hoffmann 定律

来自 Chinchilla 论文，损失遵循：

```
L(N, D) = A / N^α + B / D^β + E
```

- `N` = 参数（非嵌入）。
- `D` = 训练 token。
- `α ≈ 0.34`，`β ≈ 0.28`（大致对称）。
- `E ≈ 1.69`，不可约损失上限。
- `A ≈ 406`，`B ≈ 411`。

两项在扩展时相互权衡。对固定计算量（C = 6ND）下的 N 求导并求解：

```
N_opt ≈ 0.6 × (C/6)^0.5
D_opt ≈ 0.6 × (C/6)^0.5
D_opt / N_opt ≈ 20
```

计算最优：每个参数 20 个 token。

### 为什么还要过度训练

Chinchilla 最优值在每训练 FLOP 下最小化训练损失。但你只支付一次训练成本；推理成本是永远的。

对于每月服务一万亿 token 的聊天机器人，推理主导总成本。Llama 的方法：训练更小、更长。8B 在 15T token 上是深度推理优化的：

- 适合消费级 GPU。
- 延迟是 70B Chinchilla 最优模型的一小部分。
- 质量对大多数任务来说足够接近。

DeepMind 2024 年的论文（"过度训练是新的最优"）形式化了这一点。对于推理主导的工作负载，正确比率接近每个参数 100–500 个 token，具体取决于服务量。

### 涌现 vs 平滑性

声称：某些能力（算术、多步推理、思维链遵循）在某个规模"涌现"出来。

Schaeffer 等人（2023）认为这是测量伪影：涌现指标使用不连续的评分（精确匹配、阈值准确率），这隐藏了底层 logits 中平滑的改进。连续指标（交叉熵）显示平滑曲线。

在 2026 年，共识是：通过连续损失的预测是可靠的。基准的跳跃通常是评分器伪影。根据连续指标规划预算。

### 2026 年图景

扩展律仍然有效，但是：

| 因素 | 如何改变 |
|--------|-------------|
| 数据质量 | 精选"好"token（Phi 风格）使曲线偏移 >2× 有效计算量 |
| MoE | 总参数与活跃 FLOPs 解耦；按活跃 FLOP 的扩展律 |
| 后训练 | 某些能力（指令遵循、代码）通过 SFT+RLHF 的偏移比预训练更多 |
| 多模态 | 图像 + 文本 token 一起扩展；每种模态有单独的曲线 |
| 合成数据 | 模型生成训练数据；有效计算量可以复合 |

Muon 优化器（Kimi Moonlight，2024）在匹配数据上显示出比 AdamW 约 2× 的有效计算量增益。一些 2026 年的训练运行默认使用 Muon。改变扩展律中的绝对常数，而不是其形状。

## 动手构建

参见 `code/main.py`。我们实现 Chinchilla 损失方程，并为几个计算预算分别求解计算最优 `(N, D)`。

### 步骤 1：Chinchilla 损失

```python
def chinchilla_loss(N, D, A=406.4, B=410.7, alpha=0.34, beta=0.28, E=1.69):
    return A / N ** alpha + B / D ** beta + E
```

在固定 `C = 6ND` 下将 `L` 绘制为 `(N, D)` 上的等高线。找到最小值。

### 步骤 2：计算最优前沿

对于从 `1e17` 到 `1e25` FLOPs 的计算预算，找到在 `6ND = C` 约束下最小化损失的 `(N, D)`。验证比率 `D/N ≈ 20`。

### 步骤 3：过度训练成本

计算训练小 10 倍模型（最优 N 的 1/10，最优 D 的 10×）的额外损失。报告以推理 FLOPs 节省（与 N 成正比）作为交换。

### 步骤 4：与真实模型比较

插入 GPT-3、Chinchilla、Llama 3 8B、DeepSeek-V3（活跃参数）的已知 `(N, D)` 对，并比较预测损失与报告损失。

## 使用它

你自己不太可能训练一个前沿模型。但扩展律告诉你：

1. **你的微调是否有足够的数据。** 如果你任务特定的数据低于每个基模型参数 20 个 token，预计在某个损失下限出现饱和。
2. **是否选择更大的基模型。** 如果你将所有预算都花在推理上，偏好更小、训练更长的模型。
3. **回报在哪里递减。** 超过 Chinchilla 最优值的 1000 倍后，对数损失的变化变成噪声。

**2026 年的研究轨迹：**

- **数据受限体制。** 网络具有有限数量的高质量 token（经过滤后约 5–10 万亿英语 token）。前沿预训练正在接近这个上限。合成数据、多语言、多模态和 RLHF 扩大的微调是下一个杠杆。
- **计算乘法器技巧。** Muon 优化器、MoE、更好的数据策展——每个改变绝对常数，而不是渐近线。
- **RL 的扩展律。** 待解决的问题。早期证据表明 RL 样本上的幂律，但指数与预训练非常不同。

1. **简单。** 运行 `code/main.py`。打印计算预算 `1e20`、`1e22`、`1e24` 的 Chinchilla 最优 `(N, D)`。与真实模型表进行比较。

3. **困难。** 在同一个数据集上训练 5 个微型模型（100K 到 10M 参数），拟合你自己的扩展律。估计 `α` 和 `E`。你的指数与已发表的匹配程度如何？

## 关键术语

| 术语 | 人们怎么说 | 它实际上的含义 |
|------|-----------------|-----------------------|
| 参数（N） | "模型大小" | 非嵌入权重计数；决定容量。 |
| Token（D） | "训练数据" | 看到的训练 token 数量；决定参数被利用得有多好。 |
| 计算量（C） | "花费的 FLOPs" | 对于标准 transformer 大约为 `6 × N × D`。 |
| Chinchilla 最优 | "D/N ≈ 20" | 每预训练 FLOP 最小化损失的比率。 |
| 过度训练 | "超过 Chinchilla" | 花费额外的训练 FLOPs 以节省推理 FLOPs；D/N >> 20。 |
| 不可约损失 | "下限" | 扩展律中的 `E` 项；数据本身的熵。 |
| 涌现能力 | "在规模上突然跃升" | 通常是评分器伪影；连续损失是平滑的。 |
| 有效计算量 | "训练效率乘法器" | 更好的数据/优化器/架构乘大了一个 FLOP 能走多远。 |
