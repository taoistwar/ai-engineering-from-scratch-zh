# 为什么是 Transformer — RNN 的问题所在

> RNN 每次处理一个 token。Transformer 一次性处理所有 token。这个架构上的赌注改变了 2017 年后深度学习的每一条扩展曲线。

**类型：** 学习
**语言：** Python
**前置条件：** 第三阶段（深度学习核心），第五阶段 · 09（序列到序列），第五阶段 · 10（注意力机制）
**时间：** 约 45 分钟

## 问题

2017 年之前，地球上每一个最先进的序列模型——语言、翻译、语音——都是循环神经网络。LSTM 和 GRU 在翻译基准测试上赢得了相当于 ImageNet 级别的成绩，持续了五年之久。它们是所有人唯一的工具。

它们有三个致命弱点。串行计算意味着你无法沿时间轴并行化：token `t+1` 需要来自 token `t` 的隐藏状态。一个 1024 个 token 的序列意味着在能够每秒执行 1,000,000 次浮点运算的 GPU 上进行 1024 次串行步骤。训练挂钟时间与序列长度线性扩展，而硬件是为并行设计的。

梯度消失意味着 50 个 token 之前的信息已经被压缩通过了 50 个非线性层。门控循环单元（LSTM、GRU）缓解了这种压缩，但从未消除它。长距离依赖——"我去年夏天在去京都的飞机上读的那本书是……"——经常失败。

固定宽度的隐藏状态意味着编码器在解码器看到任何内容之前，将整个源序列压缩成一个单一的向量。源序列无论是 5 个 token 还是 500 个 token，瓶颈的形状是一样的。

2017 年的论文 "Attention Is All You Need" 提出了一些激进的想法：完全放弃循环。让每个位置并行地关注所有其他位置。用一次大规模的矩阵乘法而不是 1024 次串行计算来训练。

到了 2026 年，其结果主导了每一种模态。语言（GPT-5、Claude 4、Llama 4）、视觉（ViT、DINOv2、SAM 3）、音频（Whisper）、生物学（AlphaFold 3）、机器人学（RT-2）。相同的模块，不同的输入。

## 概念

![RNN 串行计算 vs Transformer 并行注意力](../assets/rnn-vs-transformer.svg)

**循环作为瓶颈。** RNN 计算 `h_t = f(h_{t-1}, x_t)`。每一步依赖于前一步。在 `h_4` 之前你无法计算 `h_5`。在拥有 10,000 多个并行核心的现代 GPU 上，对于长序列来说这浪费了 99% 的硅片。

**注意力作为广播。** 自注意力为每一对 `(i, j)` 同时计算 `output_i = sum_j(a_ij * v_j)`。整个 N×N 注意力矩阵在一次批量矩阵乘法中完成。没有任何步骤依赖于另一个步骤。GPU 喜欢它。

**加速不是一个常数。** 它是 `O(N)` 串行深度与 `O(1)` 串行深度之间的差异。实践中，在匹配的硬件上，N=512 时 transformer 每个 epoch 训练快 5–10 倍，并且随着序列长度的增长差距会扩大，直到你遇到注意力的 `O(N²)` 内存墙（Flash Attention 后来解决了这个问题——参见第 12 课）。

**transformer 的代价。** 注意力内存按 `O(N²)` 扩展。对于 2K 上下文，没问题。对于 128K 上下文，你需要滑动窗口、RoPE 外推、Flash Attention 分块或线性注意力变体。循环在时间和内存上都是 `O(N)`；transformer 用时间换取内存，然后通过并行性赢回时间。

**归纳偏置的转变。** RNN 假设局部性和近因性。Transformer 不作任何假设——每一对都是注意力的候选。这就是为什么 transformer 需要更多数据来训练良好，但一旦有了数据就能进一步扩展。Chinchilla（2022）形式化了这一点：给定足够的 token，一个 transformer 总是优于同等参数数量的 RNN。

## 动手构建

这里没有神经网络——我们通过数值模拟核心瓶颈，让你在笔记本电脑上感受这种差距。

### 步骤 1：测量串行深度

参见 `code/main.py`。我们构建两个函数。一个将序列编码为加法链（串行，类似 RNN）。另一个将其编码为并行归约（广播，类似注意力）。相同的数学，不同的依赖图。

```python
def rnn_style(xs):
    h = 0.0
    for x in xs:
        h = 0.9 * h + x   # 无法并行化：h 依赖于前一个 h
    return h

def attention_style(xs):
    return sum(xs) / len(xs)  # 每个 x 是独立的
```

我们在最多 100,000 个元素的序列上对两者计时。RNN 版本是 O(N) 且使用单一 CPU 流水线。即使在纯 Python 中，在长度 ≥ 1,000 时，注意力式归约也能击败它，因为 Python 的 `sum()` 是用 C 实现的，并且迭代时没有每一步的解释器开销。

### 步骤 2：计算理论运算次数

两种算法都做 N 次加法。区别在于*依赖深度*：在下一个可以开始之前必须串行发生的运算次数。RNN 深度 = N。注意力深度 = log(N)（使用树状归约），或 1（使用并行扫描）。决定 GPU 时间的是深度，不是运算次数。

### 步骤 3：长序列上的经验性扩展

我们打印一个计时表，使 O(N) 的差距可见。在 2026 年的 Mac 笔记本电脑上，1,000 个元素以下的序列太快而无法测量。100,000 个元素的序列显示出清晰的线性扫描。将其扩展到 16,384 token 的 transformer，与等效的 12 层 LSTM 对比，你就会明白为什么 2016 年训练挂钟时间是一个障碍。

## 使用它

在 2026 年何时仍然选择 RNN：

| 情况 | 选择 |
|-----------|------|
| 流式推理，每次一个 token，恒定内存 | RNN 或状态空间模型（Mamba、RWKV） |
| 非常长的序列（>1M token），注意力内存爆炸 | 线性注意力、Mamba 2、Hyena |
| 没有矩阵乘法加速器的边缘设备 | 深度可分离 RNN 在 FLOPs/watt 上仍然胜出 |
| 其他任何情况（训练、批量推理、最高 128K 的上下文） | Transformer |

状态空间模型（SSM）如 Mamba 本质上是带有结构化参数化的 RNN，赋予它们两全其美的优势：`O(N)` 扫描内存，通过选择性扫描实现并行训练。它们恢复了 transformer 90% 的质量，并具有更好的长上下文扩展性。在 2026 年，大多数前沿实验室训练混合 SSM+transformer 模型（例如 Jamba、Samba）——循环并没有消亡，它是一个组件。

## 练习

1. **简单。** 取 `code/main.py` 中的 `rnn_style`，将标量隐藏状态替换为长度为 64 的隐藏状态向量。重新测量。串行开销随着隐藏状态维度增长多少？
2. **中等。** 用纯 Python 实现并行前缀和（Hillis-Steele 扫描）。验证它在长度为 1024 时产生与串行扫描相同的数值输出。计算深度。
3. **困难。** 将注意力式归约移植到 PyTorch 并在 GPU 上运行。在从 64 到 65,536 的序列长度范围内计时两者。绘制并解释曲线形状。

## 关键术语

| 术语 | 人们怎么说 | 它实际上的含义 |
|------|-----------------|-----------------------|
| 循环 | "RNN 是串行的" | 步骤 `t` 依赖于步骤 `t-1` 的计算，强制沿时间轴串行执行。 |
| 串行深度 | "图的深度" | 依赖操作的最长链；即使在无限硬件上也限制挂钟时间。 |
| 注意力 | "让 token 互相查看" | 加权求和 `sum_j a_ij v_j`，其中 `a_ij` 来自位置 i 和 j 之间的相似度分数。 |
| 上下文窗口 | "模型看到多少" | 注意力层可以接收为输入的位置数量；二次方内存成本在此处扩展。 |
| 归纳偏置 | "内置于架构中的假设" | 关于数据样子的先验；CNN 假设平移不变性，RNN 假设近因性。 |
| 状态空间模型 | "背后有代数的 RNN" | 通过结构化状态空间矩阵参数化以实现并行训练的循环。 |
| 二次方瓶颈 | "为什么上下文成本如此高" | 注意力内存 = 序列长度的 `O(N²)`；Flash Attention 隐藏了常数，但不能隐藏扩展性。 |
