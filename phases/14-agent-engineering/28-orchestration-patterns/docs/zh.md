# 编排模式：监督者、群体、层级式

> 四种编排模式在 2026 年各框架中反复出现：监督者-工作者、群体/对等、层级式、辩论。Anthropic 的指导："关键在于为你的需求构建合适的系统。"从简单开始；仅在单个 agent 加五种工作流模式不够时才引入拓扑结构。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置条件：** 第 14 阶段 · 12（工作流模式）、第 14 阶段 · 25（多 Agent 辩论）
**时间：** 约 60 分钟

## 学习目标

- 说出四种反复出现的编排模式以及各自适用时机。
- 描述 2026 年 LangChain 建议：基于工具调用的监督 vs 监督者库。
- 解释 Anthropic 的"构建合适系统"规则以及它如何影响拓扑选择。
- 在标准库中针对一个共性脚本化 LLM 实现全部四种模式。

## 问题

团队在需要之前就伸手要"多 Agent"。四种模式在各个框架中反复出现；一旦你能命名它们，就能选择正确的一个 — 或完全跳过拓扑结构。

## 概念

### 监督者-工作者

- 一个中央路由 LLM 将任务分派给专家 agent。
- 决策：循环回自己、交给专家、终止。
- 专家之间不互相交谈；所有路由通过监督者。

框架：LangGraph `create_supervisor`、Anthropic orchestrator-workers、CrewAI 层级式流程。

**2026 年 LangChain 建议：** 通过直接工具调用而非 `create_supervisor` 实现监督。这提供了更精细的上下文工程控制 — 你决定每个专家具体看到什么。

### 群体 / 对等

- Agent 通过共享工具面直接交接。
- 无中央路由器。
- 延迟低于监督者（更少的跳数）。
- 更难推理（没有单一控制点）。

框架：LangGraph 群体拓扑、OpenAI Agents SDK 交接（当所有 agent 都可以交接给所有其他 agent 时）。

### 层级式

- 监督者管理子监督者，子监督者管理工作者。
- 在 LangGraph 中实现为嵌套子图；在 CrewAI 中实现为嵌套 crew。
- 可以扩展到大型 agent 群体，但操作复杂性高。

何时需要：当单一监督者的上下文预算无法容纳所有专家的描述时。

### 辩论

- 并行提议者 + 迭代交叉批评（第 25 课）。
- 不是真正的编排 — 更像是验证 — 但在框架中显示为一种拓扑选择。

### CrewAI Crew vs Flow

CrewAI 形式化了两种部署模式：

- **Flow** 用于确定性的、事件驱动的自动化（推荐的生产起点）。
- **Crew** 用于自主的、基于角色的协作。

这与上述四种模式正交，但映射到拓扑：Flow 通常是监督者或层级式；Crew 通常是带 LLM 路由器的监督者。

### Anthropic 的指导

"在 LLM 领域的成功不在于构建最复杂的系统。而在于为你的需求构建合适的系统。"

决策顺序：

1. 单个 agent + 工作流模式（第 12 课）— 从这里开始。
2. 监督者-工作者 — 当你有 2-4 个专家时。
3. 群体 — 当延迟比推理清晰度更重要时。
4. 层级式 — 仅在监督者上下文预算不足时。
5. 辩论 — 当准确率比成本更重要时。

### 此模式的常见错误

- **拓扑优先思维。** 在弄清楚多 Agent 解决什么问题之前就说"我们需要多 Agent"。
- **群体中的弹跳交接。** A -> B -> A -> B。使用跳数计数器。
- **虚假层级。** 因为"企业级"而搞三层；实际只有两个团队。合并。

## 构建它

`code/main.py` 在标准库中针对脚本化 LLM 实现了全部四种模式：

- `Supervisor` — 中央路由器。
- `Swarm` — 带直接交接的对等模式。
- `Hierarchical` — 监督者的监督者。
- `Debate` — 并行提议者 + 批评。

每种模式处理相同的三意图任务（退款/故障/销售）。追踪形状各不相同。

运行它：

```
python3 code/main.py
```

输出：每种模式的追踪 + 操作计数。监督者最清晰；群体最短；层级式最深；辩论最昂贵。

## 使用它

- **LangGraph** 用于监督者和层级式（嵌套子图）。
- **OpenAI Agents SDK** 用于作为工具的交接（监督者形态）。
- **CrewAI Flow** 用于生产确定性。
- **自定义** 用于辩论或需要精确控制时。

## 练习

1. 通过移除路由器将监督者-工作者转换为群体。什么会出问题？什么会改善？
2. 为群体添加跳数计数器：3 次交接后拒绝。它是否能捕获 A->B->A 弹跳？
3. 为 12 个专家的领域构建两级层级式系统。上下文预算在没有嵌套的情况下在哪里失效？
4. 在生产形态的工作负载上对四种模式进行性能分析。每种模式在哪个指标上胜出（延迟、成本、准确率、可调试性）？

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| 监督者-工作者 | "路由器 + 专家" | 中央 LLM 将任务分派给专家；它们之间不互相通信 |
| 群体 | "对等" | 通过共享工具直接交接；无中央路由器 |
| 层级式 | "监督者的监督者" | 用于大规模群体的嵌套子图 |
| 辩论 | "提议者 + 批评" | 并行提议者，交叉批评（第 25 课） |
| 基于工具调用的监督 | "无库的监督者" | 通过直接工具调用实现监督以控制上下文 |
| Crew | "自主团队" | CrewAI 基于角色的协作模式 |
| Flow | "确定性工作流" | CrewAI 事件驱动的生产模式 |
