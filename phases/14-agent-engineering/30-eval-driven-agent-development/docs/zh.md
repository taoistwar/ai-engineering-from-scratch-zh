# 评估驱动的 Agent 开发

> Anthropic 的指导："从简单的提示开始，通过全面评估来优化它们，仅在需要时添加多步 agentic 系统。"评估不是最后一步。它是驱动第 14 阶段每个其他选择的外部循环。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置条件：** 整个第 14 阶段。
**时间：** 约 60 分钟

## 学习目标

- 说出三个评估层 — 静态基准、自定义离线、在线生产 — 以及每层的用途。
- 解释评估器-优化器的紧密循环。
- 描述 2026 年最佳实践：评估与代码共存、在 CI 中运行、作为 PR 的卡口。
- 将第 14 阶段的每一课连接到它生成的评估用例。

## 问题

Agent 通过演示。它们在生产中失败的方式是演示无法预测的。基准回答的是"这个模型是否广泛有能力？"而不是"这个 Agent 是否为我的产品发布了正确的补丁？"答案是：三层评估，持续运行，每个护栏和已学习的规则都映射到一个评估用例。

## 概念

### 三个评估层

1. **静态基准** — SWE-bench Verified 用于代码（第 19 课），WebArena/OSWorld 用于浏览/桌面（第 20 课），GAIA 用于通用能力（第 19 课），BFCL V4 用于工具使用（第 06 课）。用于跨模型比较和回归卡口。污染是真实存在的：SWE-bench+ 发现 32.67% 的方案泄漏。始终报告 Verified / + 审计分数。

2. **自定义离线评估** — 你的产品形态：
   - LLM 作裁判（Langfuse、Phoenix、Opik — 第 24 课）。
   - 基于执行（运行补丁，检查测试）。
   - 基于轨迹（将操作序列与黄金轨迹比较；OSWorld-Human 显示顶级 Agent 是黄金的 1.4-2.7 倍）。

3. **在线评估** — 生产环境：
   - 会话回放（Langfuse）。
   - 护栏触发的警报（第 16、21 课）。
   - 每步成本/延迟追踪（第 23 课 OTel span）。

### 评估器-优化器（Anthropic）

紧密循环：

1. 提议者生成输出。
2. 评估者评判。
3. 不断优化直到评估者通过。

这是自优化（第 05 课）的泛化版本。任何你关心的 Agent 流程都可以包装在评估器-优化器中以提高可靠性。

### 2026 年最佳实践

- 评估与代码共存。
- 在每个 PR 上通过 CI 运行。
- 以评估分数作为合并卡口（例如"与 main 相比回归不超过 5%"）。
- 每个护栏映射到一个评估用例。
- 每个已学习的规则（Reflexion、pro-workflow learn-rule）映射到一个失败用例。

### 评估驱动开发的失败常见情况

- **无基线。** 没有最后已知良好状态的评估是不可读的。存储基线。
- **LLM 裁判缺乏事实依据。** 裁判也会幻觉。CRITIC 模式（第 05 课）— 裁判需要基于外部工具。
- **过度拟合评估。** 为评估优化的结果偏离了生产的实际用途。轮换用例。
- **不稳定的评估。** 非确定性用例导致误报。固定随机种子、保存快照状态。

## 构建它

`code/main.py` 是一个标准库评估工具：

- 带类别（benchmark、custom、online）的用例注册表。
- 一个受测试的脚本化 Agent。
- 评估器-优化器循环：提议、评判、优化直到通过或达到最大轮次。
- CI 卡口：聚合通过率 + 相对于基线的回归。

运行它：

```
python3 code/main.py
```

输出：每个用例的通过/失败、回归标记、CI 卡口裁决。

## 使用它

- 在与 Agent 代码相同的仓库中编写评估用例。
- 通过 CI 在每次 PR 上运行它们。
- 回归时构建失败。
- 随时间追踪通过率。
- 将每个生产失败关联到一个新用例。

## 交付它

`outputs/skill-eval-suite.md` 为 Agent 产品构建三层评估套件，包含 CI 卡口和回归追踪。

## 练习

1. 取一次你的生产失败。编写一个重现它的评估用例。你的 Agent 现在能通过吗？
2. 为你的领域构建一个三维度 LLM 裁判量规（事实、语气、范围）。对 50 个会话打分。
3. 将评估套件接入 CI。在 >= 5% 回归时构建失败。
4. 添加轨迹效率指标：Agent 用了多少步 vs 黄金轨迹？
5. 将第 14 阶段的每一课映射到你的套件中的一个评估用例。有遗漏吗？那是需要填补的空缺。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| 静态基准 | "现成的评估" | SWE-bench、GAIA、AgentBench、WebArena、OSWorld |
| 自定义离线评估 | "领域评估" | 在你的产品形态上 LLM 作裁判 / 执行 / 轨迹 |
| 在线评估 | "生产评估" | 会话回放、护栏警报、成本/延迟追踪 |
| 评估器-优化器 | "提议-评判-优化" | 迭代直到裁判通过 |
| CI 卡口 | "合并拦截器" | 评估回归时构建失败 |
| 基线 | "最后已知良好状态" | 用于检测回归的参考分数 |
| 轨迹效率 | "步数 / 黄金" | Agent 步数除以人类专家的最小步数 |
