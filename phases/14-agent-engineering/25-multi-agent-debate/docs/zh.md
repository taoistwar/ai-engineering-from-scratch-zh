# 多 Agent 辩论与协作

> Du 等人（ICML 2024，"Society of Minds"）运行 N 个模型实例独立提出答案，然后在 R 轮中迭代相互批评以求收敛。提高了事实性、规则遵循和推理能力。稀疏拓扑在词元成本上优于全连接。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置条件：** 第 14 阶段 · 12（工作流模式）、第 14 阶段 · 05（自优化与 CRITIC）
**时间：** 约 60 分钟

## 学习目标

- 解释辩论协议：N 个提议者、R 轮、收敛到一个共同答案。
- 描述辩论为何提高事实性、规则遵循和推理能力。
- 解释稀疏拓扑：并非每个辩论者都需要看到所有其他辩论者。
- 在脚本化 LLM 上实现带全连接和稀疏变体的标准库辩论；衡量词元成本 vs 准确性。

## 问题

自优化（第 05 课）是一个模型批评自己 — 存在群体思维风险。CRITIC（第 05 课）将批评建立在外部工具上 — 并非始终可用。辩论引入了第三种模式：多个实例、交叉批评、通过分歧收敛。

## 概念

### Society of Minds（Du 等人，ICML 2024）

- N 个模型实例对同一问题独立提出答案。
- 在 R 轮中，每个模型阅读其他人的提议并批评它们。
- 模型基于批评更新其答案。
- R 轮之后，返回收敛的答案。

原始实验因成本使用了 N=3、R=2。准确率随着更多 agent 和更多轮次在困难问题上提高（MMLU、GSM8K、国际象棋着法有效性、传记生成）。

跨模型组合优于单模型辩论：ChatGPT + Bard 一起 > 单独任一个。

### 稀疏拓扑

"Improving Multi-Agent Debate with Sparse Communication Topology"（arXiv:2406.11776，2024-2025）表明全连接辩论并不总是最优。稀疏拓扑（星形、环形、中心辐射式）能够在更低的词元成本下达到相同的准确率。每个辩论者只看到一部分对等方。

影响：

- 全连接 N=5、R=3 = 5 × 3 = 15 个提议，每个阅读 4 个对等方 = 60 次批评操作。
- 星形 N=5、R=3（一个中心 + 4 个辐射） = 15 个提议，辐射只阅读中心 = 12 次批评操作。

### 辩论何时有帮助

- **事实性。** N 个独立提案，交叉检查减少幻觉。
- **规则遵循。** 国际象棋着法有效性 — 一个模型漏掉规则，其他模型捕捉到。
- **开放式推理。** 多个视角缩小到正确答案。

### 辩论何时有害

- **延迟敏感的 UX。** N × R 轮的串行延迟你承担不起。
- **成本敏感的场景。** 每个问题 N × R 词元。
- **简单的事实查询。** 一次查找比五次辩论更便宜。

### 2026 年实践实例

- **Anthropic orchestrator-workers**（第 12 课）— 辩论的一种变体，带有综合步骤。
- **LangGraph supervisor**（第 13 课）— 中央路由器 + 专家 agent 可以将辩论实现为一组节点。
- **OpenAI Agents SDK**（第 16 课）— Agent 之间来回交接以进行迭代批评。
- **多 Agent 评估** — 将辩论与评估器-优化器配对以获取评估信号。

### 此模式的常见错误

- **收敛坍塌。** 所有 agent 收敛到第一个错误答案。通过要求分歧轮次来缓解。
- **中心节点故障。** 在星形拓扑中，一个坏的中心节点污染所有人。轮换或使用多个中心节点。
- **提示同质化。** 所有 agent 使用相同的提示；它们产生相同的答案。使用多样化的提示和/或模型。

## 构建它

`code/main.py` 实现了标准库辩论：

- `Debater` 类（脚本化 LLM，每个辩论者有不同的观点偏移）。
- `FullMeshDebate` 和 `SparseDebate` 执行器。
- 三个问题：一个事实型、一个规则型、一个推理型。
- 指标：收敛答案、收敛轮次、总批评操作数。

运行它：

```
python3 code/main.py
```

输出：每种协议的准确率和成本；稀疏在 2/3 的问题上以更低的成本匹配全连接。

## 使用它

- **Anthropic orchestrator-workers** 用于简单的 2-3 worker 辩论。
- **LangGraph** 用于带检查点的有状态多轮辩论。
- **自定义** 用于研究或专门的正确性保证。

## 交付它

`outputs/skill-debate.md` 构建带可配置拓扑、N、R 和收敛规则的多 agent 辩论。

## 练习

1. 实现"强制分歧"规则：在第 1 轮中，每个辩论者必须产生不同的提案。衡量对收敛速度的影响。
2. 添加置信度加权聚合：辩论者返回（答案，置信度）；聚合器按置信度加权。是否有帮助？
3. 将一个"agent"替换为持有不同意见的不同脚本化 LLM。异质性是否提高准确率？
4. 在 3 个问题上衡量全连接 vs 稀疏的词元成本。绘制成本 vs 准确率图表。
5. 阅读 Society of Minds 论文。将你的玩具移植到 N=5、R=3。什么会出问题？什么会变好？

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| 辩论 | "多 Agent 批评" | N 个提议者，R 轮交叉批评，收敛 |
| 全连接 | "每个人阅读每个人" | 每轮每个辩论者阅读每个对等方 |
| 稀疏拓扑 | "有限的对等方视图" | 辩论者只阅读部分对等方 |
| 中心辐射式 | "星形拓扑" | 一个中央辩论者，N-1 个辐射只阅读中心 |
| 收敛 | "达成一致" | 辩论者收敛到一个共同答案 |
| Society of Minds | "Du 等人辩论论文" | ICML 2024 多 agent 辩论方法 |
