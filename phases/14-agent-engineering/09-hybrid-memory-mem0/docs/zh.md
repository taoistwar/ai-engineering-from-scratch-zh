# 混合记忆：向量 + 图 + KV（Mem0）

> Mem0（Chhikara et al., 2025）将记忆视为三个并行的存储——向量用于语义相似性、KV 用于快速事实查找、图用于实体关系推理。一个评分层在检索时融合三者。这是 2026 年外部记忆的生产标准。

**类型:** Build
**语言:** Python（标准库）
**前置要求:** Phase 14 · 07（MemGPT）, Phase 14 · 08（Letta 块）
**时间:** ~75 分钟

## 学习目标

- 解释为什么单一存储（仅向量、仅图、仅 KV）对 agent 记忆是不足的。
- 说出 Mem0 的三个并行存储以及每个优化了什么。
- 描述 Mem0 的融合评分——相关性、重要性、新近度——以及为什么它是加权和而非层次结构。
- 在标准库中实现一个玩具三存储记忆，包含写入所有三个的 `add()` 和融合结果的 `search()`。

## 问题

单一存储对三类查询之一是不对的：

- **语义相似性** — "我们上周关于 agent 漂移讨论了什么？"向量胜出；KV 和图错过。
- **事实查找** — "用户的电话号码是什么？"KV 胜出；向量是浪费，图是过度。
- **关系推理** — "哪些客户共享同一个计费实体？"图胜出；向量和 KV 无法回答。

生产级 agent 在一次会话中发出所有三种查询。单一存储记忆对其中的两种总是错误的。Mem0 的贡献是在单一 `add`/`search` 面后面连接所有三个，并用评分函数融合它们。

## 概念

### 三个并行的存储

Mem0（arXiv:2504.19413, 2025 年 4 月）在 `add(text, user_id, metadata)` 时：

1. 从文本提取候选事实（LLM 驱动的步骤）。
2. 将每个事实写入向量存储（嵌入）用于语义搜索。
3. 将每个事实写入以 `(user_id, fact_type, entity)` 为键的 KV 存储用于 O(1) 查找。
4. 将每个事实作为类型化边写入图存储（Mem0g）用于关系查询。

在 `search(query, user_id)` 时：

1. 向量存储通过嵌入余弦返回 top-k。
2. KV 存储返回以查询派生的 `(user_id, type, entity)` 为键的直接命中。
3. 图存储返回从查询实体可到达的子图。
4. 一个评分层融合三者。

### 融合评分

```
score = w_relevance * relevance(q, record)
      + w_importance * importance(record)
      + w_recency * recency(record)
```

- **相关性（Relevance）** — 向量余弦、KV 精确匹配、图路径权重。
- **重要性（Importance）** — 在写入时标记或学习（某些事实更重要：姓名、ID、策略）。
- **新近度（Recency）** — 自上次写入或读取以来的指数衰减。

权重按产品调优。聊天 agent 用更高 `w_recency`；合规 agent 用更高 `w_importance`；检索 agent 用更高 `w_relevance`。

### Mem0g 与时序推理

Mem0g 增加了一个冲突检测器。当一个新事实与现有边矛盾时，现有边被标记为无效但不删除。时序查询（"用户三月的城市是什么？"）遍历在该时间有效的子图。

这是 Letta 的失效模式泛化的合规级别行为。

### 基准数据

Mem0 论文报告（2025 年）：

- **LoCoMo**（长对话记忆）: 91.6
- **LongMemEval**（长周期情景记忆）: 93.4
- **BEAM 1M**（1M-token 记忆基准）: 64.1

对比基线（全上下文 128k LLM、扁平向量存储、扁平 KV）都落后 10+ 分。仅基准不能证明选择的合理性——运维形态才能——但这些数字表明融合设计不是舍入误差。

### 作用域分类

Mem0 按作用域分离记忆：

- **用户记忆** — 跨会话持久，以 `user_id` 为键。
- **会话记忆** — 在一个线程内持久。
- **Agent 记忆** — 每个 agent 实例状态。

每次写入选择一个作用域。检索可以跨作用域查询并带有每个作用域的权重。未经思考混合作用域是导致"助手将 Alice 关于 Bob 项目的信息告诉了 Bob"事故的原因。

### 此模式在哪些情况下会出错

- **嵌入漂移。** 在前几百次查询中看起来正确的向量结果随着语料库增长而退化。添加对 top-N 最常用记录的定期重新嵌入。
- **KV 模式蔓延。** `(user_id, type, entity)` 看起来简单，直到每个团队添加自己的 `type`。按季度审计 type 集合。
- **图爆炸。** 一个有噪声的提取器为每条消息添加 50 条边。限制每次 `add` 调用的图写入；丢弃低置信度边。

## Build It

`code/main.py` 在标准库中实现三存储模式：

- `VectorStore` — 以朴素 token 重叠相似性作为嵌入替身。
- `KVStore` — 以 `(user_id, fact_type, entity)` 为键的字典。
- `GraphStore` — 类型化边（subject、relation、object、valid）。
- `Mem0` — 顶层外观，包含 `add()`、`search()`、融合评分和作用域感知检索。
- 在多用户、多会话对话上的工作追踪。

运行它：

```
python3 code/main.py
```

输出显示三个单独的回忆路径加上融合的 top-k。在 `main()` 顶部切换评分权重，观察排名变化。

## Use It

- **Mem0（Apache 2.0）** — 生产就绪。用 Postgres + Qdrant + Neo4j 自托管，或使用托管云。
- **Letta** — 三层 core/recall/archival；自带向量和图后端。
- **Zep** — 商业替代方案，具有时序知识图谱和事实抽取。
- **自定义构建** — 当你需要精确控制抽取器（合规）或融合权重（新近度占主导的语音 agent）时。

## Ship It

`outputs/skill-hybrid-memory.md` 生成一个三存储记忆脚手架，内置融合评分器、作用域分类和时序失效。

## 练习

1. 将玩具向量相似性替换为真实嵌入模型（sentence-transformers、Ollama、OpenAI embeddings）。在合成长对话上测量 recall@10。在 1000 次写入后排名会漂移吗？
2. 添加时序查询：`search(query, as_of=timestamp)`。仅返回该时间点或之前有效的记录。哪个存储需要最多工作？
3. 实现冲突检测器：如果传入的事实与图边矛盾，失效旧边并记录两者。在"用户居住在柏林" -> "用户居住在里斯本"上测试。
4. 将融合评分器移植为包含 `user_feedback` 维度（对检索记录点赞）。如何防止博弈（agent 只返回它已经点赞过的记录）？
5. 阅读 Mem0 文档（`docs.mem0.ai`）。将玩具移植到 `mem0` 客户端调用。在相同的 20 个测试查询上比较检索质量。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| 混合记忆 | "向量加图加 KV" | 三个存储并行写入，在检索时融合 |
| 事实抽取 | "记忆摄取" | 将文本分解为 (entity, relation, fact) 元组的 LLM 步骤 |
| 融合评分 | "相关性排名" | 相关性、重要性、新近度的加权和 |
| 作用域 | "记忆命名空间" | user / session / agent — 决定谁能看到什么 |
| Mem0g | "记忆图" | 具有时序有效性的类型化边，用于关系查询 |
| 时序失效 | "软删除" | 将矛盾的边标记为无效；绝不删除 |
| 嵌入漂移 | "检索腐化" | 向量质量随语料库增长而退化；定期重新嵌入 |
