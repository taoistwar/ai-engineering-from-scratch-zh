# 失败模式：Agent 为何会出问题

> MASFT（伯克利，2025）将 14 种多 Agent 失败模式编入 3 个类别。微软的分类法记录了现有 AI 失败在 Agent 环境中的放大效应。行业现场数据汇聚到五种反复出现的模式：幻觉行为、范围蔓延、级联错误、上下文丢失、工具误用。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置条件：** 第 14 阶段 · 05（自优化与 CRITIC）、第 14 阶段 · 24（可观测性）
**时间：** 约 60 分钟

## 学习目标

- 说出 MASFT 的三个失败类别以及每类至少四种具体模式。
- 解释为何 Agent 失败会放大现有 AI 失败模式（偏见、幻觉）。
- 描述五种行业反复出现的模式及其缓解措施。
- 实现一个标准库检测器，为 agent 追踪打上失败模式标签。

## 问题

团队发布的 agent 在 90% 的追踪上工作正常。那 10% 的失败并非随机噪声 — 它们落入少数几个反复出现的类别。一旦你能命名它们，就能监控它们并修复它们。

## 概念

### MASFT（伯克利，arXiv:2503.13657）

多 Agent 系统失败分类法。14 种失败模式分为 3 个类别。标注者间 Cohen's Kappa 为 0.88 — 这些类别是可靠可区分的。

核心主张：失败是多 Agent 系统的基本设计缺陷，而非可以通过更好的基础模型解决的 LLM 局限性。

### 微软 Agentic AI 系统失败模式分类法

- 现有 AI 失败（偏见、幻觉、数据泄漏）在 Agent 环境中被放大。
- 新的失败从自主性中涌现：规模化的意外操作、工具误用、任务漂移。
- 这份白皮书是 Agentic 产品的风险登记册。

### Characterizing Faults in Agentic AI（arXiv:2603.06847）

- 失败源于编排、内部状态演化和环境交互。
- 不仅仅是"糟糕的代码"或"糟糕的模型输出"。

### LLM Agent 幻觉综述（arXiv:2509.18970）

两种主要表现：

1. **指令遵循偏差** — Agent 不遵循系统提示。
2. **长程上下文误用** — Agent 遗忘或错误应用前面轮次的上下文。

子意图错误：省略（漏掉步骤）、冗余（重复步骤）、乱序（步骤顺序错误）。

### 五种行业反复出现的模式

Arize、Galileo、NimbleBrain 2024-2026 年现场分析汇聚到：

1. **幻觉行为。** Agent 调用不存在的工具或捏造参数。
2. **范围蔓延。** Agent 将任务扩展到超出用户的请求（创建额外的 PR、发送额外的邮件）。
3. **级联错误。** 一个错误调用触发下游效应。一次虚假 SKU 幻觉触发四次 API 调用 — 一起多系统事故。
4. **上下文丢失。** 长时间任务忘记早期轮次的约束。
5. **工具误用。** 用错误的参数调用正确的工具，或调用了完全错误的工具。

级联错误是致命的。Agent 无法区分"我失败了"与"任务是不可能的"，常常在 400 错误上幻觉一个成功消息来结束循环。

### 缓解：每步都设关卡

在推理链的每一步设置自动验证关卡，检查事实依据与环境状态是否一致。具体来说：

- 每步安全检查器（第 21 课）。
- 工具调用参数验证（第 06 课）。
- 交叉检查检索到的内容与已知事实（第 05 课，CRITIC）。
- 通过重新探测状态来检测成功幻觉（文件真的被创建了吗？）。

### 失败监控的常见错误

- **仅标记崩溃。** 大多数 agent 失败产生看起来有效的输出。需要进行内容级检查。
- **无基线。** 漂移检测需要一个最后已知良好状态；没有它你无法判断"情况在恶化"。
- **过度告警。** 每次失败都触发一个页面通知。聚类并限速。

## 构建它

`code/main.py` 实现了一个标准库失败模式标记器：

- 覆盖五种模式的合成追踪数据集。
- 每种模式的检测函数（工具调用、输出、重复操作的特征模式）。
- 标记每个追踪并报告模式分布的标记器。

运行它：

```
python3 code/main.py
```

输出：每个追踪的标签 + 聚合分布，是 Phoenix 追踪聚类功能的低成本复现。

## 使用它

- **Phoenix** 用于生产环境漂移聚类（第 24 课）。
- **Langfuse** 用于会话回放 + 标注。
- **自定义** 用于你可观测性平台无法检测的领域特定特征。

## 交付它

`outputs/skill-failure-detector.md` 生成针对你领域的失败模式检测器，并接入追踪存储。

## 练习

1. 添加"成功幻觉"检测器：agent 返回成功但目标状态未变化。
2. 标记你构建过的产品中的 100 条真实追踪。哪种模式占主导？修复它的成本是多少？
3. 实现"级联半径"指标：给定步骤 N 的一个失败，它影响了多少下游步骤？
4. 阅读 MASFT 的 14 种失败模式。选择三种适用于你产品的。编写检测器。
5. 将一个检测器接入 CI 作业：如果 >= 5% 的追踪标记了一种模式，则构建失败。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| MASFT | "多 Agent 失败分类法" | 伯克利 14 种模式分类 |
| 级联错误 | "连锁失败" | 一个早期错误通过 N 步传播 |
| 上下文丢失 | "忘记了约束" | 长程任务丢失早期轮次的事实 |
| 工具误用 | "错误工具 / 错误参数" | 有效调用，错误的方式 |
| 成功幻觉 | "伪造的完成" | Agent 对 400 声称成功；状态未变 |
| 范围蔓延 | "越界" | Agent 做了超出要求的事 |
| 指令遵循偏差 | "不服从" | 忽略系统提示或用户约束 |
| 子意图错误 | "计划缺陷" | 计划执行中的省略、冗余、乱序 |
