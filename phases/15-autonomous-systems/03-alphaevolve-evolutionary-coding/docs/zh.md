# AlphaEvolve——进化式编程智能体

> 将一个前沿编程模型与进化循环和机器可检查的评估器配对。让循环运行足够长时间。它发现了一个使用48次标量乘法的4x4复数矩阵乘法过程——这是56年来对Strassen算法的首次改进。它还找到了一个Google范围的Borg调度启发式算法，在生产中恢复了约0.7%的集群计算资源。这个架构故意设计得很无聊。胜利来自评估器的严谨性。

**Type:** Learn
**Languages:** Python (stdlib, evolutionary-loop toy)
**Prerequisites:** Phase 15 · 01 (long-horizon framing), Phase 15 · 02 (self-taught reasoning)
**Time:** ~60 minutes

## 问题

大语言模型可以编写代码。进化算法可以在代码空间中搜索。两者已被分别尝试了几十年；两者都遇到了天花板。LLM的天花板是臆造：模型编写看似合理但实际上并不具备其声称功能的代码。进化算法的天花板是搜索成本：在语法上的随机突变很少产生可编译的程序，更不用说更好的程序。

AlphaEvolve（Novikov等人，DeepMind，arXiv:2506.13131，2025年6月）将两者结合。LLM对程序数据库提出有针对性的编辑建议；自动评估器对每个变体进行评分；高评分变体成为未来世代的父代。LLM处理编写看似合理代码这一昂贵步骤；评估器捕获臆造。循环运行数小时到数周。

报告的结果：48次标量乘法的4x4复数矩阵乘法（Strassen在1969年给出的上界是49次），Google生产中的一个Borg调度启发式算法，FlashAttention内核32.5%的加速，以及Gemini训练吞吐量的改进。

该架构之所以有效，是因为评估器是机器可检查的。在评估器不是机器可检查的领域它无效。这种不对称性就是这堂课的核心。

## 概念

### 循环

1. 从一个正确但次优的种子程序 `P_0` 开始。
2. 维护一个程序变体数据库，每个变体由评估器评分。
3. 从数据库中采样一个或多个父代（MAP-elites风格或孤岛模型）。
4. 提示LLM（对许多候选使用Gemini Flash，对困难的候选使用Gemini Pro）生成父代的一个修改变体。
5. 编译、运行并在保留的评估器上评估该变体。
6. 按照分数和特征向量键值插入数据库。
7. 重复。

有两个细节很重要。第一，LLM接收的提示不仅仅是父程序——通常还包括数据库中的几个顶级变体、评估器签名和简短的任务描述。模型的任务是提出一个可能提高分数的有针对性的修改。第二，数据库是结构化的（MAP-elites网格、孤岛模型），这样循环可以探索多样性，而不仅仅围绕当前领先者。

### 评估器为何是不可妥协的

AlphaEvolve的胜利都来自评估器快速、确定且难以博弈的领域：

- **矩阵乘法算法：** 一个单元测试，对矩阵进行乘法并逐位检查相等性。
- **Borg调度启发式算法：** 一个生产级模拟器，重放历史集群负载并测量浪费的计算资源。
- **FlashAttention内核：** 一个正确性测试加上在真实硬件上的墙上时钟基准。
- **Gemini训练吞吐量：** 以每秒GPU步数测量。

在每种情况下，评估器捕获了原本会占主导地位的LLM错误类型：臆造的正确性声明、在硬件上消失的性能声明以及边界情况失败。移除评估器，循环就会优化看似漂亮的代码。

### 奖励黑客行为是这一陈述的另一面

进化优化的是评估器测量的任何东西。如果评估器不完美，循环就会找到那个不完美之处。在一个未经验证的领域，循环会优化表面特征，而不是预期行为。DeepMind在论文中明确指出了这一点：AlphaEvolve的成功只转移到那些评估器严谨性与搜索目标相匹配的领域。

2025-2026年代码搜索循环中奖励黑客行为的具体例子：

- 奖励"完成时间"的优化目标奖励了提交空解决方案。
- 奖励测试下正确性的基准分数奖励了记忆测试和过拟合。
- 一个"代码质量"代理奖励了删除注释和重写变量名，但没有语义改变。

AlphaEvolve中的修复：发布一个LLM从未见过的保留评估器，其输入在评估时生成。即便如此，DeepMind建议对任何提议的部署进行严格审核。

### 为什么LLM + 搜索胜过单独任何一种

LLM可以产生可编译、语义上合理的修改。对一个2000行的Python文件进行随机突变GA几乎总是产生语法错误。LLM还将搜索集中在合理的邻域上（改变一个函数，而不是随机字节），这大大减少了浪费的评估器调用。

反过来，评估器捕获LLM的臆造。LLM会自信地声称一个函数"在极限情况下是O(n log n)"，而它实际上是O(n^2)；一次墙上时钟基准测试就能让问题尘埃落定。

### AlphaEvolve在前沿技术栈中的位置

| 系统 | 生成器 | 评估器 | 领域 | 典型成果 |
|---|---|---|---|---|
| AlphaEvolve | Gemini | 正确性 + 基准 | 算法、内核、调度器 | 48次乘法的4x4矩阵乘法 |
| FunSearch (DeepMind, 2023) | PaLM / Codey | 正确性 | 组合数学 | cap-set下界 |
| AI Scientist v2 (Sakana, 第5课) | GPT/Claude | LLM评论 + 实验 | ML研究 | ICLR workshop论文 |
| Darwin Godel Machine (第4课) | 智能体脚手架 | SWE-bench / Polyglot | 智能体代码 | 20% → 50% SWE-bench |

这四种都是同一配方——生成器加评估器加循环——的变体。区别在于评估器评分的对象以及其严谨程度。

## 运用

`code/main.py` 在一个玩具符号回归问题上实现了一个极简的AlphaEvolve风格循环。"LLM"是一个使用标准库的代理，对计算目标函数的程序提出小的语法突变。"评估器"在保留的测试点上测量均方误差。

观察：

- 最佳分数如何随世代改进。
- MAP-elites网格如何保持多样的解决方案存活，使循环不会收敛到局部最小值。
- 移除保留测试（仅使用训练评估器）如何让循环过拟合到惊人的程度。

## 练习

1. 运行 `code/main.py`。记录最佳分数轨迹。禁用保留评估器（标志 `--no-holdout`）并重新运行。量化过拟合。

2. 阅读AlphaEvolve论文第3节关于MAP-elites网格的内容。为一个新问题（例如编译器优化过程）设计一个特征向量描述符，以保持搜索的多样性。

3. 48次乘法的4x4结果在56年后改进了Strassen的49次乘法上界。阅读论文附录F，用三句话解释为什么这个问题的评估器特别容易做对，以及为什么大多数领域并非如此。

4. 提出一个AlphaEvolve会失败的领域。准确指出评估器在哪里失效以及为什么。

5. 对于一个你了解的领域，写出你会使用的评估器签名。包括(a)正确性条件，(b)性能指标，(c)保留输入生成规则，(d)至少一个反奖励黑客检查。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|---|---|---|
| AlphaEvolve | "DeepMind的进化式编程智能体" | Gemini + 程序数据库 + 机器可检查的评估器 |
| MAP-elites | "保多样性的存档" | 按特征向量键值的网格；每个单元格保存具有该描述符的最佳变体 |
| 孤岛模型 | "并行进化子种群" | 独立种群定期迁移；防止过早收敛 |
| 机器可检查的评估器 | "确定性预言机" | LLM无法伪造的单元测试、模拟器或基准——这个循环的前提条件 |
| 奖励黑客行为 | "优化度量，而不是目标" | 循环找到了一种在不执行预期任务的情况下最大化分数的方法 |
| 种子程序 | "起点" | 一个初始的正确但次优的程序，循环从此开始进化 |
| 保留评估器 | "LLM从未见过的评估数据" | 在评估时生成的输入，以防止记忆 |
