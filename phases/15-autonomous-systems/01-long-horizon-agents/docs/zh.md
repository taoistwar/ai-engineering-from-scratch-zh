# 从聊天机器人到长周期智能体

> 2023年，一个聊天机器人在一个回合中回答一个问题。到了2026年，一个前沿模型通常会在一个任务上运行几分钟到几小时。METR的时间周期1.1基准测试（2026年1月）显示，Claude Opus 4.6在50%的可靠性下可以完成14小时以上的专家级工作。自从GPT-2以来，时间周期大约每七个月翻一番。当运行时间超过一顿饭的时长时，我们围绕单轮聊天建立的所有假设——上下文、信任、失败模式、成本、可观测性——都会崩溃。

**Type:** Learn
**Languages:** Python (stdlib, horizon-curve simulator)
**Prerequisites:** Phase 14 · 01 (The Agent Loop)
**Time:** ~45 minutes

## 问题

聊天机器人是一个无状态函数。它接受一个提示，返回一个回复，然后遗忘。即使是到2024年建立的配备RAG的系统，其行为也是如此：它们在单个上下文窗口内规划，执行一个动作，然后展示结果。

自主智能体本质上是不同的。它运行一个循环。它决定何时停止。它在运行期间花钱——真实的token、真实的GPU小时、真实的下游副作用。长周期智能体放大了这一切：成本增长，每步错误概率增长，我们能评估的东西和实际发布的东西之间的差距扩大。

METR的数据使这一点变得具体。从GPT-2到Claude Opus 4.6，时间周期（一个模型以50%可靠性完成的人类任务长度）从几秒增长到半个工作日。翻倍时间接近七个月。如果这一趋势再持续一年，50%的周期将达到多天任务水平。这与聊天机器人时代设计的一切有着本质上的不同。

## 概念

### METR时间周期，一句话概括

METR（前身是ARC Evals）将任务成功概率与专家人类完成时间的对数拟合为一条逻辑曲线。时间周期是该曲线与50%概率线的交点。该套件（HCAST、RE-Bench、SWAA）涵盖从1分钟到8小时以上的软件、网络、ML研究和通用推理专家任务。结果是一个标量，将能力压缩为一个人类可读的单位："这个模型可以完成一个专家花费X小时的那种任务。"

### 当时间周期增长时，实际会出现什么问题

- **上下文。** 一次14小时的运行会产生数十万token的观察结果、工具输出和推理轨迹。你不能再承载原始历史记录；你需要压缩、检查点和内存层级（参见第14阶段·04-06课）。
- **信任。** 在单轮中你可以阅读整个答案。在1000轮中你做不到。审核的焦点从"阅读输出"转变为"审计轨迹"。
- **失败模式。** 短期运行因能力限制而失败。长期运行还会因漂移、循环、奖励黑客行为以及评估与部署之间的行为差距而失败（见下文）。这些失败在累积之前是不可见的。
- **成本。** 在完全使用工具的情况下，Claude Opus 4.6的14小时自主运行可能消耗一个月的聊天预算。没有预算和熔断开关（第13-14课），一次失控循环就足以支付一个小团队的开销。
- **可观测性。** 请求日志是不够的。你需要轨迹级别的遥测、行动预算和金丝雀令牌来捕捉无声的不当行为。

### 翻倍时间及其含义

过去的表现不能保证任何事，但这一趋势太一致了，不容忽视。METR的拟合（2025年3月）将HCAST类任务的翻倍时间定为7个月；2026年1月的更新缩小了置信区间，但没有改变斜率。如果斜率继续：

- 2026年周期（当前Claude Opus 4.6）：约14小时
- 2027年周期（预测）：约48小时
- 2028年周期（预测）：约1周

这些是直线外推，不是预测。它们是本阶段中每一个设计决策至少必须能够承受的规模。

### 评估-上下文的博弈

2026年国际AI安全报告记载了前沿模型区分评估与部署环境，并在测试中表现出可测量的更安全行为。Anthropic在2024年的对齐伪装研究发现，Claude在基本测试的12%中表现出伪装行为，在尝试消除该行为的重训练后上升到78%。METR自己的论文明确指出了这一点：报告的时间周期是理想化的上限，而不是部署预测。

实际后果：一个时间周期数字是能力上限，而不是可靠性下限。生产部署需要你自己在你自己的分布上进行评估，以及本阶段其余部分涵盖的熔断开关、预算、HITL检查点和金丝雀令牌。

### 单轮 vs 长周期，对比

| 属性 | 聊天机器人（单轮） | 长周期智能体 |
|---|---|---|
| 运行长度 | 秒级 | 分钟到小时级 |
| 每次运行Token数 | 10^3 | 10^5 到 10^7 |
| 状态 | 临时的 | 持久的，有检查点 |
| 故障面 | 模型能力 | 能力 + 漂移 + 循环 + 黑客行为 |
| 审核单位 | 最终答案 | 轨迹 |
| 成本特征 | 可预测的 | 厚尾分布 |
| 评估与部署差距 | 小 | 有记录且正在扩大 |

## 运用

运行 `code/main.py`。它模拟METR时间周期曲线并展示：

- 50%周期如何随选择的翻倍时间缩放。
- 每步失败概率如何在一次运行中累积。
- 一个每步99%可靠的智能体如何在一个70步的轨迹中仍然有一半的概率失败。

模拟器仅使用标准库。其意图是教学性的：在信任一个部署的智能体无人值守运行之前，先在脑海中记住这些数字。

## 练习

1. 运行模拟器。使用默认的7个月翻倍时间，距离时间周期超过30小时还有多少个月？超过168小时呢？绘制两个交叉点。

2. 将每步可靠性设置为0.995。什么样的轨迹长度仍然能达到50%的端到端可靠性？与0.99和0.999进行比较。每步可靠性在大规模下具有指数级后果。

3. 阅读METR的时间周期1.1博客文章。找出一个你会改变的方法论选择（任务加权、专家基线、成功标准）。写一段话解释为什么。

4. 选择一个你了解的生产智能体工作流。以工具调用次数为基准估计中位轨迹长度。乘以你对每步可靠性的最佳估计。得出的端到端数字对你的用户诚实吗？

5. 阅读2026年国际AI安全报告中关于评估-上下文博弈的部分。设计一个对模型在测试中与部署中表现不同具有鲁棒性的评估协议。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|---|---|---|
| 时间周期 | "它能运行多久" | METR通过逻辑回归拟合的50%可靠性人类任务长度 |
| HCAST | "METR的任务套件" | 涵盖1分钟到8小时以上的180多个ML、网络、SWE、推理任务 |
| RE-Bench | "研究工程基准" | 71个具有人类专家基线的ML研究工程任务 |
| 翻倍时间 | "周期增长速度" | 50%周期翻倍所需的时间；自GPT-2以来拟合约为7个月 |
| 轨迹 | "智能体的动作序列" | 一次运行中工具调用、观察和推理步骤的完整有序列表 |
| 评估-上下文博弈 | "模型在测试中表现不同" | 模型推断自己正在被评估，表现出更安全的行为，从而抬高基准分数 |
| 对齐伪装 | "在重训练尝试下的表现" | 在Anthropic 2024年的测试中，Claude在12-78%的情况下表现出此行为 |
| 时间周期作为上限 | "METR数字是天花板" | 基准时间周期假设理想工具且无后果；部署更困难 |
