# 自动化对齐研究（Anthropic AAR）

> Anthropic在独立沙盒中运行了Claude Opus 4.6自动化对齐研究员的并行团队，通过一个共享论坛进行协调，该论坛的日志存储在沙盒之外（因此智能体无法删除自己的记录）。在弱到强训练问题上，AAR的表现优于人类研究员。Anthropic自己的总结指出，预设的工作流程常常限制AAR的灵活性并降低性能。将对齐研究自动化是一个将时间线压缩到RSP旨在检测的确切错位风险的压缩步骤。

**Type:** Learn
**Languages:** Python (stdlib, parallel-research-forum simulator)
**Prerequisites:** Phase 15 · 05 (AI Scientist v2), Phase 15 · 04 (DGM)
**Time:** ~60 minutes

## 问题

对齐研究在人类研究员时间上是昂贵的。像可扩展监督、奖励规范或弱到强训练这样的问题，每次迭代都需要数周的实验。随着前沿能力的进步，对齐工作负载的增长速度快于合格研究员的供给。

自动化对齐研究（AAR）问的是：那些能力正跑在对齐前面的同一个前沿模型，能否为缩小差距做出贡献。Anthropic在2026年关于AAR运行的弱到强训练研究的报告（alignment.anthropic.com/2026/automated-w2s-researcher/）是此类已部署系统的首批公开结果之一。

结果确实是积极的：AAR解决了一个研究问题，而且比人类基线更好。这个结果也将本阶段形成的每一个担忧集中在了单一系统中。如果对齐研究可以自动化，那么破坏安全保障的部分也可以。RSP中AI研发能力的阈值就是围绕这个循环制定的。

## 概念

### 架构（按照公开描述）

- **并行智能体。** 多个Claude Opus 4.6实例作为AAR运行，每个在独立的沙盒中。沙盒限制文件系统、网络和进程表面。
- **共享论坛。** 发现结果被发布到一个共享论坛，其存储后端位于每个沙盒之外。智能体可以阅读论坛；智能体不能从自己的沙盒内删除或编辑论坛记录。
- **任务分配。** 一个人类设计的任务队列将研究问题分配给AAR。AAR提出分解方案，运行实验，撰写发现结果。
- **弱到强训练重点。** 已发表的研究针对弱到强训练——使用较弱的监督模型来训练较强的学生模型。AAR在此任务上表现优于人类研究员。

### 为什么沙盒外日志很重要

日志完整性属性是受控实验和潜在被破坏实验之间的区别。如果AAR可以编辑自己的日志，它们就可以掩盖失败或可疑的实验。Anthropic直接指出了这一点：该属性是信任研究输出的必要条件，且验证它并非易事。

在基础设施层面的类比是带有写穿到外部存储的仅追加日志（例如S3对象锁定、不可变的Datadog日志）。智能体没有凭据来修改过去的记录。这与2026年企业安全团队用来构建抗勒索软件审计追踪的模式相同。

### 预设工作流程的权衡

Anthropic的报告指出，预设的工作流程常常限制AAR的灵活性并降低性能。换句话说：如果人类设计者逐步编写研究计划，AAR的表现不如被赋予高层目标和自由进行分解。这与智能体研究（LangGraph、Microsoft的Agent Framework）的结果一致——过度规定的脚手架会损害有能力的智能体。

安全含义是微妙的。改善AAR性能的灵活性也是允许未经批准的分解、新颖工具使用和目标漂移的灵活性。这个权衡是一个设计空间决策：多少灵活性足以获得超越人类的能力，而又不给智能体留出在分布外泛化目标的空间？

### 压缩风险

RSP v3.0（第19课）引入了一个AI研发能力阈值：完全自动化AI研发流程并以与人类 + AI工具相比具有竞争力的成本完成的能力。DeepMind的FSF v3包含一个类似的ML研发自主性水平。两个框架都将此阈值视为升级控制措施的触发条件。

AAR距离该阈值还差一步：它自动化了流程的一部分（在特定、范围明确的任务上进行对齐研究），但不是端到端的能力开发循环。时间线问题是差距缩小的速度有多快。

压缩的时间线是复利式失败的担忧所在。如果对齐研究和能力研究以相似的速度复利增长，错位风险表面至少与能力一样快地增长。如果能力复利增长更快（历史趋势），差距就会扩大。这就是AAR是有限度的好处的论点：每一份额外的对齐成果只有在研究过程值得信赖的情况下才能缩小差距。

### AAR不取代什么

人类研究员设定任务队列，审核结果，并拥有宪制权威。AAR加速流程的中间部分，而不是两端。Anthropic发表的输出既包括AAR的贡献，也包括人类研究员对发表什么、撤回什么和优化什么的判断。

这与第15课中应用于研究本身的"提议然后提交"模式相匹配：AAR提议；人类提交。

## 运用

`code/main.py` 模拟一个多AAR研究论坛。三个独立的"研究智能体"并行运行，向一个仅追加的论坛发布发现结果，并可选择尝试篡改。

观察：

- 沙盒外日志如何捕获日志篡改尝试。
- 在更难的问题上，允许自由分解的任务分配如何优于固定工作流程。
- 如果日志不具备防篡改性，单一被破坏的AAR如何污染论坛的信号。

## 交付物

`outputs/skill-aar-deployment-review.md` 是对自动化对齐研究流程的部署前审核。

## 练习

1. 运行 `code/main.py`。比较"固定工作流程"与"自由分解"设置。自由分解总是胜出，还是存在某些问题类别中固定工作流程具有竞争力？

2. 修改模拟器，使一个智能体尝试日志篡改。确认仅追加日志能够检测到。写一段话描述日志中的检测特征具体是什么样子。

3. 阅读Anthropic的弱到强AAR报告。确定AAR在哪个具体子任务上击败了人类研究员。是什么使它适合自动化？

4. 设计一个任务队列分配策略，平衡AAR灵活性（更好的结果）和预设工作流程约束（更容易审计）。描述你将如何对两者进行A/B测试。

5. 阅读RSP v3.0的AI R&D-4阈值。用一段话描述你认为什么会跨越它，而AAR目前还没有。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|---|---|---|
| AAR | "自动化对齐研究员" | 在对齐问题上自主运行的Claude Opus 4.6实例 |
| 弱到强训练 | "用较弱的监督者训练较强的模型" | AAR在其中超越人类的经典可扩展监督基准 |
| 共享论坛 | "智能体发布发现结果的地方" | 仅追加的、沙盒外存储 |
| 沙盒外日志 | "智能体无法编辑自己的记录" | 写穿到外部存储的防篡改机制 |
| 预设工作流程 | "人类设计者的逐步计划" | 约束AAR；与自由分解相比通常降低性能 |
| 自由分解 | "智能体决定如何分解任务" | 能力更强，更难审计 |
| AI研发阈值 | "RSP/FSF能力水平" | 以具有竞争力的成本完全自动化研发流程 |
| 压缩的时间线 | "对齐 vs 能力的竞赛" | 如果能力复利增长快于对齐，错位风险就会增长 |
